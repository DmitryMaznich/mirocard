# Части прописных букв («Что пишем» / «Штрихи») — передача для следующей сессии

Начато 2026-11-16, состояние на 2026-11-19 (прод 1.1.151, колоды `propis2` 0.7.1, `propis2_lang` 0.11.1).
Задача следующей сессии: **разрезать каждую русскую прописную букву (строчную и заглавную) на штрихи-элементы
школьной методики**, чтобы взрослый мог дать ребёнку писать только часть буквы. Владелец: «многие буквы
неправильно, давай позже отшлифуем разрезание» (2026-11-16) — поэтому в приложении нарезка прописных сейчас
**выключена**.

## Что уже работает (не переделывать)

- **Интерфейс.** Строка из одной буквы → её штрихи нажимаются: на компьютере в панели строки справа
  (`PartsPad`, раздел «Что пишем»), на телефоне — кнопка «Штрихи» в полосе над клавиатурой, буква во всплывающем
  окне (`PartsPicker`, `src/features/propis2/Propis2Editor.jsx`). Правила владельца: **никаких подписей, кнопок по
  штрихам, «Вся буква»** — только кликабельная буква; на месте невыбранного на листе **ничего не рисуется**.
- **Хранение.** `row.parts = { of, keep }`: `of` — буква, для которой выбирали; `keep` — индексы частей, которые
  пишем. Перепечатали строку другой буквой — выбор не действует (`model.js rowPartsOf`). В строку движка — флаг
  `#p0.2` (`pageToLines`, перед `#y<стиль>`).
- **Движок.** `src/handwriting/wordEngine.js`: `PARTS_FLAG`, `partsGlyphMap` (у буквы — `hiddenParts`),
  буква ставится целиком как обычно, потом режется на части (`splitIntoParts`), скрытые выбрасываются, у них нет
  стартовой точки. Выбранная часть стоит ровно там же, где в целой букве.
- **Печатные (стиль «Печатные», Илюхина)** — каждый штрих = часть, работает (тест `printStyle.test.jsx`).

## Что делать — сама разрезка

Всё в одном файле: **`src/handwriting/letterParts.js`**.

- Часть = кусок одного штриха глифа `{ stroke, from, to }` в долях длины пути (`piecePathD` режет ломаной по длине).
- Сейчас части берутся: печатные (`glyph.upright`) — штрихи; прописные — `glyph.partCuts?.[si]` (свой разрез,
  **пока ни у одной буквы нет**), иначе `autoCuts(d)` — но только если включено `setAutoCuts(true)` (в приложении
  `false`; стенд и тесты включают).
- `autoCuts` режет в **остром** развороте пера: вверху (поднялся по линии и пошёл вниз — и, палочка а) и внизу,
  только если перо снова идёт вверх по всей палочке (п т р). Круглый верх овала (о е с, чаша а) не режет.
  Пороги: `PROMINENCE 0.45`, `BOTTOM_PROMINENCE 0.85`, `TURN_COS -0.35`, `END_SHARE 0.1`.

**Текущая автоматика на картинке** (части разными цветами, число частей серым) —
`docs/mockups/propis2-parts/auto-cuts-lower-2026-11-19.png` и `…-upper-…png` (+ `.html`). С неё и начинать:
показать владельцу, по каждой букве записать, где резать.

Рекомендуемый путь (моё мнение, обсудить с владельцем в начале):
1. **Ручной разрез — данные, не код.** Автоматика не знает методики (например, у в её длинная петля, у з нижняя
   петля, у б флажок). Завести файл `tools/handwriting/cyrillic/part_cuts.json` — `{ "а": [[0.62]], "Б": [[], [0.4]] }`
   (по букве — массив по штрихам, в каждом доли длины, где резать) — и при сборке колоды
   (`scripts/build-propis2-deck.mjs`, где читается `wide.json`) класть его в глиф как `partCuts`. `wide.json` (формы
   букв) не трогать. `glyphMapOf` (`src/topics/renderers/propis2/pageTask.js`) передаёт поля глифа как есть, так что
   `partCuts` дойдёт до `letterPieces` без правок движка.
2. Подбирать доли на стенде (ниже), каждую букву — картинкой владельцу; принятое — в `part_cuts.json`.
3. Когда все буквы приняты — `autoCuts` можно удалить или оставить подсказкой для стенда; в приложении частями
   становятся только `partCuts`.
4. Методические элементы владельца уже описаны в `tools/propis2/parts/README.md` (лист 2026-10-29: «палка» из
   ножки р, «левая/правая» П, «шапка» Р, петля В, флажок К …) — это **те же элементы**, ими и проверять, где резать.

## Элементы и траектория — две техники письма (2026-11-19, начато с «р»)

Решено с владельцем: у буквы есть **элементы** (что остаётся на бумаге) и **траектория** (как по ним шло перо). Разрез
не меняет порядок и направление письма. Две техники над одними и теми же элементами:
- **безотрывно (по умолчанию, владелец так учил сына):** путь как в глифе; **возврат** (перо по бумаге по уже нарисованному —
  «р»: вниз по палочке, обратно вверх до средней линии, крючок — почти «г», от средней линии до средней линии) новой линии не даёт, в анимации — бегущее перо; точка начала одна;
- **возврат двух видов** (владелец 2026-11-19): по уже нарисованному («р», «п»: обратно вверх по палочке) — новой линии нет; **впереди элемента** («и й у ц»: после закругления вверх по наклонной до верхней линии, по линии, которую потом пройдёт вторая палочка) — перо оставляет линию (`letterMoves` → `retrace` с `ink: true`), иначе безотрывная анимация выглядит как отрыв;
- **с отрывом:** каждый элемент от своей точки начала; путь пера по воздуху между ними **не показывается** (владелец: «там закончилось и потом началось»).
Переносы по воздуху бывают и в безотрывном письме (владелец: такие буквы есть — какие, ещё не названо).

Данные — `tools/handwriting/cyrillic/letter_elements.json` (готовы и приняты: «р»; размечены «у», «й», «ц», «т» (палочка и два крючка, возвраты вверх по палочкам до средней линии; низ палочек опущен вдоль них до низа закругления — в строке все три элемента на 62, верх первой палочки 10,7 — точка начала, к ней приходит соединение, не тронут; сравнение 1426 слов: изменились только 522 слова с «т» и только в ней, ≤ 1,1); «г» — один элемент, без разреза (владелец); «ш» (владелец: «аналогично и»): буква составная (`compose` 6+6+6, своей линии нет) — `composedMoves(strokes, trajectory, technique)` берёт части и соединения из раскладки строки: элементы — три «6», подъёмы — соединения движка, идут по следующей палочке (≤ 0,08 — округление строки) и оставляют линию; в `letter_elements.json` у неё только `composed` и названия элементов; стенд раскладывает такие буквы движком. **Стенд рисует буквы как строка: подгонка к линиям И растяжение вширь (`stretch` 1,8, наклон сохранён)** — без растяжения обычная буква на стенде в 1,8 раза уже составной (владелец заметил: «почему такая разная ширина у ш и и»). «щ» (владелец, 2026-11-20: «аналогично ц») — собрана заново: начало «ц» до верха второй палочки, звено «палочка, закругление, подъём к верху» той же «ц», сдвинутое на шаг палочек (18), и конец «ц» с маленькой петлёй и выходом, сдвинутый так же; ширина та же (41,88 от начала до выхода), слова с «щ» той же ширины (±0,1), стыки с соседними буквами прежние; старая запись (ш0 + хвост: подъёмы буквой V, до 1,5 в стороне от палочек) заменена; размечена как «ц» (два подъёма вперёд, петля — `cuts: [15]`). Закругление элемента «6» (из него собрана «ш», в строке на 1,3 выше нижней линии) — владелец не стал трогать; «ь» — один элемент (владелец); **сверка с прописями Мазиной** (владелец 2026-11-20: де-факто школьный стандарт): у «ъ» флажок переделан — подъём по наклону от четверти строки, закруглённый угол, планка вдоль верхней линии около клетки с провисом ~2,8, вход в верх палочки положе (~14°) без шипа над линией (те же 15 команд флажка: `bellyFrom` считает куски); «ъ» стала шире — в 9 словах колоды она и всё после неё встаёт на клетку правее; у «ы» пузо смыкается с палочкой и соединительный элемент начинается на средней линии (`Y_STEM_Y 36`); пузо «ь» (у Мазиной шире, ~0,9 клетки против наших 0,77) — отдельный шаг, ждёт владельца; «ъ» — флажок и «ь», разрез на вершине (`cuts: [14]`), размечена по букве с поправками приложения (у неё петля от «в»); «ы» — составная (`ы1` + `ы2` из `glyphOverrides.js`, левую часть строит `yerLoop`): три элемента — левая часть, **соединительный элемент от палочки** к верху правой палочки (владелец 2026-11-20: часть буквы; «начинается от вертикальной линии» — раньше он уходил от петельки в 3,7 правее палочки; теперь живот доходит до самой палочки и перо разворачивается там узким клином), правая палочка (`parts: [[0], [1], [3]]` — куски раскладки по элементам). Слова с «ы» (158): входы и выходы «ы» прежние, меняется только начало соединения внутри неё. **Выход к следующей букве — соединение, не часть буквы** (владелец, про «ъ»): стенд отрезает его там, где приложение его отделяет (`tailSplit` / `tailStroke`), как одна буква и пишется; «л», «м» (владелец: «просто делятся по верхним точкам»): разрез без возврата в верхней точке поворота пера (`cuts: [{ seg, top: true }]`), формы не тронуты; «н» (владелец, по ролику школы с тремя точками начала: «первая палочка сверху вниз до конца, потом от середины вогнутая перекладина до третьего штриха, третий штрих — такой же, как правый у „и“»): палочка, возврат по ней вверх до начала перекладины, вогнутая перекладина (форма глифа, не выпрямлять!) до второй палочки, подъём по ней с линией к верху, вторая палочка; низ первой палочки и верх второй продлены вдоль них на линии строки (изменились только 366 слов с «н», ≤ 1,48); размечены «п» — как «р», палочка до нижней строки — и «и»: первая палочка с закруглением до средней линии, подъём от средней линии к верху идёт точно по второй палочке и считается возвратом — перо по линии элемента, который оно сейчас напишет; вторая палочка — от верхней линии): по штриху буквы `retrace: [[a, b]]` и `cuts: [a]`,
позиции — в сегментах пути от начала штриха (не в долях длины: так не зависят от растяжения глифа). Код —
`letterPaths` / `letterMoves(glyph, "joined" | "lifted")` в `src/handwriting/letterParts.js`, тесты
`src/handwriting/letterTrajectory.test.js`. Стенд-анимация: `node tools/propis2/parts-review/trajectory-sheet.mjs р > out.html`
(картинка «р п и» — `docs/mockups/propis2-parts/trajectory-2026-11-19.html`).

**Выравнивание элементов (владелец 2026-11-19: «у обоих штрихов верхние и нижние точки должны быть на одной линии», «все должно
быть четко»).** Важно: движок ставит букву на строку не как она лежит в `wide.json` — `normalizeLetterExtremes` (`wordEngine.js`)
растягивает её вдоль наклона так, чтобы **крайние** точки легли на линии 10 и 62 (кроме букв с ножкой — `р`, `descender`). Каждый
элемент по отдельности он не выравнивает, поэтому сравнивать и рисовать стенды нужно **после** этой подгонки (стенд
`trajectory-sheet.mjs` так и делает; первая картинка сессии рисовала сырой глиф и сбила владельца). Правки в `wide.json`, только внутри
штрихов (ручки кривых растянуты вдоль своих касательных, концы и направления на концах прежние):
«и» — верх второй палочки 11,48 → 10, закругление первой 59,69 → 60,73; «п» — верх крючка 12,17 → 11,12, низ крючка 59,90 → 60,18 (как
палочка); «р» не подгоняется движком — она пересобрана из подогнанной «п» с ножкой, продлённой до 114 по её наклону, точка выхода
(161,22; 36) прежняя, точка начала поднялась на верхнюю линию, как у «п» в строке. После подгонки у всех элементов «и п р» верх 10, низ 62
(тест в `letterTrajectory.test.js`). Проверка соединений: слова разложены на старом и новом `wide.json` — стыки те же (крупные картинки
«ар», «пр», «ра» сверены), меняются только сами выправленные дуги. Тот же ряд выровнен следом: «у» и «ц» движок не подгоняет (ножка) — их начало взято из «и» в том виде, как её ставит строка (тест «ц and у begin with и»), ножка, петля и выход свои, прежние; «й» — как «и» (верх второй палочки по её наклону на 10, её закругление как у первой). Слова с «у ц й» сверены на старом и новом `wide.json`: концы штрихов и соседние буквы те же, слово с «ц» в начале сдвигается целиком на 0,84. Петля «ц» кончается на 86,4 — не на линии (так задумана, «уменьшенная»). Размечены элементы «у» и «й» (кратка — свой элемент, всегда с отрывом); «ц» размечена по владельцу: две палочки от «и» и маленькая петля — отдельный элемент от конца второй палочки (вершина подъёма, y 49; `cuts: [10]`, без возврата). В прод форма уйдёт
только с пересборкой колоды `propis2`.

**Крючок начинается строго на палочке (владелец 2026-11-19: у «т» иначе «ступенчатое» безотрывное письмо).** Раньше возврат шёл по
палочке, а крючок начинался там, где кривая пересекает среднюю линию, — уже в 0,7–1,1 от палочки. Теперь у «п», «р», «т» прямой возврат
доведён по самой палочке до средней линии (`retrace: [[1, 2]]` — точки излома, не «до высоты»), кривая крючка перестроена оттуда (без
захода назад вдоль палочки; конец и его направление прежние). Изменение формы ≤ 0,95 / 1,06 / 1,58, концы штрихов во всех словах на месте.
Тест «after a retrace back, the next element begins on the line» держит это для всех букв. **При сравнении слов точки брать плотно по
длине** (не N на сегмент): на длинных прямых редкие точки дают ложные расхождения до 3–4.

**Стыки в безотрывной анимации незаметны (владелец 2026-11-19).** `letterMoves` помечает `continues: true` каждый кусок, который идёт
дальше без отрыва; проигрыватель обязан вести такие куски одним движением — с той же скоростью, без паузы и без нового старта кадра
(стенд переносит время конца куска на начало следующего). Паузы — только на отрыве и в конце буквы. Проверено замером положения пера
по кадрам в браузере: в безотрывной анимации ни одного кадра без движения. В приложении это понадобится, когда анимация станет
поэлементной (сейчас буква анимируется одним штрихом целиком, стыков нет).

**Решено не делать (владелец, 2026-11-19, после оценки):** второй элемент «и» точной копией первого (разница ≤ 1,0, а меняются соединения и
интервалы во всех 459 словах с «и» из 1426) и подгонку движка с неподвижной средней линией (выход 10 букв уходит с неё на 0,19–0,68;
правка меняет 1367 слов из 1426). Тесты движка такие изменения почти не ловят — мерить сравнением раскладки всех слов колоды.

**В приложение не подключено.** Дальше: принять «р» у владельца → разметить остальные буквы → в движке строк не рисовать возврат
вторым слоем, выбор техники (тетрадь/строка), части «Что пишем» = элементы (сначала решить сдвиг индексов `row.parts`, см. ниже).
`partCuts` из плана выше заменяется этим файлом.

## Стенд

**Сетка (2026-11-20).** `trajectory-sheet.mjs` рисует частую наклонную сетку тетради (5 мм, «dense») и среднюю пунктирную; буква ставится на неё
тем же движком, что в тетради (`snapXFor` из `PrintPageView.jsx` грузится через Vite `runnerImport` — поэтому скрипт должен лежать в проекте).
Буквы — как их собирает приложение: `buildGlyphMap` из `pageTask.js` (с поправками `glyphOverrides.js`, у «у» выпрямленный хвост). Над каждой
буквой — отход каждой палочки от ближайшей наклонной в единицах строки (клетка 30). Состояние 2026-11-20: «л м н п р т й ш» — 0,0;
«и у ц щ» были +0,8 (движок ставил на линию точку начала, а у них начало — скруглённый кончик левее палочки) — владелец разрешил
`stemOnLine` (как у «ъ», `glyphOverrides.js`), теперь 0,0; ножка маленькой петли «ц», «щ» — посередине клетки, так и должно быть (владелец).
Проверка 2026-11-20: 1426 слов колоды на частой сетке — 9828 палочек из 11 911 на наклонной, 128 посередине клетки (петли ц щ, ж),
1955 в 0,1–1,52 (чужие пока буквы, худшие — «д»); 879 сочетаний и слов только из размеченных букв — все палочки на наклонной, кроме «г» (0,15)
и петель «ц щ». Со `stemOnLine` буквы и соединения только сдвигаются на 0,83; изредка слово с этой буквой в начале строки встаёт на клетку
правее (2 строки из 667). Весь набор тестов приложения проходит.


`tools/propis2/parts-review/` (README там же): временный тест рисует HTML-лист всех букв, части цветами.

```bash
cp tools/propis2/parts-review/sheet.test.jsx.txt src/topics/renderers/propis2/zzParts.test.jsx
LETTERS="абвгдеёжзийклмнопрстуфхцчшщъыьэюя" OUT=$PWD/out.html npx vitest run src/topics/renderers/propis2/zzParts.test.jsx
rm src/topics/renderers/propis2/zzParts.test.jsx   # не коммитить
```

## Подводные камни

- **Индексы `keep` сдвинутся.** Сейчас у прописных из нескольких штрихов (б ё й к х э, А Б В Г Ё Ж З Й К Л М О П Р
  Т Ф Х Э Ю — по штрихам, без разреза) части = штрихи, и у пользователей уже могут быть сохранённые строки с
  `row.parts`. Как только у такой буквы появится разрез, номера частей поменяются и строка начнёт писать не то.
  Решение: хранить в `row.parts` число частей (`n`) или версию разреза и игнорировать выбор, если они не совпали
  (`rowPartsOf` в `src/topics/renderers/propis2/model.js`), — сделать **до** включения разрезов.
- **Буквы из элементов** (`glyph.compose`: ш = 6+6+6, ы) — частей нет (`partsGlyph` их пропускает в
  `Propis2Editor.jsx`). Отдельный вопрос владельцу: части = элементы сборки?
- **Части только у строки из одной буквы.** Слово/слог — «Штрихов» нет (так решено, не менять без владельца).
- **Соединения.** Часть режется по глифу буквы; соединение к следующей букве в строку из одной буквы не входит,
  но выход (хвостик) — часть штриха. Решить с владельцем, отдельная ли это часть.
- Разрез — ломаная по длине пути (`PER_SEGMENT 24` точек на сегмент): на крутых изгибах конец части может чуть
  «гранить»; при видимых углах — поднять плотность.
- Другие языки прописи (болгарский, казахский) берут те же русские глифы: разрез русской буквы подействует и там.
