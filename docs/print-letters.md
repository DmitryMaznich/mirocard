# «Печатные буквы» (print_letters) — передача контекста (на 2026-11-01)

Новая тема, прототип первого этапа (визуал на бумаге). Начата по запросу владельца: конструктор
«на основе прописей», но для дошкольного возраста (4–6 лет) и печатных букв, без курсива.

## Чем отличается от соседних тем

- **`propis2`** («Прописи») — курсив, соединения, наклон, текстовый редактор строк с кодами
  `{э1}`. Не трогаем, не форкаем: `print_letters` — отдельная тема со своим рендерером и
  движком, без общего кода с `propis2`.
- **`letter_writing`** («Написание букв», скрытая/платная, независимая — см. `CLAUDE.md`,
  **не редактировать**) — уже есть простые прямые (без наклона, без соединений) SVG-глифы
  печатных букв формата `{d: "M x,y L x,y"}`, `viewBox "0 0 100 110"`, и похожие приёмы анимации
  по штрихам (`LetterDemoView.jsx`, `WorksheetView.jsx`). Контуры и порядок штрихов для всех 8
  букв первой семьи **взяты оттуда verbatim** (та же буква — тот же путь, тот же порядок
  штрихов), чтобы не плодить два разных «правильных» способа писать одну и ту же букву в одном
  приложении. **Порядок/направление штрихов не мой — это перенос из `letter_writing`; владелец
  как методист должен проверить и поправить, если не согласен** (ровно как с соединениями в
  `propis2`: при сомнении в методике — спросить, не придумывать).
- Чего у `letter_writing` нет и что здесь новое: тетрадь-конструктор (выбрать букву + тип
  страницы → страница добавляется в список, печать), лестница из 4 типов страниц с убывающей
  опорой (most-to-least prompting), группировка букв по семьям штрихов, а не по алфавиту.

## Методика (конспект; полное обоснование — в переписке с владельцем 2026-11-01)

- Печатные буквы — не «пропись полегче», а самостоятельная, часто терминальная цель письма для
  дошкольников и части детей с РАС; подаётся не как подготовка к курсиву.
  **Один порядок штрихов, без вариантов** — важно для моторного обучения через повтор.
- Буквы осваиваются **семьями по сложности штрихов** (как Handwriting Without Tears), не по
  алфавиту. Первая семья — «Прямые линии»: Г Т П Н И Ш Е Ё.
- Лестница опоры по типам страницы (most-to-least prompting, опора убывает **между страницами**,
  не внутри одной страницы/строки):
  1. **Знакомство** — одна крупная буква без линовки, обводка пальцем, порядок штрихов
     проигрывается сам при открытии.
  2. **Обводка по точкам** — несколько строк, буква пунктиром, стрелка направления на каждой
     копии (это и есть опора), номер штриха — только у первой копии первой строки (справочно).
  3. **Угасающая опора** — та же раскладка, буква сплошная, но бледнеет от строки к строке.
  4. **Самостоятельно по образцу** — один образец в начале строки, остальная строка пустая.
- Разлиновка — **3 линии без наклонных** (верх/пунктирная середина/жирная базовая линия), в
  отличие от курсивной разлиновки `propis2`.

## Разворот 2026-11-01: от полноэкранных страниц к компактным блокам

Первая версия делала **4 отдельные полноэкранные страницы на букву** (знакомство — на весь
экран, большая буква для пальца; обводка по точкам; угасающая опора; самостоятельно), по одной
букве на лист. Владелец прислал разворот настоящей книжки-прописи для печати (4 буквы на листе,
каждая — компактный цветной блок: ярлычок с буквой слева + 2–3 коротких строки, первая строка —
отдельный штрих буквы повторяется по строке, дальше штрихи складываются, последняя строка — вся
буква целиком) и поправил: **это конструктор для печати, а не для рисования на экране** —
гигантская буква для обводки пальцем была лишней.

Переделано на `LetterBlock.jsx`: один компактный блок на букву (цветная рамка + ярлычок),
несколько блоков в одной тетради. Отдельные `IntroPage`/`DottedPage`/`FadingPage`/
`IndependentPage.jsx` удалены.

## Разворот 2026-11-01 (второй, тот же день): блок должен быть наборным

Первая переделка всё ещё решала за владельца, сколько строк в блоке и что на них — ряд
«штрих → штрих+штрих → целая буква» собирался автоматически из `letter.strokes`, и единственная
настройка была общей на всю тетрадь («Обводка по точкам» / «Часть строки — самостоятельно»).
Владелец поправил: это должен быть конструктор **в духе `propis2`** — блок наборный: учитель сам
добавляет и убирает строки кнопкой («можем оставить 3 строки, можем 2, можем 1, можем 22»), и на
каждой строке сам выбирает, что там — буква целиком, конкретный отдельный элемент буквы или
пустая строка для самостоятельного письма. Блок растёт по высоте по мере добавления строк. Один
тип блока/листа — не несколько типов страниц и не глобальный переключатель.

Текущее устройство:

- `ConstructorView.jsx`: `blocks` — состояние, каждый `{ id, letterId, color, rows: [{id, content}] }`.
  Выбор буквы создаёт блок с разумным набором строк по умолчанию (`defaultRows` — по одному
  элементу на штрих + строка «целиком»), который дальше **полностью редактируется**:
  `addRow`/`removeRow`/`setRowContent`, плюс `removeBlock`.

## Разворот 2026-11-01 (третий): архитектура конструктора — холст + попап, как у `propis2`

Второй разворот ещё оставлял UI как отдельную панель сбоку: список букв плитками постоянно на
экране, отдельно область предпросмотра. Владелец поправил: это должна быть **та же архитектура,
что уже отработана в конструкторе `propis2`** — холст (тетрадь) как основной экран, узкая панель
инструментов сверху, а выбор буквы — не постоянная сетка, а **попап по нажатию кнопки**, как
`ElementPicker`/`LetterPicker` в `src/features/propis2/Propis2Field.jsx` (кнопка с иконкой и
подписью в строке инструментов, под ней всплывает список).

Сделано без импорта из `src/features/propis2/` (у `print_letters` нет и не должно быть
зависимости от чужой темы/feature-папки) — технику скопировал как генерик-утилиту:

- `usePopupPos.js` — локальная копия `src/features/propis2/usePopupPos.js` один в один
  (чистая позиционирующая логика, без контента/методики прописей — поэтому копия, а не общий
  модуль между темами).
- `LetterPickerButton.jsx` — кнопка «+ Буква» в панели инструментов; открывает `pl-letters-panel`
  (список семей букв, плитки) поверх холста, спозиционированный `usePopupPos` под кнопкой; выбор
  буквы закрывает попап и сразу создаёт блок (`onPick(letterId)`).
- `ConstructorView.jsx` теперь: `.pl-toolbar` (кнопки «+ Буква», «Печать», «Завершить», все через
  общий класс `.pl-tool`) + `.pl-canvas` (сквозной `.pl-notebook` с блоками) — панели-сайдбара с
  постоянной сеткой букв больше нет. Внутриблочное редактирование строк (`<select>`/✕,
  `LetterBlock.jsx`) не трогали — жалоба была про верхний уровень интерфейса, не про это.
- Тулбар не прибит к экрану (`position` обычный, прокручивается вместе с холстом) — поэтому
  правило safe-area из `CLAUDE.md` для новых fixed/sticky элементов тут не применяется; если
  тулбар когда-нибудь станет `sticky`/`fixed`, это нужно будет добавить.
- `LetterBlock.jsx`: рендерит блок из переданных `rows`; для каждой строки — `<select>` (Целиком /
  Элемент N / Пусто) и кнопка ✕, обе — через `rightSlot` у `RulingRow` (абсолютно позиционированы
  поверх правого края строки, не участвуют в раскладке букв/повторов) и класс `no-print`, так что
  в печати их не видно. `content` строки переводится в набор штрихов через `strokesForContent`:
  `"full"` → все штрихи буквы, число → один штрих с этим индексом (а не накопленная комбинация,
  как было раньше), `"blank"` → пустая линованная строка без единой буквы.
- Разлиновка/печать: ушли от «фиксированные карточки по 4 блока на лист» — теперь один сквозной
  `.pl-notebook`, блоки просто идут друг за другом (`break-inside: avoid` на `.pl-block`), а
  разбивку на физические страницы делает сам браузер при печати (`@page { size: A4; margin: 14mm }`
  в `@media print`). Это правильнее старого ручного деления по 4: теперь блоки разной высоты
  (разное число строк) не ломают разбивку руками посчитанными группами.

## Что сделано (0.1.0, прототип визуала)

- `tools/print_letters/topic.json` — `meta`, один режим `constructor`, 8 карточек-букв семьи
  «Прямые линии» (Г Т П Н И Ш Е Ё), глифы и порядок штрихов — копия из `letter_writing`.
- `src/topics/renderers/print_letters/`:
  - `LetterGlyph.jsx` — общий SVG-компонент буквы: отдельно **опорный штрих** (всегда виден,
    solid/dotted/приглушённый по `variant`/`opacity`) и **штрих-демонстрация пера** поверх него
    (анимируется по тапу/автозапуску, в покое скрыт — это разделение понадобилось: одна и та же
    SVG-механика `dasharray`/`dashoffset` не может одновременно быть «пунктирным узором в покое»
    и «прогрессивной отрисовкой при анимации», наступил на это в первой версии — опорный штрих
    был невидим везде, кроме автозапуска). Цифра-бейдж начала штриха: если два штриха одной буквы
    стартуют в одной точке (оба штриха «Г», левая палочка «П» и т. д.), бейджи каскадом
    смещаются по диагонали с тонкой линией-указателем на настоящую точку — иначе бейджи
    накладываются и виден только последний.
  - `Ruling.jsx` — строка разлиновки (3 линии, без наклонных; `padLeft`/`showMargin`/`justify`
    настраиваются вызывающим — компактным блокам нужна другая раскладка, чем было у полноэкранных
    страниц).
  - `LetterBlock.jsx` — наборный печатный блок одной буквы (см. выше): цветная рамка, ярлычок с
    буквой, кнопка удаления блока, по каждой строке — повтор содержимого (`REPEATS = 10`,
    `justify="space-between"`, чтобы заполнять строку целиком независимо от ширины содержимого) и
    `<select>`+✕ для её настройки, кнопка «+ Строка» внизу.
  - `ConstructorView.jsx` — конструктор: плитки букв (по семьям, одиночный выбор — какая буква
    достанется следующему блоку), кнопка «+ Добавить блок буквы», состояние `blocks`/`rows`,
    сквозной предпросмотр `.pl-notebook`, кнопка «Печать».
  - `engine.js`, `index.jsx`, `print_letters.css`, `media/avatar.svg`.
- Зарегистрировано в `src/topics/renderers/engineRegistry.js` и `src/topics/registry.js`
  (`print_letters` → свой `engine.js`/рендерер). **В `public/decks/catalog.json` тема пока НЕ
  добавлена** — значит, в обычном приложении (по каталогу/зипу) её ещё не открыть; проверялась
  отдельным dev-preview (vite + fabricated task, не часть репозитория, удалён после проверки).
- Проверено визуально (Playwright-скриншоты, не в репозитории): добавление блоков, добавление/
  удаление строк кнопкой, смена содержимого строки через `<select>` (включая «Пусто»), вид под
  `@media print` (панель и органы редактирования скрыты, остаётся только печатное содержимое).

## Чего нет / следующие шаги (решает владелец)

1. **Регистрация как настоящая тема в приложении** — нужно решить, как: `catalog.json` (`hidden`,
   `access: paid`, как `letter_writing`), сборка ZIP (`tools/print_letters/build.mjs` + Vite
   IIFE-бандл `renderer.js`/`mirocard2.css`, см. `rendererLoader.js`) — отдельная задача,
   сознательно отложена, пока не одобрен визуал.
2. **Сохранение тетради** — сейчас список страниц живёт только в состоянии компонента (пропадает
   при закрытии экрана). Полноценная библиотека/синхронизация тетрадей (как `Propis2Home`/
   `propis2:set:*`) — не делали; решить, нужна ли она вообще в этом объёме для печатных букв, или
   достаточно «собрал — распечатал — забыл».
3. **Письмо на экране** — по решению от 2026-11-01, первая волна — только бумага (как сейчас);
   интерактивная обводка пальцем с проверкой пути — отдельный режим второй волной (в
   `letter_writing` уже ЕСТЬ `letter_follow`/`letter_trace`, похожий на то, что потребуется —
   посмотреть `LetterTraceView.jsx`/`LetterFollowView.jsx` как референс, не копировать).
4. **Остальные семьи букв** — только «Прямые линии» (8 букв) сделаны. Дальше (деление владельцем
   не согласовано): диагонали (А М Л У Х Ж К), дуги (О С Э Ю Ф В Б Ь Ъ Ы Я), смешанные
   (Д Р Ч Ц Щ З).
5. **Листы 5–7** (буква+картинка, различение, сортировка схожих) из предложенной лестницы — не
   реализованы, решение по объёму MVP было: сначала листы 1–4.
6. Порядок/направление штрихов (унаследованный из `letter_writing`) и формулировки на страницах —
   ждут проверки владельцем как методистом.
