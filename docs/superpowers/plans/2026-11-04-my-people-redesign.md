# План переделки темы Мои люди

Дата: 4 ноября 2026 года. Основание: [согласованная механика и дизайн](../../my-people-design.md). Проверенная база исходников: [`26a50349d237bae665eb3c586876e2df5450982f`](https://github.com/DmitryMaznich/mirocard/tree/26a50349d237bae665eb3c586876e2df5450982f), приложение `1.0.2817`, встроенная тема `my_people` версии `1.4.0`.

Статус: спецификация и последовательность реализации готовы. Эта фиксация меняет документацию и сохраняет макеты; поведение приложения не изменено. Инженерные имена новых модулей и схем ниже — решения для реализации, а не уже существующие API.

## 1 Порядок работы

Сначала разделить данные и результаты навыков, затем собирать новый вход и экраны. Иначе новый интерфейс продолжит выдавать ответ «мама» за знание имени Анна.

| Этап | Результат | Условие завершения |
| --- | --- | --- |
| P0 | Зафиксированные решения и артефакты | Спецификация, план, макеты 06 и 07 доступны из репозитория |
| P1 | Доменная модель, несколько отношений, версии планов и результатов | Миграция без потери данных; устойчивая идентичность понятий и проб |
| P2 | Генератор заданий и правила обучения | Обе цели, оба задания, поля 2/3/4/6, корректная помощь и повтор |
| P3 | Новый вход, подготовка взрослого, черновик и подтверждённый план | Ребёнок запускает только проверенный самостоятельный план |
| P4 | Экраны занятия и завершения | Компактные кнопки, самостоятельная практика без оценки, правильный результат |
| P5 | Сводка, следующий план, офлайн и общая интеграция | Данные проходят сохранение и bootstrap без искажения |
| P6 | Совместимость, устройства и отдельная приёмка озвучки | Регрессии закрыты, дополнительные упражнения доступны, выпуск подготовлен |

Первый рабочий срез после P1 — цель «Имена», выбор фото, персональные карточки, поле 2/3/4/6 и новый журнал проб. Следом подключается та же доменная модель к называнию и отношениям. Новый основной вход включается после готовности полного сквозного пути; промежуточный срез не заменяет рабочую тему автоматически.

## 3 Доменная модель P1

### Карточка человека

Канонический объект остаётся в `student.myPeople`. Сохраняются `id`, `type`, `name`, `relation`, `contexts`, `photos`, `enabled`, `sentenceLabel`, `legacyAdultId`, `legacyAdultIds`, `mergedInto`, timestamps и флаги участия в предложениях и общении.

Предлагаемое расширение:

```js
{
  peopleSchemaVersion: 2,
  nameVariants: [],
  relations: [
    {
      key: 'classmate',
      label: 'одноклассница',
      acceptedLabels: ['одноклассница'],
      questionForm: 'одноклассницу'
    },
    { key: 'friend', label: 'подруга', acceptedLabels: ['подруга'] }
  ],
  preferredRelationKey: 'classmate'
}
```

Имена полей уточняются в реализации, семантика фиксирована. `relation` остаётся совместимой строкой основной связи. Старое значение не делится на несколько ролей по догадке или запятой: сначала одна соответствующая запись, исходная строка сохранена. Для неизвестной связи создаётся стабильный пользовательский ключ. Род и склонение не выводятся автоматически из пола на фотографии. Для распространённых форм использовать явный словарь; неизвестную форму не исправлять молча.

При объединении карточек объединять новые отношения и варианты имени вместе с фото и alias ID. Не объединять людей только по одинаковому имени. Предъявления и результаты следуют за разрешением `mergedInto`, а история сохраняет исходные ссылки.

### Параметры и подтверждённый план

Конфигурация занятия:

```js
{
  schemaVersion: 2,
  studentId,
  goal: 'name' | 'relation',
  activity: 'select' | 'recall',
  context: 'self' | 'adult',
  targetPersonIds: [],
  distractorPoolIds: [],
  fieldSize: 2 | 3 | 4 | 6,
  initialHint: 'none' | 'prefix' | 'model',
  photoMode: 'primary' | 'available',
  questionCount: 4 | 6 | 8,
  introMode: 'new' | 'all' | 'off',
  voice: true
}
```

`fieldSize` не используется для `recall`. `initialHint` не подменяет помощь в `select`. Значения сохраняются по ученику и комбинации `goal/activity/context`. Подтверждённые самостоятельный и взрослый планы хранятся отдельно от последних параметров и черновика.

Рекомендуемый транспорт — существующий account KV с ключами пространства `my_people`, включающими student ID и scope. Подтверждённый план хранит полную неизменяемую конфигурацию, revision, время и ID подтверждения; фотографии остаются ссылками на канонические карточки, не копиями base64. Существующий `myPeopleProfile` с личными данными не превращается в общий изменяемый объект планов.

На сервере старый offline-документ этого пространства не должен молча заменять более новую подтверждённую версию. Добавить общий для клиента и сервера компаратор версий только для новых документов темы; не менять глобальное поведение всех `kv.upsert`. Конфликт разных подтверждений обрабатывается явно. Авторизация проверяется по аккаунту и ученику.

### Предъявление слова

Ключ включает ученика, person ID, цель, ключ конкретного отношения при необходимости и версию текста понятия. Факт означает «образец предъявлялся», не «знает». Для нового дополнительного отношения старого `introducedAxes: relation` недостаточно.

Хранить предъявление отдельно от редактируемой карточки, чтобы занятие не перезаписывало фотографии, добавленные с другого устройства. Старые `introducedAxes` использовать только как совместимую историю предъявления там, где можно установить точное соответствие слову. Не переносить из них освоение.

## 4 Проба и её результат P1 и P2

У каждой пробы свой `trialId`, отличный от `conceptId`. Повтор одного человека имеет новый `trialId`; возврат после помощи содержит `sourceTrialId`.

Минимальный контракт:

```js
{
  schemaVersion: 2,
  trialId,
  sourceTrialId: null,
  kind: 'main' | 'retry' | 'transfer' | 'intro',
  goal,
  activity,
  context,
  targetPersonId,
  targetRelationKey: null,
  acceptedRelationKeys: [],
  photoRef,
  choicePersonIds: [],
  initialHint,
  assistanceUsed: [],
  firstChoiceCorrect: null,
  outcome: 'independent' | 'prompted' | 'not_recalled' |
           'practice' | 'skipped' | 'presented',
  conditionsFingerprint
}
```

Для открытого называния связи взрослый не сообщает, какое именно слово произнесено. Поэтому `targetRelationKey` остаётся пустым, а `acceptedRelationKeys` — это допустимый набор, не список проверенных слов. Для конкретного выбора по отношению задаётся один проверяемый ключ.

Помощь, ошибка первого выбора и завершение коррекции — события одной пробы. Касание подсвеченного ответа не создаёт второй самостоятельный успех. Самостоятельный ответ в `retry` записывается честно, но не смешивается с основными пробами.

Сохранять новый журнал в versioned-секции `statistics.myPeople`, используя существующий JSON-транспорт сессий. `computeSessionRecord` сейчас сворачивает `assessments` и теряет нужную последовательность; это не основной источник нового результата. Количество интро, `practice` и `skipped` не входит в знаменатель проверенной точности. Для практики правильность и процент — `null`, а не 0 или 100.

Не хранить запись речи, видео или последовательность сырых тапов. Для согласованной механики достаточно результата пробы, факта первого неверного выбора, помощи и условий.

## 5 Генератор P2

Добавить чистые функции нормализации конфигурации, readiness, построения проб, неоднозначности имени и отношения, плана повторения и краткого результата. UI не дублирует правила генератора.

- Источник — только активные карточки текущего ученика с допустимыми фото.
- Вопросы строятся по целевому набору; отвлекающие варианты берутся из отдельного набора.
- В каждой выборной пробе ровно N разных людей; нет дублирования одного лица как разных ответов.
- Неоднозначность имени определяется запрашиваемой формой имени и допустимыми вариантами; примитивная проверка только первого слова из HTML не переносится в production.
- По отношению все подходящие люди исключаются из дистракторов. При неожиданно неоднозначном поле верный альтернативный ответ не штрафуется.
- Нельзя незаметно уменьшать N. Readiness даёт причину для конкретной цели после всех фильтров.
- Равномерное покрытие целей, без трёх одинаковых подряд и без закрепления позиции за человеком.
- Чередуются реально доступные фото. Не изображать перенос там, где второе фото отсутствует.
- Возврат после помощи — после двух других вопросов, если это возможно; не раздувать раунд бесконечно. Изменять позицию ответа и сохранять проверяемое слово.
- Отсутствие ответа не оценивается таймером. Первая подсказка по запросу. При заданной начальной помощи «Полностью сам» недоступно сразу.
- Подсказка при назывании — начало слова, затем полный образец. Не переносить `slice(0, 2)` из демонстрационного JS как логопедический алгоритм.
- В знакомстве показывать конкретное слово. Модель перед проверкой называния не включается тайно.
- Питомцы разрешены для имён; человеческие отношения им не назначаются.

Пакет P2 готов, когда новые пробы можно генерировать и оценивать независимо от React, а контракт сохраняет различия целей, помощи и повторов.

## 6 Навигация и UI P3 и P4

Предлагаемые новые модули в `src/features/myPeople/`: домашний экран, подготовка, параметры, хранение планов, сводка. Логику проб отделить в доменные JS-модули, рендерер использовать для сцен. Конкретные имена файлов допускают адаптацию к структуре проекта.

Точки интеграции: `src/App.jsx`, `src/core/store.js`, вход темы из домашнего экрана и планировщика, `ModePickerScreen.jsx`, `ParamsScreen.jsx`, `SessionScreen.jsx`, `useSessionEngine.js`.

Маршрут:

```text
Экран ребёнка → подтверждённый самостоятельный план → занятие
      ↓
Для взрослого → цель + формат + задание → параметры → подтверждение

Занятие → завершение ребёнка → сводка взрослого → черновик следующего плана
```

Использовать существующий доступ взрослого. Не переносить взрослую защиту в браузерный флаг из HTML. При первом запуске нужен реальный план; демонстрационный `DEFAULT_PLAN` не является миграцией учеников.

Подтверждённый план не должен быть ссылкой на живой объект параметров. После подтверждения его изменение требует нового подтверждения. Детский запуск сохраняет конфигурацию сессии как snapshot. Во время задания настройка не меняет уже созданные пробы.

Экран называния: одна фотография, вопрос, динамик повторения и четыре компактные кнопки. Убрать поясняющий текст из нижней панели. Сохранить достаточную площадь касания, доступность без цвета и стабильное положение фото при появлении подсказки.

Самостоятельное называние: модель и следующий шаг, без оценочных кнопок. Самостоятельный выбор: автоматическая оценка выбора и детская помощь. Детское завершение и взрослая сводка — разные экраны.

Не копировать глобальные селекторы `.phone`, `body`, стили review-sidebar и фиктивные данные из HTML в приложение. Демонстрационные ID, пол по имени файла, встроенные фото и локальный `localStorage` не заменяют доменную модель, IndexedDB и синхронизацию.

Соблюдать реальные настройки темпа ученика (`lessonFlow`): автоматический переход или касание. 850/1250 мс из макета не являются принятой настройкой. При навигации отменять старую речь и таймеры; одна реакция не может завершить следующую пробу.

## 7 Статистика синхронизация и восстановление P5

1. Протащить типизированный результат через `useSessionEngine`, `sessionEngine`, сохранение checkpoint/final и `session.append`.
2. Проверить, что `statistics.myPeople` и полная конфигурация проходят backend JSON и `bootstrap` без удаления дополнительных полей.
3. Добавить сведения о фактическом размере `choices`; существующий `captureConditions` видит только `options`.
4. Стабильные ID проб и revision обеспечивают идемпотентность: двойное касание, переотправка offline и переход checkpoint → final не удваивают результат.
5. Восстановление учитывает ученика, topic/schema version, подтверждённый plan revision, цель, задание, контекст, target/pool IDs и параметры. После изменения плана нельзя продолжить старое занятие с другим полем под видом нового.
6. Помощь, фаза коррекции и показ модели переживают восстановление; после перезапуска нельзя снова поставить «сам» в уже подсказанной пробе.
7. Удалённые/объединённые карточки разрешаются по каноническим ID. Недоступные фото не заменяются случайными людьми.
8. Смена ученика и аккаунта не переносит подготовленный план, состояние предъявления и результат другому ребёнку.
9. Следующий план — черновик по реально завершённым пробам. При одной трудной цели добавляется знакомый материал для чередования. Подтверждённый план до принятия черновика не меняется.

Вызовы `onStreakReset` сейчас используются и после таймера подсказки. Их нельзя переиспользовать как универсальную запись помощи: они одновременно влияют на ошибки и призы. Для запроса помощи использовать отдельный assisted/prompted путь. Реальный первый неверный выбор учитывается согласно существующей политике ученика. Глобальные правила призов других тем не переписываются.

## 8 Миграция и дополнительные упражнения P1 и P6

- Сначала аддитивное чтение и запись новых полей, затем новый UI. Не выполнять разрушительную конверсию массива людей.
- Сохранить строковое `relation`, старые `introducedAxes`, исторические concept/mode ID и настройки дополнительных упражнений.
- Старое `person_naming:<id>` принимало имя или роль. Его точность остаётся `legacy`, без распределения по новым целям.
- Старое `point:<id>` спрашивало `mainWord`; нельзя объявить все эти записи проверкой имени.
- Не переносить автоматически «Обо мне» в называние по фото: это другой контекст ответа.
- Старые ссылки планов уроков продолжают разрешаться. Не подменять задачу на чтение новым выбором фотографии под тем же ID.
- Дополнительные упражнения доступны взрослому отдельно от основного входа. Их данные не удаляются; существующая лестница сохраняется, расширение поля там, где оно применимо, входит в отдельный шаг P6.
- Контекст `home` и связи с предложениями/общением не переименовываются в «друзей» и не удаляются при обновлении групп.

Рекомендуемый внутренний контракт новых основных заданий — версия v2 с явными `goal/activity/context`. Не обязательно добавлять восемь пользовательских режимов. Адаптер связывает новый план с устойчивым внутренним режимом/версией, а старые ID остаются обслуживаться отдельно.

## 9 Проверки

### Доменные и данные

- Миграция строки отношения, нескольких связей, вариантов имени, удалений и объединений; повторная миграция ничего не дублирует.
- Два разных человека с одним именем остаются разными. Неоднозначные формы не попадают в дистракторы.
- Имя и роль не принимаются друг за друга; Саша с двумя отношениями не получает ложной ошибки.
- Все восемь основных комбинаций имеют правильный контракт оценки.
- Поле 2/3/4/6 после всех фильтров; отдельный pool; недостаток и неоднозначность; отсутствие дубликатов.
- Генерация не даёт трёх одинаковых целей/позиций и не закрепляет за человеком угол.
- Реальные варианты фото и единственное фото; конкретные новые отношения; предъявление не равно освоению.
- Ошибка + исправление дают одну aided-пробу, повтор имеет новый ID и ссылку на исходную; нет бесконечных повторов.
- Начальная помощь и любая подсказка исключают independent в текущей пробе; новая проба сбрасывает только своё состояние.
- Самостоятельная практика и пропуск не дают процента правильности; открытая связь не засчитывает весь набор ролей.

### Интеграция

- Черновик → подтверждение → самостоятельный запуск; изменение черновика не меняет готовый план.
- Офлайн запись → очередь → сервер → bootstrap; два устройства редактируют разные карточки и разные планы без потерь.
- Устаревшая offline-версия не заменяет новое подтверждение; конфликты видны.
- Checkpoint/final и восстановление без двойного результата; смена условий не восстанавливает несовместимую сессию.
- Карточки продолжают работать в общении, предложениях, важных датах и дополнительных упражнениях.
- Первый запуск без плана; пустое окружение; недостающие дистракторы; удалённые фото; смена ученика и выход из аккаунта.

### Визуальная и ручная приёмка

- 320/360/390 px, планшет, desktop; поля 2/3/4/6 и длинные имена.
- iOS safe area: существующие `--app-safe-*`; без двойных отступов и перекрытых нижних кнопок.
- В панели четыре кнопки, без методического текста; фото не прыгает при подсказке.
- Режимы tap/auto согласно настройкам ученика, пауза и прерывание озвучки.
- Отдельная проверка произношения и окончательных голосов с владельцем.

## 10 Выпуск и завершение

Обязательное условие владельца: возможность вернуться к текущей версии. Сохранён production baseline `1.0.2818` / `9b7ca097983cd5cc2906563063deab45be7412c5` в ветке `backup/my-people-before-redesign-2026-11-04`. Перед реализацией прочитать [план отката](../../my-people-rollback.md): старый путь за переключателем, обратимая схема, тест старого клиента на новых данных, проверенная резервная копия БД и фото перед выпуском. Код разрабатывать в отдельной ветке. Новые функции темы должны быть проверены полным путём, прежде чем заменить основной вход. При первых промежуточных изменениях сохранять возможность старого маршрута.

Перед производственным выпуском: все данные и история сохранены, основные сценарии приняты, аудио принято отдельно, версия приложения увеличена по `CLAUDE.md`, сборка проходит, diff проверен. `main` автоматически разворачивается на Railway — фиксация документации не является разрешением на выпуск незавершённой реализации.

После разрешённого выпуска проверить `/api/version`, доступность приложения, реальный самостоятельный запуск и занятие со взрослым. Для `my_people` не требуется пересобирать deck ZIP. При откате интерфейса новые аддитивные поля и старые карточки остаются читаемыми.

Критерий завершения переделки: родитель может подготовить занятие, ребёнок — пройти доступный самостоятельный сценарий, взрослый — корректно проверить называние, а результат показывает только реально проверенный навык и условия его выполнения.
