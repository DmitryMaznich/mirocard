# Дизайн: Тема «Звуки и буквы» (фонематический анализ слова)

**Дата:** 2026-07-05
**Автор:** Dima (при консультации Claude в роли логопеда)
**Статус:** Approved

---

## Цель

Тема-тренажёр для детей 5-7 лет с нарушениями речи (ОНР, ФФНР), работающих с логопедом, на этапе подготовки к чтению. Ребёнок анализирует звучание слова (по картинке-опоре, без озвучки приложением) и сопоставляет анализ со знакомыми буквами.

Референс-аналог на рынке — игра «IQ Лото. Азбука. Подбери букву» (Airis): картинка → подбор буквы первого звука. Наша тема шире и методически строже: 4 режима вместо одного, честное разделение звука и буквы, дистракторы по логопедическим парам смешения вместо декоративных.

Задачи:

1. Определить первый звук слова по картинке
2. Определить последний звук слова по картинке
3. Определить позицию заданного звука в слове (начало / середина / конец)
4. Вставить пропущенную букву в написанном слове (по картинке)

---

## Педагогическая рамка

### Исправленные ошибки референсных продуктов

- **Буква ≠ звук.** В режимах 1-3 слово не показывается написанным — только картинка. Ребёнок называет слово вслух сам (или слышит от логопеда), затем анализирует звучание. Подпись слова появляется только в режиме 4, где задача уже сознательно орфографическая.
- **Порядок навыков.** Первый звук → последний звук → позиция звука → пропущенная буква — по возрастанию сложности (Эльконин, Ткаченко): выделение первого звука проще последнего; произвольная позиция сложнее обоих.
- **Честная, но дозированная работа с фонетическими сложностями.** Банк слов v1 подобран так, чтобы целевой звук был фонетически однозначным (см. «Критерии отбора слов» ниже). Йотированные гласные, оглушение на конце слова, твёрдость/мягкость как отдельный навык — вынесены в v2 (см. «Вне рамок v1»), а не скрыты произвольно.
- **Дистракторы — по логопедическим парам смешения**, а не случайные буквы (см. ниже).

### Без аудио

Приложение не озвучивает ни слово, ни звук буквы (ни TTS, ни mp3). Стимул — только картинка. Слово ребёнок называет сам вслух или слышит от взрослого/логопеда вживую — это методически предпочтительнее записи, так как даёт живую артикуляционную модель. Приложение оценивает выбор буквы/зоны, не пытаясь распознавать речь.

## Данные

### Структура слова в банке

Каждое слово — один концепт с полями:

```json
{
  "word": "сом",
  "imageId": "phon_som",
  "targetSoundFirst": "с",
  "targetSoundLast": "м",
  "targetLetterFirst": "С",
  "targetLetterLast": "М",
  "positionWords": [
    { "targetLetter": "С", "position": "start" },
    { "targetLetter": "О", "position": "middle" },
    { "targetLetter": "М", "position": "end" }
  ],
  "blanks": [
    { "blankIndex": 0, "targetLetter": "С" }
  ],
  "difficultyTier": 1
}
```

- `targetSoundFirst` / `targetSoundLast` — фонетическая запись звука (не орфографическая), используется для подбора дистракторов и валидации в режимах 1-2.
- `positionWords` — список валидных пар «буква → позиция» для режима 3 (обычно 1-3 записи на слово, не для каждой буквы слова — только там, где позиция однозначна).
- `blanks` — список позиций, допустимых для пропуска в режиме 4 (только согласные в сильной позиции, гласные — только под ударением).
- `difficultyTier` — 1 (простое CVC-слово без стечений) или 2 (стечения согласных, более длинное слово).

### Критерии отбора слов (v1)

Общие для режимов 1-3:
- Не брать слова, начинающиеся с Е/Ё/Ю/Я (йотированность первого звука).
- Уровень 1 сложности — без стечений согласных в целевой позиции.

Режим 2 (последний звук):
- Только слова без оглушения на конце (сонорные, глухие по природе, гласные на конце): «сом», «шар», «кит», «окно». Слова с оглушением («зуб», «нож») — в v2.

Режим 3 (позиция звука):
- Целевой звук встречается в слове один раз (без повторов) — позиция однозначна. Не берём «барабан» для звука «б».

Режим 4 (пропущенная буква):
- Пропуск — согласный в сильной позиции: не в конце слова перед паузой (оглушение), не перед Ь/йотированной гласной.
- Гласные пропуски — только под ударением (без риска акающей редукции: не «м_локо»).

### Картинки

Генерируются через существующий cardgen-studio pipeline (Gemini) под список слов из банка. Хранятся как статичные ассеты темы (аналогично тому, как `written_letters` хранит свои SVG-данные в `letterData.js`), а не как cardgen ZIP-колода — это builtin-renderer тема, не image-driven cardgen-колода.

**Открытый технический вопрос для этапа планирования:** cardgen-studio pipeline (`cardgen-cli.mjs`) на сегодня заточен под полный цикл image-driven колоды (spec.json → import → render → review → build ZIP в `public/decks/`). Для этой темы он нужен только на шаге генерации картинок (без audio/icons/ZIP-этапов). Нужно на этапе `writing-plans` проверить, можно ли использовать пайплайн частично (только `import`+`render`) и забрать готовые PNG из `cardgen-studio/projects/<id>/` напрямую как статичные ассеты темы, либо потребуется отдельный скрипт-обёртка.

### Объём стартового банка

25-30 слов, покрывающих основные пары смешения (см. ниже) минимум по 2-3 раза каждую, чтобы дистракторному движку было из чего выбирать варианты.

### Словарь фонетических пар смешения (`phoneticDistractors.js`)

```json
{
  "б": ["п"], "п": ["б"],
  "в": ["ф"], "ф": ["в"],
  "г": ["к"], "к": ["г"],
  "д": ["т"], "т": ["д"],
  "ж": ["ш"], "ш": ["ж"],
  "з": ["с"], "с": ["з", "ш", "щ"],
  "ц": ["с", "т"],
  "ч": ["щ", "ть"],
  "л": ["р", "й"], "р": ["л"]
}
```

Правило подбора дистракторов для конкретного задания:
1. Один дистрактор — обязательно буква из пары смешения для целевого звука (если пары нет в словаре, например для гласных — берётся ближайшая гласная той же артикуляционной группы).
2. Остальные 1-2 варианта — случайные буквы вне пары смешения и графически непохожие на цель (чтобы не смешивать фонетическую и графическую путаницу без необходимости).
3. `difficultyTier` слова определяет, разрешено ли дистрактору быть одновременно фонетически и графически похожим (продвинутый уровень) или только фонетически (базовый).

Реализуется как отдельный модуль рядом с существующим `src/shared/utils/distractorEngine.js`, использующий тот же паттерн выбора, что и `selectDistractorConceptIds`, но с фонетическим словарём вместо `similarityGroups`.

## Режимы

### Режим 1: `first_sound` — «Первый звук»

- **Стимул:** картинка, без подписи слова
- **Ответ:** 3-4 кнопки-буквы, тап по правильной
- **Дистракторы:** 1 из пары смешения для `targetSoundFirst` + 1-2 нейтральные
- **Правильный ответ:** `targetLetterFirst`

### Режим 2: `last_sound` — «Последний звук»

- Идентичная механика режиму 1, целевая позиция — конец слова (`targetSoundLast` / `targetLetterLast`)
- Банк слов исключает финальное оглушение (см. критерии отбора)

### Режим 3: `sound_position` — «Где спрятался звук»

- **Стимул:** картинка + целевая буква/звук показаны явно вверху крупно
- **Ответ:** слово представлено как визуальная полоска-«гусеница» из трёх нейтральных сегментов (начало / середина / конец, без букв внутри) — ребёнок тапает нужный сегмент
- **Данные:** берётся случайная запись из `positionWords` слова
- **Отличие от режимов 1-2:** не «назови звук», а «найди заданный звук в слове» — тренирует позиционный анализ отдельно от вычленения звука

### Режим 4: `missing_letter` — «Пропущенная буква»

- **Стимул:** картинка + написанное слово с одним пропуском (по `blanks`)
- **Ответ:** варианты букв, тап по правильной
- **Дистракторы:** строго по фонетическим парам смешения для пропущенной буквы
- **Отличие от режимов 1-3:** слово показано написанным — это уже орфографическая задача поверх сформированного фонематического навыка

## Архитектура

### Файловая структура

```
src/topics/renderers/phonetic_analysis/
  index.jsx                ← точка входа, switch по task.type
  engine.js                 ← generateTasks() для всех 4 режимов
  wordBank.js                ← банк слов (см. «Данные»)
  phoneticDistractors.js     ← словарь пар смешения + функция подбора
  SoundMatchView.jsx         ← режимы first_sound, last_sound, missing_letter (общая раскладка: картинка/слово + кнопки-буквы)
  SoundPositionView.jsx      ← режим sound_position (полоска с тремя зонами)
  phonetic_analysis.css
```

### `engine.js`

```js
export function generateTasks(modeType, cards, _sessionSize, params) {
  switch (modeType) {
    case "first_sound":     return generateSoundTasks(cards, "first");
    case "last_sound":      return generateSoundTasks(cards, "last");
    case "sound_position":  return generatePositionTasks(cards);
    case "missing_letter":  return generateBlankTasks(cards);
  }
}
```

Дистракторы подбираются через `phoneticDistractors.js` (см. «Словарь фонетических пар смешения»).

### `SoundMatchView`

Универсальный компонент для режимов `first_sound`, `last_sound`, `missing_letter`:
- Картинка сверху (крупно)
- Для `missing_letter` — под картинкой слово с пропуском на месте нужной буквы
- Снизу — ряд кнопок-букв (3-4 варианта)
- Тап → зелёный/красный feedback → `onAdvance()`

### `SoundPositionView`

- Крупная целевая буква вверху
- Картинка слова
- Слово представлено как полоска из трёх зон (начало/середина/конец), без текста внутри
- Тап по зоне → feedback → `onAdvance()`

### Регистрация

Добавление в `src/topics/registry.js` (маппинг renderer id → компонент) и `src/topics/builtinTopics.js`/`topicLoader.js` (id темы `phonetic_analysis`, дефолтные modes, methodology-описание) — по образцу `written_letters`.

### Аудио

Не используется. Ни TTS (`useSpeech.js`), ни готовые mp3 (`public/sounds/letters/`) в этой теме не задействуются.

## Вне рамок v1 (кандидаты на v2)

- Твёрдость/мягкость согласного как отдельный навык (цветовая схема по Эльконину: синий/зелёный/красный)
- Йотированные гласные («буква одна — звуков два»)
- Слова со стечением согласных и позиционным оглушением — расширение банка слов внутри существующих режимов
- Полный звуко-слоговой анализ с подсчётом звуков (фишки Эльконина, построение схемы слова целиком)

---

## MVP vs полная версия

**MVP (итерация 1):** 25-30 слов уровня сложности 1 (без стечений), все 4 режима, минимальный словарь пар смешения, покрывающий эти слова.

**Полная версия v1:** банк расширяется до покрытия всех пар смешения из словаря `phoneticDistractors.js` равномерно, добавляется уровень сложности 2 (стечения согласных) там, где режим это допускает.
