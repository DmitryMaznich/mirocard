# Написание слов — design spec

**Дата:** 2026-08-07
**Тема:** Прописи (`propis`)

## Цель

Новый режим темы «Прописи» — **«Написание слов»**. Ребёнок набирает слово на
экранной клавиатуре, и приложение автоматически собирает и проигрывает
(в цикле) анимацию написания этого слова целиком — рукописным пером, тем же
визуальным языком, что уже используется для демонстрации одной буквы
(режим «Учим буквы» / `PropisPracticeView`).

Источник букв — только рукописный захват через инструмент «Мастерская
траекторий» (`tools/letter_capture/handwriting_capture.html` →
`tools/propis/topic.json`), не шрифтовые данные `written_letters`.

**Условие релиза темы:** все 33 буквы алфавита (обе формы, где применимо)
должны быть отсняты рукой до включения режима «Написание слов» в прод.
Никакой UI-обработки «буква ещё не записана» в этом режиме не
предусматривается — предполагается, что на момент показа ребёнку данные уже
полные.

## Часть 1 — Классификация входа/выхода буквы

Каждая захваченная буква автоматически получает `entryLine` и `exitLine` —
номер (1–7) одной из уже существующих пронумерованных направляющих линий
разлиновки (`tools/letter_capture/handwriting_capture.html`, функция
`drawRuling()`; та же геометрия — `propisRuling.js` в приложении):

| № | Линия | Y (в системе 100×150) |
|---|-------|------------------------|
| 1 | L1 (верх строки) | 10 |
| 2 | середина верхнего выноса | 36 |
| 3 | L2 (верх рабочей строки) | 62 |
| 4 | середина узкой строки | 75 |
| 5 | L3 / базовая линия | 88 |
| 6 | середина нижнего выноса | 110 |
| 7 | L4 (низ строки) | 140 |

Логика классификации — чистая функция, без ручной разметки:

- `entryLine` буквы = номер линии, ближайшей по Y к первой точке первого
  штриха.
- `exitLine` буквы = номер линии, ближайшей по Y к последней точке
  последнего штриха.

Эмпирическая проверка на шрифтовых данных (`written_letters/letterPaths.js`,
как ориентир формы, не как источник финальных данных) показала, что
подавляющее большинство строчных букв входят и выходят на линии 4; буквы с
росчерком вниз (д, з, у, ц, щ) выходят на линии 5; б и в входят выше — ближе
к линии 2–3. Т.е. реально используемых комбинаций перехода — единицы, а не
тысяча теоретически возможных пар букв.

## Часть 2 — Захват соединительных штрихов

В `handwriting_capture.html` добавляется третий тип записи (наравне с
«Буква(ы)» и «Элемент»): **«Соединитель»**. Вместо текстового поля с
буквами — два выпадающих списка `fromLine` / `toLine` (1–7). Рисуется тем же
способом, что и буква/элемент; сохраняется в тот же набор с ключом вида
`conn_<fromLine>_<toLine>`.

Хранение — `tools/propis/topic.json`, новый массив на верхнем уровне:

```json
"connectors": [
  { "id": "conn_5_4", "fromLine": 5, "toLine": 4, "viewBox": "0 0 100 150", "strokes": [{ "d": "..." }] }
]
```

Коннектор захватывается один раз на пару линий (не на пару конкретных букв).
При сборке слова он растягивается по горизонтали под фактический зазор
между реальными точками выхода/входа конкретных букв — своя высота/форма не
меняется, меняется только ширина. Переходы, где `fromLine === toLine`
(доминирующий случай — 4→4), рисованного коннектора не требуют вовсе: между
такими точками генерируется простая прямая/лёгкая дуга алгоритмически (см.
часть 3).

**Условие релиза:** для каждой реально встречающейся в алфавите комбинации
`(exitLine, entryLine)`, где линии не совпадают, соответствующий коннектор
должен быть отснят. Отсутствие коннектора не должно приводить к падению —
на время разработки используется тот же алгоритмический прямой мостик, что
и для совпадающих линий (dev-заглушка, не финальное поведение).

## Часть 3 — Движок сборки слова

Новый чистый модуль (без React): `src/topics/renderers/propis/wordEngine.js`.

```js
buildWordTrajectory(word: string, letters: Map<char, LetterRecord>, connectors: Map<string, ConnectorRecord>): { strokes: Stroke[], totalWidthUnits: number, viewBox: string }
```

Алгоритм:

1. Буквы слова раскладываются слева направо, каждая в слоте фиксированной
   ширины (`VB_W = 100`, тот же слот, что уже используется при захвате).
2. Для каждой пары соседних букв берутся `exitLine` первой и `entryLine`
   второй (часть 1):
   - **Совпали** → генерируется прямой/слегка изогнутый мостик между
     реальными точками (в мировых координатах после раскладки), без
     обращения к библиотеке коннекторов.
   - **Не совпали** → берётся коннектор `conn_<exitLine>_<entryLine>` из
     библиотеки, его собственная стартовая точка совмещается с точкой
     выхода первой буквы, дальше коннектор растягивается по горизонтали,
     пока его конечная точка не совпадёт с точкой входа второй буквы.
3. Итог — один сплошной упорядоченный список штрихов на всё слово: `[буква₁
   штрихи…, мостик₁, буква₂ штрихи…, мостик₂, …]`.

Этот список подаётся в тот же аниматор, что уже проигрывает одну зацикленную
букву (`LoopingLetterCell` — штрих за штрихом, с точкой-пером), только
теперь на входе не одна буква, а весь список штрихов слова.

## Часть 4 — UI режима «Написание слов»

Новый компонент `WriteWordsView.jsx`, один экран (без отдельного экрана
выбора, в отличие от `LetterPickerScreen` буквенного режима):

```
┌──────────────────────────────────┐
│ [×]                    закрыть   │
│                                   │
│  ┌─────────────────────────────┐ │ ← карточка-«тетрадь»: та же
│  │  анимация слова (петля)     │ │   разлиновка propis, что и в
│  └─────────────────────────────┘ │   букве, растянута под слово
│                                   │
│   Мама              ←  Очистить  │ ← превью набранного слова
│                                   │
│  [▲ЗАГЛ.]  [клавиатура алфавита, │
│  [▼строч.]  как в «Учим буквы»]  │
└──────────────────────────────────┘
```

- Клавиатура и переключатель регистра — переиспользуются из
  `PropisPracticeView` как есть (те же ряды АБВ…, тот же
  `▲ ЗАГЛАВНАЯ / ▼ строчная` тумблер слева от клавиатуры). Тумблер —
  **постоянный переключатель режима**, не Shift с автосбросом: ребёнок
  переключает регистр перед вводом каждой буквы, если нужно (типичный
  сценарий — «ЗАГЛАВНАЯ» → одна буква → «строчная» → остальные).
- Так как в этом режиме все буквы обязаны быть отсняты (условие релиза),
  никаких неактивных/disabled клавиш на клавиатуре нет — она полностью
  рабочая с первого экрана.
- Превью слова — обычный текст, кнопка «←» стирает последнюю букву, «Очистить»
  сбрасывает всё поле.
- Как только в поле есть хотя бы одна буква, `wordEngine.buildWordTrajectory`
  пересобирает траекторию и карточка сверху начинает (или обновляет)
  зацикленную анимацию.

## Тестирование

Unit-тесты (vitest, `wordEngine.test.js`):

- классификатор: по заданным синтетическим штрихам корректно определяет
  `entryLine`/`exitLine`;
- генератор прямого мостика: по двум точкам — корректный сегмент;
- `buildWordTrajectory` на моковых буквах/коннекторах: корректный порядок и
  состав итогового списка штрихов, включая случай отсутствующего
  коннектора (dev-заглушка прямой линией, без падения).

Визуальная проверка — вручную через `WriteWordsView` в браузере, отдельного
Playwright-сценария на первой итерации не предусмотрено.

## Вне рамок (пока не делаем)

- Обработка незаписанной буквы в UI — не нужна, т.к. полный алфавит это
  условие релиза темы.
- Экспорт/печать слова на бумаге (PDF-режим) — отдельная задача,
  пересекается с уже существующим, но неподключённым `PropisShowView.jsx`.
