# Редизайн экрана «Начать готовить» (RecipeStartParams)

## Контекст

`RecipeStartParams` в `src/features/session/ParamsScreen.jsx` — экран настроек перед
готовкой одного рецепта: выбор числа порций и (для 5 ключевых полей chicken.txt —
`oil`, `butter`, `sauteTime`, `fryTime`, `simmerTime`) степперы количеств/времени,
реализованные в задаче «Осмысленное масштабирование порций рецептов»
(`docs/superpowers/specs/2026-07-18-recipe-portion-scaling-design.md`).

Экран визуально не проработан: степпер порций — голая пара кнопок с числом; список
степперов — общий заголовок «Количества» без разделения ингредиентов и времени;
двухстрочные подписи наезжали на контрол при длинных названиях и длинной записи
значения («4 с половиной столовой ложки»).

Дизайн проработан итеративно через интерактивный HTML-мокап (см. историю чата,
финальная версия — [артефакт](https://claude.ai/code/artifact/50668204-ee83-4d09-aa70-006d3af76bd7)),
согласован с пользователем за три раунда правок. Эта задача переносит согласованный
визуал в реальный код `ParamsScreen.jsx`/`styles.css`.

## Явное ограничение охвата

Переносим редизайн **только для полей, уже размеченных `{ключ:...}` в тексте шага** —
сейчас это 5: `oil`, `butter`, `sauteTime`, `fryTime`, `simmerTime`. Остальные
ингредиенты рецепта (курица, лук, морковь, сливки, соль, специи, укроп) на этот экран
не выводятся — как и сейчас. Мокап показывал все 9 ингредиентов ради стресс-теста
компактности по высоте, а не как функциональное требование. Расширение того, какие
поля получают ключ/override — отдельная будущая задача, не эта.

## Дизайн

### 1. Порции — ряд фигурок вместо голого степпера

8 фигурок «пряничного человечка» (SVG-силуэт: голова-круг + руки + ноги — узнаваемый,
однозначный силуэт, легче для восприятия ребёнком с РАС, чем абстрактная капля/блок).
Заполненные (`n ≤ portions`) — сплошной горчичный цвет (`#d9a441`) с двумя точками-
глазами; незаполненные — контурные, пунктирный обвод, `opacity: 0.75`, слегка меньше
(`scale(0.86)`). Каждая фигурка слегка наклонена (`±2.5–3deg`, чередование по чётности)
для живости. При +/- новая заполняемая фигурка получает pop-анимацию
(`cubic-bezier(.34,1.56,.64,1)`, перелёт масштаба).

Под рядом — фраза `formatPortionsPhrase(portions)` (уже есть в
`parseRecipeTxt.js`, ничего нового реализовывать не нужно), под ней — компактный
контрол `− N +` (переиспользует текущую роль `all-texts-portions-btn`, но новая
разметка/стили).

Смена порций сбрасывает `ingredientOverrides` — это уже так в текущем коде
(`changePortions`), не меняется.

### 2. Список — две секции, однострочные строки

Вместо одного `param-section` с заголовком «Количества» — две секции: «Ингредиенты»
(`oil`, `butter`) и «Время готовки» (`sauteTime`, `fryTime`, `simmerTime`). Заголовок
каждой секции — не текст, к нему добавляется одна маленькая SVG-иконка (миска — для
ингредиентов, часы — для времени). **Иконки убраны с каждой строки** — только в
заголовке секции.

Строка — снова однострочная (подпись слева, степпер справа на той же линии), а не
двухъярусная (как в промежуточной версии мокапа) — это стало возможным благодаря
двум изменениям:
- нет иконки строки → +46px свободного места;
- значение степпера показывается в компактной записи (`4½ ст.л.` вместо
  «4 с половиной столовой ложки» — грамматически верное склонение остаётся только в
  тексте шага готовки, экран настроек — для взрослого, не для чтения ребёнком вслух).

«Правка · вернуть» — рендерится инлайново сразу после подписи, **только когда есть
override** (не резервирует место на пустых строках, как было раньше).

### 3. Формат данных `# adjustable:` — 4 колонки вместо 2

Текущий формат (`key | label`) не даёт данных для группировки (ингредиент/время) и
для компактной единицы измерения. Новый формат:

```
# adjustable:
#   oil | ingredient | Растительное масло | ст.л.
#   butter | ingredient | Сливочное масло | ст.л.
#   sauteTime | time | Лук и морковь на сковороде | мин
#   fryTime | time | Курица на сковороде | мин
#   simmerTime | time | Тушение в сливках | мин
```

`parseAdjustable()` в `builtinRecipesTopic.js` возвращает `{ [key]: { group, label,
unit } }` вместо `{ [key]: label }` — единственное место разбора этого блока (у
Планировщика степперов нет, `recipeParser.js` этот блок не читает и не должен).

`group` — строковый литерал `'ingredient'` или `'time'` (не enum в коде, просто две
ожидаемые строки; невалидное/отсутствующее значение — просто не попадёт ни в одну
секцию, без падения).

### 4. Компактный формат значения — новая функция `formatCompact`

Экспортируется из `parseRecipeTxt.js` рядом с `formatWithUnit` (та же логика
округления до 0.5, другой хвост):

```js
export function formatCompact(val, unit) {
  const snapped = Math.round(val * 2) / 2;
  const whole = Math.floor(snapped);
  const isHalf = snapped - whole === 0.5;
  const num = isHalf ? (whole > 0 ? `${whole}½` : '½') : `${whole}`;
  return `${num} ${unit}`;
}
```

Юнит-тесты рядом с существующими тестами `formatWithUnit`.

### 5. CSS — новые классы, не трогаем `.param-row`/`.stepper-btn`

`.param-row`/`.param-label`/`.param-stepper`/`.stepper-btn`/`.stepper-value`/
`.param-section` — общие классы, используются другими экранами настроек (сравнение,
столбик и т.д.). Редизайн получает **отдельные, не пересекающиеся** имена классов
(префикс `rp-`, «recipe params»), чтобы не задеть визуал других режимов:
`rp-people-hero`, `rp-person`, `rp-people-phrase`, `rp-people-control`,
`rp-section`, `rp-section-icon`, `rp-ledger`, `rp-row`, `rp-row-main`,
`rp-row-label`, `rp-row-note`, `rp-row-control`, `rp-spoon-btn`, `rp-row-value`.

Палитра — существующие хардкод-значения из этого же файла (тот же паттерн, что уже
используют соседние правила): тёмный чай `#1c7a6e`/`#4a9b8f`, горчичный `#d9a441`,
крем `#fffaf0`, чернила `#1a2e2b`/`#3a5c58`/`#7a9e9a`, линия `#c8d4d2`. Ничего нового
не вводится.

Строка «Порций» и блок «Цифры на плите» / топпинги вне области редизайна — остаются
на `.param-row` как есть, редизайн затрагивает только hero-блок порций и список
`oil`/`butter`/`sauteTime`/`fryTime`/`simmerTime`.

## Что не делается в этой задаче

- Не расширяется список полей с `{ключ:...}` — остаются те же 5.
- `# ingredients:`/Планировщик/Покупки не трогаются — там иконок и группировки нет и
  не появится.
- Другие экраны настроек (`ComparisonParams`, `column_arithmetic` и т.д.) не
  меняются — их классы (`param-row` и т.д.) остаются нетронутыми.
