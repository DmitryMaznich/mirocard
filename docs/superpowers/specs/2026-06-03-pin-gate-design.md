# PIN-гейт на запуск сессии

**Дата:** 2026-06-03  
**Статус:** approved

## Проблема

Ребёнок мог многократно нажимать «Назад», выйти из сессии на главный экран и самостоятельно запустить другую тему/режим в обход задания взрослого. Блокировка выхода (useBackButtonGuard + HoldButton с тап-кодом) не давала надёжной защиты.

## Решение

Санкционирование **входа** вместо блокировки выхода. Единственная точка контроля — кнопка «Начать занятие». Ребёнок может свободно перемещаться по меню, но запустить сессию без PIN невозможно.

## Архитектура

### PinGateModal

Один компонент, два режима:

**setup** — первоначальная настройка (когда `adultPinHash === null`):
- Два прохода: «Придумайте PIN» → «Повторите PIN»
- При совпадении: `SHA-256(pin)` сохраняется в store → IndexedDB
- Сразу переходит в verify-режим и открывает сессию

**verify** — ввод PIN при каждом запуске:
- Пользователь вводит 4 цифры
- Сравнивается `SHA-256(input) === adultPinHash`
- Успех → вызывается `onSuccess()` → сессия стартует
- Неудача → shake-анимация точек, счётчик попыток (+1)

### Кастомный пинпад

- 4 точки-индикатора (○○○○ → ●●●● по мере ввода)
- Числовая сетка 3×4: `1 2 3 / 4 5 6 / 7 8 9 / [пусто] 0 ←`
- Только pointer-события, без системной клавиатуры — нет прыжков layout
- Кнопка `←` удаляет последнюю цифру
- После 4-й цифры проверка срабатывает автоматически — отдельной кнопки «ОК» нет

### Хранение PIN

- Поле `adultPinHash: null` уже есть в `store.js` — просто начинаем использовать
- Хеширование: `crypto.subtle.digest('SHA-256', ...)` (Web Crypto API, синхронно недоступен → await)
- Сброс PIN: через Settings, с подтверждением старого PIN

### Точка вставки

`ParamsScreen.jsx` — именно здесь находится кнопка «Начать занятие» и вызов `setScreen('session')`. Нажатие открывает `PinGateModal`; при `onSuccess` выполняется тот же код запуска сессии, что и сейчас.

## Изменения в HoldButton / тап-код

| Место | Было | Станет |
|---|---|---|
| SessionSummary — «Завершить» | HoldButton (3 тапа + hold) | Обычная кнопка |
| App.jsx модалка прерывания — «Завершить» | HoldButton (3 тапа + hold) | HoldButton только hold (без тап-кода) |

HoldButton остаётся в проекте. Добавляется проп `skipTaps={true}` — пропускает фазу тапов и сразу входит в фазу hold. Используется для кнопки прерывания в App.jsx.

---

## Что не меняется

- `useBackButtonGuard.js` — остаётся без изменений
- Весь UI главного экрана, выбора студента, темы, режима
- Логика сессии, ParamsScreen, ModePickerScreen

## Сценарии

**Первый запуск:**
1. Взрослый настраивает занятие → нажимает «Начать занятие»
2. Модалка: «Создайте PIN» → вводит 4 цифры → подтверждает
3. Сессия стартует

**Обычный запуск:**
1. Взрослый нажимает «Начать занятие» → вводит PIN → сессия стартует
2. Передаёт планшет ребёнку

**Ребёнок пытается запустить другое:**
1. Выходит на главный экран (любым способом)
2. Нажимает «Начать занятие» на другой теме
3. Видит пинпад → не знает PIN → не может продолжить

**Сброс PIN:**
1. Взрослый идёт в Settings → «Изменить PIN»
2. Вводит текущий PIN → задаёт новый
