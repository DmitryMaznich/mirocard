# Пилюля хедера сессии как индикатор правильности ответа

## Контекст

На экранах занятия пилюля `.session-plan-tongue` (`src/features/session/SessionHeader.jsx`) —
это капсула-«ручка», торчащая из нижнего края `.session-topbar`. В обычном состоянии внутри
неё три полоски (бургер-иконка), которые морфятся в крестик, когда открыта панель доп. функций
`SessionPlanDrawer`.

Отдельно от пилюли сейчас существует визуализация правильности ответа — она реализована
в двух местах:

1. Текстовый счётчик `✓{correctCount} ✗{incorrectCount}` в `.session-counter` (хедер).
2. Полноэкранный оверлей `.session-fb-overlay--correct` / `--incorrect` в `SessionScreen.jsx`
   (строки ~312–328) — крупная анимированная галочка/крестик поверх карточки после каждого
   ответа, для `--correct` ещё и текст-подсказка «Нажмите, чтобы продолжить» с тапом на
   `requestAdvance`.

Источник состояния — `sessionState.status`, управляется чистыми функциями-редьюсерами
в `src/features/session/sessionEngine.js` (`handleAnswer`) и колбэками `onCorrect`/`onIncorrect`
в `src/features/session/useSessionEngine.js`. Переход обратно в нейтральный статус уже
происходит автоматически — по таймеру (`autoAdvanceDelay` для правильных ответов, `1500мс`
для неправильных через `INCORRECT_FEEDBACK_MS`) или по действию пользователя (тап,
подтверждение взрослого через `adultConfirmAdvance`). Эта логика не завязана на UI оверлея
и не меняется.

## Идея

Превратить саму пилюлю в оригинальный индикатор правильности ответа: в момент, когда
`sessionState.status === "answer_correct"` / `"answer_incorrect"`, пилюля вместо трёх полосок
показывает эмодзи (😊 / 😢) с мягким цветным тонированием фона. После того как статус уходит
из feedback-состояния (что происходит само, см. выше), удаляем полноэкранный оверлей
`.session-fb-overlay--correct`/`--incorrect` как избыточный.

## Поведение

- Пилюля получает новый проп со статусом ответа (например, `answerStatus` — значение
  `sessionState.status`, пробрасывается из `SessionScreen.jsx` в `SessionHeader`, как уже
  пробрасываются `correctCount`/`incorrectCount`).
- Приоритет визуальных состояний пилюли (от высшего к низшему):
  1. Панель открыта (`isDrawerOpen`) → крестик (текущее поведение, не меняется).
  2. Панель закрыта и `answerStatus === "answer_correct"` → эмодзи 😊.
  3. Панель закрыта и `answerStatus === "answer_incorrect"` → эмодзи 😢.
  4. Иначе → три полоски (текущее нейтральное состояние).
- Тап по пилюле в состоянии эмодзи по-прежнему открывает `SessionPlanDrawer` — функция пилюли
  не меняется, меняется только её вид в состоянии покоя/feedback.
- Никакого отдельного таймера показа эмодзи не заводим — пилюля чистая функция от
  `sessionState.status`, который и так меняется по существующим таймерам/действиям.
- Если на момент feedback-статуса должен был идти пульс (`--pulse`, есть невыполненные пункты
  плана занятия), пульс на это время подавляется классом эмодзи-состояния; после возврата
  к нейтральному виду пульс возобновляется, если условие всё ещё верно.

## Внешний вид и анимация

- Фон пилюли на время feedback-состояния сменяется с текущего кремового градиента
  (`linear-gradient(180deg, #ffffff 0%, #f8f3e8 55%, #efe5d2 100%)`) на:
  - мягкий зелёный градиент для `answer_correct`;
  - мягкий коралловый/красный градиент для `answer_incorrect`.
  Геометрия (48×22px, `border-radius: 999px`, тени) не меняется.
- Три полоски `.session-plan-tongue__bar` заменяются на один `<span>` с эмодзи (аналогичный
  по размеру/центровке).
- Появление эмодзи — короткий pop: scale `0.9 → 1.05 → 1`, ~200мс.
- Возврат к нейтральному виду (полоски + кремовый фон) — кроссфейд ~150мс.

## Доступность

`aria-label` пилюли (сейчас формируется через `formatPlanTongueLabel`) на время
feedback-состояния должен отражать статус (например, «Правильно, открыть меню» /
«Неправильно, открыть меню»), а не всегда описывать только открытие меню.

## Что убираем

Удаляем из `SessionScreen.jsx` (~строки 312–328) блоки:

```jsx
{isIncorrectFeedback && !ownsFeedback && (
  <div className="session-fb-overlay session-fb-overlay--incorrect" ...>...</div>
)}
{isCorrectFeedback && !ownsFeedback && (
  <div className="session-fb-overlay session-fb-overlay--correct..." onClick={requestAdvance}>...</div>
)}
```

и соответствующий CSS в `src/styles.css`: `.session-fb-overlay--incorrect`,
`.session-fb-overlay--correct` (и `--ready` модификатор для неё), `.session-fb-overlay__icon`
корректно-специфичные и некорректно-специфичные правила, `.session-fb-overlay--correct
.session-fb-overlay__hint`.

**Не трогаем:**

- `.session-fb-overlay--gate` (`showStandaloneGate` в `SessionScreen.jsx`) — это отдельный
  экран ожидания подтверждения взрослого (`adultConfirmAdvance`), не про правильность ответа.
- Базовый `.session-fb-overlay` и `.session-fb-overlay__hint`, если используются gate-вариантом
  — при удалении correct/incorrect-специфичных правил нужно перепроверить, что не остаётся
  мёртвого CSS, но не про базовые классы, которые всё ещё нужны gate.
- Текстовый счётчик `✓/✗` в `.session-counter` — остаётся без изменений.
- Звук `playFeedback("correct"/"incorrect")` в `SessionScreen.jsx` — не меняется.

## Почему это безопасно функционально

Тап-для-продолжения при правильном ответе сейчас навешен не только на удаляемый оверлей, но
и на весь `.session-renderer-wrap` (`SessionScreen.jsx` ~264–266: `onClick={(isCorrectFeedback
|| isAdvanceGateActive) ? requestAdvance : undefined}`). После удаления оверлея тап по карточке
продолжает работать без изменений. Авто-advance по таймеру для правильных и неправильных
ответов реализован в `useSessionEngine.js` независимо от UI и не завязан на оверлей.

## Зона неопределённости / риск (принято, не блокер)

Полноэкранный оверлей был намеренно крупным и однозначным сигналом — важно для маленьких
детей, аудитории приложения. Пилюля 48×22px в углу хедера заметно менее заметна. Решено
компенсировать это существующим звуком (`playFeedback`) без дополнительной подсветки карточки
в этой итерации; при необходимости подсветка карточки может быть добавлена отдельной фичей
по результатам практической проверки.

## Затронутые файлы

- `src/features/session/SessionHeader.jsx` — новый проп статуса ответа, условный рендер
  эмодзи вместо полосок, модификатор класса пилюли.
- `src/features/session/SessionScreen.jsx` — проброс `sessionState.status` в `SessionHeader`,
  удаление блоков `.session-fb-overlay--correct`/`--incorrect`.
- `src/styles.css` — CSS для новых состояний `.session-plan-tongue--correct`/`--incorrect`
  (градиенты, эмодзи, pop-анимация), удаление CSS `.session-fb-overlay--correct`/`--incorrect`
  и их специфичных под-правил.

## Не входит в объём

- Подсветка/тонирование карточки под ответ (см. риск выше).
- Изменение звуковой обратной связи.
- Изменение текстового счётчика `✓/✗` в хедере.
- Изменение gate-оверлея подтверждения взрослого.
