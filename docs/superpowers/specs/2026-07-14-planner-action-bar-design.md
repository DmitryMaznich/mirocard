# Планировщик: постоянная навигационная панель

## Проблема

Хаб Планировщика (`PlannerTab` в `src/features/home/HomeScreen.jsx:357-589`)
сейчас показывает кнопки действий («Начинаем готовить», «История», «Новое
меню») только внутри `.planner-action-dock` — блока, который (а) появляется
только когда в меню уже выбран хотя бы один рецепт (`hasSelection`), и (б)
держится у низа флекс-колонки только через `margin-top: auto`, без
`position: sticky`. На экране с высоким контентом (все 4 карточки хаба +
подсказка `.planner-cook-hint`) это уводит панель за пределы видимой
области — приходится скроллить, чтобы её найти.

Кроме этого, два полезных действия сегодня не имеют прямого входа с хаба
Планировщика:

- «Приготовить рецепт из каталога разово, не добавляя его в меню» — логика
  уже есть (`handleCook` в `PlannerMenuScreen.jsx:675-681`), но доступна
  только через кнопку ▶ у карточки рецепта внутри пикера, который
  открывается кнопкой «+» на конкретном слоте приёма пищи
  (`MealSlotSection`, `PlannerMenuScreen.jsx:378`) — т.е. только из экрана
  «Меню», а не с хаба.
- «Редактировать каталог продуктов» — уже есть как встроенный режим
  `editMode` экрана `PlannerShoppingScreen.jsx` (кнопка-карандаш ✏️, строка
  1379, компонент `CategoryEditor`, строки 224-475), но добраться до него
  можно только через «Что купить?» → нажать карандаш.

## Цели

1. Панель действий Планировщика видна всегда на хабе (`PlannerTab`), включая
   момент, когда меню ещё пустое — недоступные в моменте кнопки показываются
   задизейбленными, а не скрываются.
2. Панель не теряется при скролле контента хаба на любом размере экрана.
3. Прямой доступ с хаба к пяти действиям: разовая готовка рецепта из
   каталога, редактирование каталога продуктов, готовка по текущему меню,
   начало нового цикла, история циклов.
4. Никаких горизонтальных скроллов на самой панели — вёрстка адаптируется к
   ширине экрана (проверено на 320px и 390px).

## Область изменений

Только вкладка «Планировщик» на главном экране (`PlannerTab`). Вложенные
экраны (`planner_menu`, `planner_shopping`, `planner_putaway`) панель не
получают — у них уже есть собственная навигация внутри.

## Состав и порядок кнопок (слева направо)

**Рецепты · Продукты · [ГОТОВИМ] · Заново · История**

Обычные 4 кнопки — колонка иконка сверху + подпись снизу, третье место в
ряду — пустой слот под круглую кнопку.

| # | Подпись  | Действие | Активна, когда |
|---|----------|----------|-----------------|
| 1 | Рецепты  | Открывает список всех рецептов (`allRecipes`) для разовой готовки без изменения меню | `allRecipes.length > 0` (не идёт загрузка) |
| 2 | Продукты | Открывает `planner_shopping` сразу в режиме редактора категорий | всегда |
| 3 | ГОТОВИМ (круг) | Открывает `CookPickerSheet` по текущему меню | `readyToCook` (как у текущего «Начинаем готовить») |
| 4 | Заново   | Подтверждение → архивирует цикл и сбрасывает план (текущий `handleStartNewMenu`) | `hasSelection` |
| 5 | История  | Открывает `CycleHistorySheet` (текущий `handleOpenHistory`) | всегда |

### Кнопка 1 — «Рецепты» (новый вход)

Новый компонент `RecipeCatalogSheet` (bottom-sheet, аналог
`CookPickerSheet` по структуре) со списком всех `allRecipes`, без фильтра по
`menuRecipes`. По тапу на рецепт — тот же переход, что у `handleCook`:
`setActiveTopicId` → `setActiveText` → `setActiveModeId('follow_instruction')`
→ `setSessionReturnScreen('home')` → `setScreen('params')`. Рецепт не
добавляется ни в `selectedRecipes`, ни в `mealAssignments`.

### Кнопка 2 — «Продукты» (новый вход)

`setPlannerShoppingInitialMode` получает новое допустимое значение `'edit'`
(сейчас поддерживает только `'shop'`, см. `handleGoShopping` в
`HomeScreen.jsx:447-450`). `PlannerShoppingScreen.jsx` при монтировании с
`initialMode === 'edit'` сразу выставляет `editMode = true` (тот же стейт,
что переключает кнопка-карандаш), минуя обычный список покупок.

### Кнопка 3 — «ГОТОВИМ» (круглая, центральная)

Сохраняет текущую логику `disabled={!readyToCook}` и открытие
`CookPickerSheet`. Когда есть частичный прогресс
(`0 < cookedTextIds.size < menuRecipes.length`), на круге показывается
маленький числовой бейдж прогресса (`2/3`) в углу — сама подпись «ГОТОВИМ»
не меняется на длинный текст, как было в старом доке.

### Кнопки 4 и 5 — без изменений в логике

Дословно переиспользуют `handleStartNewMenu` и `handleOpenHistory`.
Подтверждение «Заново» переезжает из инлайн-бара `.menu-reset-bar` в
модалку — переиспользуем существующий `Modal` (`src/shared/components/Modal.jsx`)
с тем же текстом предупреждения, что и сейчас, и кнопками «Нет / Заново».

## Вёрстка и позиционирование

- Компонент рендерится внутри `.planner-hub`, сразу после
  `.planner-hub__grid` (последняя карточка — «Раскладка»), **не** через
  `margin-top: auto`. Отступ сверху — `clamp(22px, 8vh, 34px)`
  (≈ половина высоты бара) вместо прежнего авто-отступа, прижимавшего блок
  к самому низу пустого пространства.
- `position: sticky; bottom: 0` на обёртке — когда контент короче экрана,
  бар остаётся сразу под «Раскладкой» с этим отступом; когда контент выше
  экрана и происходит скролл, бар прилипает к низу видимой области
  `.home-tab-content`.
- Бар не касается физического края экрана (`.home-tabbar` снизу — отдельный
  элемент вне зоны скролла, уже учитывающий `--app-safe-bottom`), поэтому
  новой панели safe-area отступы не нужны.
- 4 обычные кнопки — `flex: 1`, круглая кнопка — `position: absolute;
  left: 50%; top: 50%; transform: translate(-50%, -50%)` относительно бара,
  т.е. её центр всегда на горизонтальной центральной линии бара независимо
  от паддингов.
- Внутри круглой кнопки подпись «ГОТОВИМ» центрирована по горизontальной
  линии круга собственным `position: absolute` (не через общий flex-стек),
  иконка-стрелка — под подписью, ближе к нижнему краю круга.
- Размеры адаптивные через `clamp()`: боковые иконки `clamp(20px, 6.5vw,
  26px)`, круг `clamp(56px, 17vw, 64px)`, шрифт подписей `clamp(8px, 2.4vw,
  9px)`. Проверено без горизонтального скролла на ширине 320px и 390px.
- Круглая кнопка визуально «выступает» над баром (лёгкий хром-ободок:
  тонкое двойное кольцо — основной цвет бара снаружи, `#d8cbb6` внутри —
  вместо объёмного металлического рендера) — вариант C из мокапов.
