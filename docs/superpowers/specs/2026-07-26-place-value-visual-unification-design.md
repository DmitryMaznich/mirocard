# Разряды: единое визуальное решение для «Какое это число?» и «Разменяй десяток» на основе «Собери число»

## Контекст

«Собери число» (`build_number`) только что доведён до полированного состояния: чек-лист с
шагами, монеты (`CoinBlocks.jsx`/`coins.css`), без озвучки, без живого счётчика (осознанно —
чтобы UI не считал за ребёнка), направленная подсказка при ошибке, подсветка нужной зоны,
затухание завершённых строк. `IdentifyNumberTask.jsx` («Какое это число?») и
`RegroupTenTask.jsx` («Разменяй десяток») визуально и по механике сильно отстали: используют
кубики/карточки (`PlaceValueBlocks.jsx`), озвучку, всегда/опционально видимый счётчик
N/M, простые экраны без чек-листа, и в «Какое это число?» неверный ответ стирает обе цифры
даже если одна была верна.

Решено (согласовано в сессии): унифицировать все три режима под стиль/механику
«Собери число».

## Согласованные решения

1. **Манипулятив → монеты.** Оба режима переходят с `PlaceValueBlocks.jsx` (UnitCube/TenCard)
   на `CoinBlocks.jsx` (Coin/TenStack) — статичное отображение (не драг), тот же паттерн,
   что уже использует `Workspace` в build_number для «уже выложенных» монет. После переноса
   `PlaceValueBlocks.jsx` не используется больше нигде — удаляется.
2. **Снять озвучку и живой счётчик.** `useSpeech`/`speak(...)` убирается из обоих файлов.
   Живой текстовый счётчик («N десятков / M единиц») убирается — в `identify_number` он был
   опциональным (`showCounters`), в `regroup_ten` — всегда включён. Параметр `showCounters`
   (топик-схема + `engine.js`) становится мёртвым — убирается вместе с рендером. Параметр
   `numericBlocks` уже был мёртвым в обоих режимах (не в схеме настроек, всегда `false`) —
   убирается заодно, тем же движением.
3. **Чек-лист с шагами** — обе темы получают тот же `ChecklistItem`/`.pv-checklist`
   визуальный язык, что и build_number (почерковый шрифт, галочка, соединительная линия,
   пульсация активной строки).
4. **Логика ошибки выравнивается** — там, где есть цифровой ответ («Какое это число?»),
   верная цифра остаётся, неверная получает направленную подсказку («Больше»/«Меньше»),
   как в build_number. `hintDirectionFor` (сейчас определена и экспортируется из
   `BuildNumberTask.jsx`) переезжает в `placeValueLabels.js` — общий модуль, который уже
   импортируют оба соседних файла — и все три компонента используют одну копию.

## Дизайн по файлам

### `IdentifyNumberTask.jsx`

Задачи здесь нет «построй» — количество уже показано, ребёнок его читает и называет. Поэтому
фазы только `answerTens → answerOnes → done` (без collect/group).

- Шапка: заголовок «Какое это число?» остаётся простым текстом (не строкой чек-листа — это
  не действие, а рамка задания).
- Чек-лист из 2 строк: «Сколько десятков?», «Сколько единиц?» — `clickable={false}`,
  отмечаются нажатием цифры на numpad, как в build_number.
- Зоны (`.pv-zone` × 2, ДЕСЯТКИ/ЕДИНИЦЫ) показывают `TenStack`/`Coin` вместо
  `TenCard`/`UnitCube`. Активная зона (соответствующая текущему вопросу) получает
  `.cb-area--focus` (тот же класс, что уже в `coins.css` — переиспользуется, не копируется).
  `AnswerSlot` (тот же компонент, что в build_number — либо импортируется, либо копируется
  один раз, см. «Общий код» ниже) встроен под соответствующей зоной.
- Неверная цифра: `flashRowWrong`-эквивалент с `hintDirectionFor`, верная цифра сохраняется,
  переход к следующему шагу только после верной.
- Кнопки «Стереть»/«Далее» внизу убираются вместе с полем `.pv-footer` — как и в
  build_number, чек-лист сам себя подтверждает, а «Далее» не нужен: `onCorrect` вызывается
  автоматически через `setTimeout` после верного ответа на «единицы» (тот же паттерн, что
  `handleOnesDigit` в build_number).

### `RegroupTenTask.jsx`

Здесь только одно действие — перетащить десяток. Чек-лист состоит из ОДНОЙ строки,
объединяющей текущую подпись-инструкцию: «Разменяй десяток в единицы» (была отдельным
`.pv-caption`, становится текстом единственной строки чек-листа — тот же приём, что
объединил инструкцию build_number с первой строкой). Строка отмечается автоматически, когда
`exchanged` становится `true` (как «Сколько десятков?»/«Сколько единиц?» — `clickable={false}`,
тикается не тапом по строке, а результатом действия).

- `DraggableTenCard` → `DraggableTenStack` (та же обёртка `useDraggable`, внутри рендерится
  `TenStack` вместо `TenCard`).
- `UnitCube` → `Coin`.
- Озвучка (`speak("Один десяток разменяли...")`) убирается.
- Счётчик N/M убирается.
- Панель результата (уравнение до/после + кнопка «Далее») **остаётся как есть** — осознанное
  исключение: смысл этого режима как раз в том, чтобы ребёнок увидел и осмыслил равенство
  `10×tens + ones = 10×(tens-1) + (ones+10)`, а не проскочил дальше через 900мс, как
  build_number после последнего верного ответа. Кнопка «Далее» — уже существующий,
  сознательный шаг паузы, не regression на фоне остального упрощения.

## Общий код

- `hintDirectionFor(guess, target)` переезжает из `BuildNumberTask.jsx` в
  `placeValueLabels.js` (уже импортируется всеми тремя компонентами для `pluralTens`/
  `pluralOnes`/`pluralCoins` — естественное место для ещё одной маленькой общей функции).
  `BuildNumberTask.jsx` обновляет свой импорт; его собственный unit-тест
  (`buildNumber.smoke.test.jsx`) обновляет источник импорта на `placeValueLabels.js`.
- `AnswerSlot` (сейчас module-private в `BuildNumberTask.jsx`) — используется в двух файлах,
  значит должна жить в общем месте. Решение: копия в каждый файл (2 строки JSX + один
  маленький компонент) — **не** экспорт из `BuildNumberTask.jsx` (кросс-импорт между
  соседними Task-компонентами создаёт хрупкую связанность: правка build_number могла бы
  незаметно сломать оба соседних режима). `ChecklistItem`/`CheckIcon` — тот же принцип,
  копия в каждый файл, как уже сегодня fingers_count/build_number независимо копируют
  похожий чек-лист-паттерн (задокументированный принцип в `designing-mirocard-screens`:
  «переиспользуй паттерн копированием, а не общим импортом между темами»).
- CSS: `.cb-area--focus`, `pv-checklist-box-pulse`, `.pv-answer-hint`,
  `.pv-checklist--focused` — все уже существуют в `place_value.css`/`coins.css`
  (написаны для build_number), переиспользуются как есть, ничего нового не добавляется в
  CSS для этой задачи, кроме, возможно, точечных мелочей при вёрстке (уточнится в плане).

## Вне рамок

- Столбик (`column_arithmetic`) — не трогается.
- Механика build_number (`collect`/`group`) — не трогается, только источник
  `hintDirectionFor` перемещается.
- Объединение трёх режимов разрядов в один режим с настройками — отдельная, ранее
  отклонённая на этой сессии идея (см. `2026-07-26-build-number-mechanics-polish-design.md`).
- `PlaceValueBlocks.jsx` — удаляется целиком (становится мёртвым файлом после переноса
  обоих потребителей на `CoinBlocks.jsx`).

## План проверки

Тот же паттерн, что уже установлен для этого файлового семейства в этой сессии: нет живой
проверки в браузере (нет рабочего бэкенда/аккаунта в этом окружении). Компонентные
smoke-тесты через `react-dom/client` + `act` — по образцу `buildNumber.smoke.test.jsx`:
mount-без-падения для обоих компонентов, плюс (для `IdentifyNumberTask`) проверка, что
неверная цифра десятков не стирает уже верную цифру единиц (или наоборот — по порядку
шагов, что проверяемо без drag-симуляции, в отличие от `RegroupTenTask`, чья единственная
интеракция — dnd-kit drag, не тестируется на этом уровне, как и `collect`/`group` в
build_number).
