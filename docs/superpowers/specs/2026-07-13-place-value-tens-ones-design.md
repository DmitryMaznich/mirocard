# Дизайн: «Десятки и единицы» (новые режимы в теме column_addition)

**Дата:** 2026-07-13
**Статус:** Согласован (по итогам интерактивных мокапов, см. историю правок ниже)
**Контекст:** Обучение разрядному составу двузначных чисел. Не отдельная тема — три новых режима внутри существующей темы `column_addition`, рядом с `column_arithmetic` / `column_copy` / `fingers_show` / `fingers_count`.

---

## 1. Объём (MVP)

Три режима:

| mode id | Название | Механика |
|---|---|---|
| `build_number` | «Собери число» | Собрать число из десятков/единиц перетаскиванием |
| `identify_number` | «Какое это число?» | По готовой модели ввести число |
| `regroup_ten` | «Размени десяток» | Разменять десяток на 10 единиц, ответить, изменилось ли число |

Явно вне объёма этой итерации:
- режим «Что означает цифра?» (значение разряда) — методически второй этап;
- доп. задание «Собери число по-другому»;
- авто-адаптивный движок уровней (в проекте нет прецедента, есть только ручной `level`);
- детальная типизация ошибок в статистике (`errorType`) — оставляем generic correct/incorrect;
- ландшафтная/двухколоночная раскладка — вместо неё `orientationLock: 'portrait'`.

## 3. Структура задачи (task object)

```js
// build_number
{
  type: "build_number",
  cardId, conceptId: "build_number",
  level,                      // 1-5, см. §8
  number,                     // 32
  target: { tens: 3, ones: 2 } // ожидаемая раскладка
}

// identify_number
{
  type: "identify_number",
  cardId, conceptId: "identify_number",
  level,
  number,                     // 32 — то, что должен ввести ребёнок
  model: { tens: 3, ones: 2 }, // готовая предметная модель, которую видит ребёнок
  showCounters                // level === 1 → true, иначе false
}

// regroup_ten
{
  type: "regroup_ten",
  cardId, conceptId: "regroup_ten",
  level,
  number,                     // 32, не меняется весь режим
  initial: { tens: 3, ones: 2 },  // раскладка до размена
  after: { tens: 2, ones: 12 }    // раскладка после размена (initial.tens - 1, initial.ones + 10)
}
```

Генератор `regroup_ten` фильтрует пул чисел на `tens >= 1` (см. §8).

## 4. Визуальная модель

### Единица

Один квадратный кубик, 20×20 (масштабируется по брейкпоинтам как остальные элементы темы).

### Десяток — тен-фрейм 2×5, не столбик 1×10 и не горизонтальная лента

Ключевое решение по итогам мокапов. Два ряда по пять кубиков (классический ten-frame из ранней/коррекционной математики):
- ребёнок мгновенно «видит десять» двумя пятёрками (subitizing), не пересчитывая по одному;
- вдвое компактнее по высоте, чем колонна из 10 — критично на телефоне при нескольких десятках.

### Десяток — непрозрачная карточка, не «палка»

Каждый десяток — отдельная карточка с непрозрачным фоном, рамкой, тенью и мелким бейджем «10» в углу. Между соседними карточками десятков — увеличенный зазор (не такой, как зазор ячеек внутри одной карточки). Без этого несколько десятков подряд визуально сливаются в «кучу единиц» (проверено на мокапе, исправлено).

### Шрифт

Обычный чистый sans-serif (как остальной UI приложения), **не** рукописный Primo. Primo в `column_arithmetic` эмулирует тетрадную запись цифр примера — здесь ребёнок оперирует предметной моделью и вводом через клавиатуру, рукописный шрифт неуместен.

### Подписи

Без текстовых подписей «десяток» / «единица» под элементами лотка — читается по смыслу и форме.

## 5. Раскладка экрана

- **Только портретная ориентация.** `orientationLock: 'portrait'` в описании режима — тот же механизм (`getActiveOrientationLock` → `OrientationGuard` в `App.jsx`), что уже используют другие режимы. В ландшафте — стандартный экран «Поверните экран вертикально», без отдельной ландшафтной вёрстки.
- **Зоны ДЕСЯТКИ/ЕДИНИЦЫ облегают собственное содержимое** (`align-items: flex-start` в строке зон — не растягивать одну зону по высоте другой) и растут по мере наполнения, а не занимают фиксированную долю экрана.
- **Скроллится весь экран целиком**, если десятков/единиц становится много — не отдельный скролл внутри зоны.
- **Лоток / клавиатура / кнопка ГОТОВО прижаты к низу экрана** через flex-спейсер между зонами и нижним блоком управления: при малом количестве элементов спейсер растягивается и толкает управляющие элементы вниз; при большом — сжимается до нуля, и дальше работает скролл всего экрана. Никогда не «подпрыгивают» под короткими зонами и не теряются за пределами экрана.

## 6. Взаимодействие (drag-and-drop на dnd-kit)

Решение по итогам обсуждения: в `column_arithmetic` когда-то отказались от drag&drop в пользу tap-to-fill, но там были узкие ячейки тетради (точное попадание пальцем — проблема). Здесь цели крупные, зоны широкие — ближе к `sentence_puzzle`, где `dnd-kit` (`PointerSensor` + `TouchSensor`, `activationConstraint: {delay:150, tolerance:5}`) уже отлично работает touch-first. Используем тот же паттерн.

### `build_number`

- Внизу — неисчерпаемый лоток: одна карточка-десяток, один кубик-единица (после переноса в зону тут же появляется новый экземпляр).
- Перетаскивание в зону ДЕСЯТКИ добавляет десяток, в ЕДИНИЦЫ — единицу (зона назначения зависит от типа перетаскиваемого объекта, а не от того, в какую из двух зон её физически бросили).
- Повторный тап по размещённому элементу — убирает его.
- Кнопка ГОТОВО запускает проверку.

### `identify_number`

- Модель числа показана заранее (нередактируема).
- Счётчики под зонами видны на уровне 1, скрываются на уровне 2+ (per-level параметр).
- Ввод — цифровая клавиатура в два отдельных слота (десятки → единицы).
- **Без кнопки ГОТОВО** — проверка происходит автоматически сразу после ввода второй цифры.
- Кнопка «Стереть» остаётся — для исправления первой цифры до ввода второй.

### `regroup_ten`

- Число уже собрано (N десятков + M единиц), заголовок с числом сверху не меняется никогда.
- Ребёнок перетаскивает одну карточку-десяток **прямо в зону ЕДИНИЦЫ** (без отдельной зоны «РАЗМЕН» — от неё отказались, лишний шаг).
- По дропу: карточка десятка исчезает из ДЕСЯТКИ, десять кубиков анимированно разлетаются и приземляются в ЕДИНИЦЫ.
- Затем контрольный вопрос «Число изменилось?» → ДА/НЕТ.
- При верном ответе (НЕТ) — показывается разбор `30 + 2 = 32` / `20 + 12 = 32`. Это не подсказка, а содержание самого задания (проверка сохранения количества), поэтому остаётся в отличие от прочих текстовых пояснений.

## 7. Никакой системы подсказок — классический тренировочный паттерн

Важное отличие от исходного ТЗ: там описана 3-уровневая лестница подсказок (подсветка → озвученная подсказка → полупрозрачный силуэт). От неё полностью отказались — в проекте нет такого паттерна, а есть свой, уже устоявшийся:

- Подтверждено по коду (`src/shared/components/RewardVideoModal.jsx`, `src/features/session/sessionEngine.js`, `FingersCountTask.jsx`, `math_houses/index.jsx`): «классические» тренировочные режимы **не показывают текстовых подсказок и не раскрывают правильный ответ**. При ошибке — только shake + подсветка того, что неверно, и повтор попытки (сброс ввода/выбора).
- Награда — не пошаговый разбор на каждой карточке, а существующий session-level механизм: серия правильных ответов подряд (`streakCount` → `rewardEarnedCount` в `useSessionEngine.js`) triggers `RewardVideoModal` («⭐⭐⭐⭐⭐ Молодец!» → «🎬 Смотреть мультик» / «Продолжать занятие»).
- Из этого следует: новым режимам **не нужна собственная логика награды** — достаточно вызывать существующий контракт `onCorrect(conceptId, cardId)` / `onMistake(conceptId, cardId)`, как это делают другие рендереры (см. `comparison/index.jsx`), и `useSessionEngine` сам посчитает streak и покажет `RewardVideoModal`.
- На верном ответе в `build_number`/`identify_number` — никакого «3 десятка = 30…» разбора, просто краткая зелёная подсветка/озвучка «Верно!» и переход к награде/следующей карточке.

## 8. Уровни сложности (диапазоны чисел)

Ручной выбор уровня в настройках режима (`level`, как в `sentence_puzzle`), без авто-переключения внутри сессии:

| Уровень | Диапазон |
|---|---|
| 1 | Числа с 1–2 единицами: 21, 32, 41, 52 и т.п. |
| 2 | Разное количество единиц: 23, 34, 46, 57 |
| 3 | Много единиц: 28, 39, 47, 56 |
| 4 | Ноль единиц: 20, 30, 40, 60 (вводить не первым — отсутствие единиц отдельная абстракция) |
| 5 | Смешанный набор всех двузначных чисел |

`regroup_ten` требует ≥1 десятка в числе (иначе размен невозможен) — фильтр в генераторе.

## 9. Статистика

Без изменений схемы: используем существующий generic `card_events` (correct/incorrect + тайминги тапов через `useCardEventLogger`). Поле `errorType` (десятки/единицы/перестановка и т.п.) из исходного ТЗ — не добавляем, чтобы не расширять backend-схему ради этой итерации.

Прогресс/mastery — существующий `useConceptProgress` (звёзды на экране выбора концепта), `conceptId` = mode id (`build_number` / `identify_number` / `regroup_ten`).
