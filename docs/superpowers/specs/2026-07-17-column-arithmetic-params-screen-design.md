# Эталонный экран настроек — режим «Столбик» (column_arithmetic)

## Контекст

Экран настроек режима отрисовывается общим компонентом `src/features/session/ParamsScreen.jsx`
по схеме `mode.params`, заданной в `src/topics/topicLoader.js`. Визуально и структурно он не
менялся с момента появления схемы: плоский список строк «лейбл слева — кнопки-пилюли справа»,
без группировки, без пояснений, с парой параметров, оформленных как enum вместо boolean.

Эта задача переделывает экран настроек режима «Столбик» (`column_addition` → `column_arithmetic`)
в новый эталонный вид. Код и схема при этом становятся переиспользуемыми — так, что другую тему
можно будет перевести на тот же вид, просто дополнив её `mode.params` (и, при необходимости,
`rewardDefaults`), без правок `ParamsScreen.jsx`. Перевод других тем на новый вид — отдельная
задача, в этой не делается.

## Находки при анализе (что реально используется в занятии)

Перед дизайном каждый параметр текущего экрана проверен по коду движка/рендерера/сессии:

| Параметр | Где используется | Вывод |
|---|---|---|
| `operation` | `engine.js:342-347` — фильтрует пул карточек по операции | реально работает |
| `carryMode` | `engine.js:343`, `generateAddTask`/`generateSubTask` | реально работает |
| `digits` | `engine.js:344` и генерация чисел | реально работает |
| `showHelper` | `index.jsx:660` — кнопка счётного помощника в занятии | реально работает, но оформлен как `enum` вместо `boolean` |
| `showCompare` | `index.jsx:597-601` — полоска сравнения разрядов при заёме | реально работает, тоже `enum` вместо `boolean` |

Дополнительно найден и исправлен независимый баг: `link.strictStars` читался с разным дефолтом
в разных местах (`useSessionEngine.js:173` и `linkUtils.js:23` — `?? false`, тогда как

`useStarProgress.test.js`, `rewardProgress.test.js` — все проходят).

## Дизайн

### 1. Раскладка — список с секциями

Из трёх рассмотренных направлений (список-с-секциями / карточки-настройки / плотная сетка 2×N)
выбран список с секциями: минимальная переделка кода (группировка по `def.section` уже
реализована в `ParamsScreen.jsx:931-949`, просто ни разу не использовалась), лучше масштабируется
на параметры с 3-4 вариантами и длинными подписями, чем сетка или карточки.

Для «Столбика» три секции:
- **«Что решаем»** — Операция, Перенос/заём, Разрядность
- **«Отображение в занятии»** — Помощник (палка), Сравнение
- **«Награда за занятие»** — Видео-награда, Серия для видеонаграды, Строгий подсчёт
  (виден только если у ученика есть видео-награды — как и сейчас)

Блок «Понятия» для этого режима убирается полностью (см. находки выше).

### 2. Тумблер вместо чекбокса/enum-пилюль для булевых настроек

`showHelper` и `showCompare` переводятся из `type: "enum"` (значения `"true"/"false"` строками)
в честный `type: "boolean"`. Компонент `BooleanParam` в `ParamsScreen.jsx` меняет визуал с
`<input type="checkbox">` на переключатель-тумблер (цветной = включено, серый = выключено, без
текстовых подписей положений) — переиспользует уже существующий класс `.param-row--disabled`
для состояния `disabled`.

**Побочный эффект, принимается сознательно:** `BooleanParam` — общий компонент, уже используется
другими режимами (например, `ComparisonParams` → «Ответ словами», `WrittenLettersPairParams`).
Обновление его визуала — глобальное, все существующие чекбоксы в приложении становятся
тумблерами. Семантика не меняется (то же `true`/`false`), это чисто визуальная полировка
общего примитива, а не перевод чужой темы на новую схему параметров.

`videoRewardEnabled` и `strictStars` (сейчас — захардкоженные enum-кнопки-пилюли в
`ParamsScreen.jsx:1032-1086`, не часть схемы `mode.params`) переводятся на тот же визуал тумблера
в рамках этой задачи (см. «Секция награды» ниже).

### 3. Кнопка (i) с пояснением — обязательна у каждого параметра

Новое поле схемы параметра:

```js
info: {
  ru: {
    text: "Что делает настройка — 1-2 предложения",
    tip:  "Совет по применению для родителя/логопеда",
  },
}
```

Рядом с лейблом каждого параметра — маленькая кнопка `(i)`. По клику — `Modal` (существующий
компонент `src/shared/components/Modal.jsx`) с заголовком = лейбл параметра, телом = `text` и
выделенный блок `tip` («Совет: …»).

Поле обязательно для всех параметров `mode.params` режима «Столбик», включая внешне очевидные
(«Разрядность», «Операция») — раз это эталон, будущие темы наследуют то же требование при
описании своих параметров. Текст для полей вне схемы (три поля секции «Награда за занятие»)
задаётся рядом отдельными константами (см. «Секция награды»), т.к. эти поля не входят в
`mode.params`.

### 4. Секция «Награда за занятие» — переупорядочивание и зависимость

Порядок меняется: **Видео-награда** идёт первой (это мастер-переключатель), затем «Серия для
видеонаграды», затем «Строгий подсчёт». Если «Видео-награда» выключена — две нижние строки
визуально гасятся (`.param-row--disabled`, уже есть в `styles.css:11838`) и не реагируют на тап —
это отражает реальность: при выключенной видео-награде `StarBar` не рендерится вовсе, и обе
настройки ни на что не влияют.

«Сложность серии» переименовывается в **«Серия для видеонаграды»**, кнопки `×1/×2/×3` → прямые
значения **`5/10/15`** (внутреннее значение `answersPerStar` остаётся 1/2/3, меняется только
отображаемая подпись/значения кнопок — это то число ответов подряд без ошибок, которое реально
нужно для полного бонуса, `5 × answersPerStar`).

«Подсчёт звёзд» (кнопки «Мягко»/«Строго») переименовывается в **«Строгий подсчёт»** и становится
тумблером (Строго = вкл, Мягко = выкл).

### 5. Дефолты

| Настройка | Дефолт | Обоснование |
|---|---|---|
| Операция | Только + | простой старт |
| Перенос / заём | Без | база перед усложнением |
| Разрядность | 2-значные | база перед усложнением |
| Помощник (палка) | Выкл | вспомогательный инструмент, не обязателен |
| Сравнение | Вкл | текущий дефолт, помогает при заёме |
| Видео-награда | Вкл | секция и так видна только если у ученика есть видео |
| Серия для видеонаграды | 5 | быстрая первая награда |
| Строгий подсчёт | **Мягко** (искл. из общего дефолта «Строго») | в «Столбике» ошибка засчитывается на уровне отдельной клетки, а не всего примера — «Строго» здесь заметно жёстче, чем в обычных карточках, и может демотивировать |

Дефолт «Строгий подсчёт» = Мягко — это исключение для конкретного режима, а не новый глобальный
дефолт (везде остальные режимы продолжают дефолтиться в `true`/Строго, как только что исправлено).
Реализуется через новое необязательное поле на уровне режима:

```js
// в topicLoader.js, для mode column_arithmetic
rewardDefaults: { strictStars: false },
```

Читается в местах, где есть доступ к `mode` и сейчас жёстко стоит `link.strictStars ?? true`:
`ParamsScreen.jsx:689` и `useSessionEngine.js:117` — заменить на
`link.strictStars ?? mode?.rewardDefaults?.strictStars ?? true`. Для всех остальных режимов, где
`rewardDefaults` не задан, поведение не меняется.

`linkUtils.js:23` доступа к `mode` не имеет и остаётся как есть (`link.strictStars ?? true`) —
это last-resort дефолт на случай, если `strictStars` вообще ни разу не был установлен ни одним
из вызывающих мест; в штатном сценарии `ParamsScreen.jsx` уже кладёт в патч конкретное
mode-aware значение (`true` или `false`), так что до этого фолбэка дело не доходит.

## Схема — итоговые изменения `mode.params` для `column_arithmetic`

- `showHelper`, `showCompare`: `type: "enum"` → `type: "boolean"`, добавлено поле `section`
  (`"Отображение в занятии"`), добавлено `info`.
- `operation`, `carryMode`, `digits`: добавлено `section: "Что решаем"`, добавлено `info`.
- На уровне режима: добавлено `hideConceptPicker: true` (новый флаг — `ParamsScreen.jsx` не
  рендерит блок «Понятия», если он выставлен) и `rewardDefaults: { strictStars: false }`.

## Вне рамок задачи

- Перевод других тем/режимов на секции/тумблеры/(i)-кнопки — отдельные задачи.
- Блоки «Понятия»/секция награды в других режимах не трогаются, кроме визуального апгрейда
  `BooleanParam` (см. пункт 2), который заденет их автоматически.
- Существующий баг в тестах `getRemoveMode` (`engine.test.js`, FingerSystem) — не связан с этой
  задачей, не трогается.
