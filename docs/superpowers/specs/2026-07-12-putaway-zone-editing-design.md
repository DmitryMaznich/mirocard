# Раскладка: редактируемые места хранения и синхронизация модуля

## Проблема

Места хранения продуктов для экрана «Раскладка» (`PlannerPutawayScreen.jsx`) сейчас
полностью зашиты в коде (`putawayLocations.js`): 6 фиксированных зон,
дефолтная зона по категории `shopping.txt`, и 5 точечных исключений по
названию товара. Ни зону товара, ни сам список зон нельзя поменять без
правки кода. Разные семьи хранят продукты по-разному (хлеб в холодильнике
или нет, яйца в холодильнике или нет и т.д.), и ребёнок в игре получает
"неправильный" фидбек на то, что на самом деле верно для его дома.

Отдельно: товары без зоны по умолчанию (например, добавленные семьёй свои
категории/товары) сейчас молча пропускаются из очереди раскладки — для них
нет вообще никакого UI.

Также в ходе анализа обнаружен несвязанный, но смежный баг: весь блок
"Planner shopping storage" в `groupStore.js` (`plannerShopPlan`,
`plannerShopCustomData`, `plannerShopBought`, `plannerPutawayPlan`,
`plannerShopMenuKeys/Stores/History`, `plannerCycleTrips/History`) пишется
только в локальный IndexedDB — без `pushOp` на сервер и без pull при
загрузке. Флоу «Покупки → В магазине → Раскладка» физически не
синхронизируется между устройствами одной семьи уже сегодня, до этой
задачи. Раз мы добавляем новые данные в этот же модуль, чинится
синхронизация всего модуля целиком, а не только новых данных.

## Цели

1. Родитель может переопределить зону хранения для конкретного товара — на
   уровне своей семьи, не глобально для всех пользователей приложения.
2. Родитель может переименовать существующие 6 зон и добавить свои
   дополнительные зоны (без удаления базовых).
3. Правка происходит "по факту столкновения" с товаром — в Списке покупок
   (до похода в магазин) и в самой Раскладке (после похода) — а не через
   отдельный экран-каталог всех товаров.
4. Товары без зоны по умолчанию (сироты) получают путь получить зону через
   тот же механизм, вместо того чтобы молча исчезать из Раскладки.
5. Весь модуль Planner shopping/putaway (включая новые данные) синхронизируется
   между устройствами одной семьи через существующий `pushOp`/pull-механизм.

## Модель данных (на семью/студента)

Два новых KV-объекта в `groupStore.js`, тот же паттерн ключей, что и у
`plannerPutawayPlan` (`planner_xxx_${studentId}`):

- **`plannerZoneCustomizations`** —
  `{ renamed: { [zoneId]: newLabel }, added: [{ id, label, icon }] }`.
  Базовые 6 зон (`ZONES` в `putawayLocations.js`) неизменны по составу и id,
  но подпись можно переопределить; семья может добавить свои зоны с новым
  `id` (сгенерированным, не пересекающимся с базовыми).
- **`plannerProductZoneOverrides`** — `{ [normalizedProductName]: zoneId }`.
  Ключ — `productName.trim().toLowerCase()`, а не `planKey`, чтобы override
  не терялся при переносе/переименовании категории — та же схема, что уже
  использует глобальный `PRODUCT_ZONE_OVERRIDES` в коде.

### Порядок разрешения зоны

`getZoneForProduct()` в `putawayLocations.js` дополняется первым шагом
(остальные не меняются):

```
plannerProductZoneOverrides[товар]   (семейный override, новое)
  → PRODUCT_ZONE_OVERRIDES[товар]    (глобальный, из кода, как сейчас)
  → CATEGORY_DEFAULT_ZONE[категория] (как сейчас)
  → null                             (нужна ручная правка)
```

Функция становится зависимой не только от `categoryName`/`productName`, но
и от передаваемого `plannerProductZoneOverrides` — вызывающий код
(`putawayUtils.js: buildPutawayQueue`, экраны) прокидывает загруженный
override-объект.

## UI

### 1. Настройки → «Зоны хранения»

Новый раздел в `SettingsScreen.jsx`, без дополнительного PIN-гейта — сам
экран Настроек уже открывается осознанным действием через иконку аккаунта
на главном экране, остальные разделы этого экрана тоже не требуют PIN.

- Список зон: базовые 6 + добавленные семьёй, у каждой иконка + подпись.
- Тап по подписи → инлайн-переименование (пишет в
  `plannerZoneCustomizations.renamed`).
- Кнопка «+ Добавить зону»: выбор иконки из небольшого фиксированного
  набора + ввод названия → добавляется в `plannerZoneCustomizations.added`
  с новым сгенерированным `id`.
- Базовые 6 зон удалить нельзя (на них завязана `CATEGORY_DEFAULT_ZONE`).
  Добавленные семьёй зоны можно удалить (ответственность семьи; если на
  зону есть исторические ссылки в `putawayPlan`, они просто останутся
  как есть — не мигрируем и не блокируем удаление).

### 2. Список покупок — режим редактирования (`editMode`)

В существующем `editMode` в `PlannerShoppingScreen.jsx` — без
дополнительного PIN, режим и так открывается намеренным действием.

- У каждого товара — компактный чип с иконкой текущей резолвнутой зоны.
- Тап по чипу → поповер-пикер зоны (список всех зон, включая добавленные
  семьёй) → выбор пишет `plannerProductZoneOverrides[товар] = zoneId`.
- Если зона не резолвится (`null`, товар-сирота) — чип вместо иконки
  показывает явное «Зона не задана», визуально выделяясь как незавершённое
  состояние — стимул родителю закрыть пробел до похода в магазин.

### 3. Раскладка (`PlannerPutawayScreen.jsx`)

- Небольшая иконка-шестерёнка в углу экрана. Учитывает safe-area (правило
  из `CLAUDE.md` — это floating-элемент на экранном крае):
  `top: calc(<original> + var(--app-safe-top, 0px))` / соответствующий
  `right`/`left`.
- Тап по шестерёнке → `PinGateModal` (родительский PIN, `adultPinHash`) →
  после успешного ввода — тот же пикер зоны, что в п.2, но для **текущего**
  товара в очереди раскладки. Выбор сразу пишет
  `plannerProductZoneOverrides` и переразрешает зону для этого товара в
  текущей сессии.
- PIN обязателен именно здесь (в отличие от Списка покупок), потому что это
  активный игровой экран ребёнка — случайный тап не должен открывать
  редактирование.

### 4. Товары-сироты в очереди раскладки

`buildPutawayQueue()` в `putawayUtils.js` сейчас пропускает товары с
`getZoneForProduct(...) === null`. Меняется:

- Такой товар всё равно попадает в очередь.
- Вместо обычных 6 (+N) зон на выбор ребёнку экран показывает отдельное
  состояние «Нужна помощь взрослого — выбери место» с тем же PIN-гейтом и
  пикером, что и в п.3.
- После выбора товар сохраняется в `plannerProductZoneOverrides` и в
  дальнейшем проходит по обычному пути (для ребёнка это уже обычная
  зона на выбор).

## Синхронизация

Расширяем существующий паттерн (сейчас используется только для
recipe-настроек: `pushOp` после `kv.set`, плюс `pullRecipeKvFromServer()`):

- **Push**: во все существующие `savePlannerShopPlan`,
  `savePlannerShopCustomData`, `savePlannerShopBought`,
  `savePlannerPutawayPlan`, `savePlannerShopMenuKeys/Stores/History`,
  `savePlannerCycleTrips/History` — и в новые `savePlannerZoneCustomizations`,
  `savePlannerProductZoneOverrides` — добавляется
  `pushOp("kv.upsert", { key, value }).catch(() => {})` после `kv.set`.
- **Pull**: новая `pullPlannerKvFromServer()` в `groupStore.js` — аналог
  `pullRecipeKvFromServer()`, с префиксом `planner_`. Вызывается в
  `HomeScreen.jsx` → `PlannerTab` (строки ~353-374), перед первым чтением
  `getPlannerShopPlan`/`getPlannerPutawayPlan`/и т.д. — единственная точка,
  где студент уже известен и эти геттеры и так вызываются при монтировании
  вкладки планировщика.
- Это чинит не только новые данные о зонах, а весь флоу
  «Покупки → В магазине → Раскладка» между устройствами одной семьи —
  ранее он был привязан к одному браузеру/устройству.

## Вне скоупа

- Полный экран-каталог со списком всех 150+ товаров и зон разом (обсуждали
  и сознательно отклонили — редко используется, стоит дороже в разработке
  и поддержке, чем точечная правка по факту).
- Удаление/переопределение базовых 6 зон.
- Миграция исторических `putawayPlan`-записей при удалении добавленной
  семьёй зоны.
- Глобальный (across all families) справочник — все переопределения
  зон и товаров — данные конкретной семьи.
