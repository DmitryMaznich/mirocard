# Экран готовки по рецепту — подтверждение шагов и модернизация навигации

## Проблема

Экран готовки (`InstructionTask` в [src/topics/renderers/reading/index.jsx](../../../src/topics/renderers/reading/index.jsx)) сейчас — линейный степпер с парой кнопок «Назад»/«Дальше». У этого два UX-дефекта:

1. **Тап-каскад.** Кнопка «Дальше» мгновенно заменяется карточкой следующего шага с новой кнопкой в том же месте экрана. Второй непроизвольный тап (той же рукой, локтем, из-за влажных/занятых готовкой рук) попадает уже на кнопку следующего шага — ученик «перескакивает» не по своей воле.
2. **Размытая семантика.** «Дальше» означает одновременно «я это прочитал» и «я это сделал» — для шагов-действий (`type: "action"`) нет явного подтверждения выполнения, в отличие от чек-листов (`type: "checklist"`), где «Дальше» уже заблокирована, пока не отмечены все пункты.

Дополнительно: выдвижной список «все шаги» (строки 643–672) позволяет прыгнуть на произвольный шаг — ещё один источник случайной/непроизвольной навигации.

## Цели

- Явное подтверждение «я выполнил(а) это действие» для каждого шага-действия, не только для чек-листов.
- Устранить тап-каскад инженерно (не только через UX-формулировки).
- Убрать возможность прыгать в произвольный шаг.
- Показать ученику, в какой фазе рецепта (Подготовка / Готовим / …) он находится, без изменения формата данных рецептов.

## Не-цели

- Никаких изменений в формате `.txt` рецептов или в `parseRecipeTxt.js` — типы шагов (`heading`, `action`, `checklist`, `warning`, `image`, `bullets`) и структура остаются как есть.
- Никакого голосового/аудио-подтверждения, таймеров-блокировок или фотофиксации — сознательно отклонено на этапе обсуждения.
- Не трогаем `adultConfirmAdvance` за пределами `reading/index.jsx` — настройка и её использование в [SessionScreen.jsx](../../../src/features/session/SessionScreen.jsx) и [useSessionEngine.js](../../../src/features/session/useSessionEngine.js) для других типов заданий остаются без изменений.

## Модель навигации

Одна главная кнопка внизу карточки вместо пары «Назад/Дальше». Текст и поведение кнопки зависят от `step.type`:

| `step.type` | Текст кнопки | Условие активности |
|---|---|---|
| `action` | **«Готово ✓»** | всегда активна |
| `checklist` | **«Готово ✓»** | активна только когда все `items` отмечены (текущая логика `allChecked`, строка 451) |
| `heading` | **«Начнём →»** | всегда активна |
| `warning` | **«Понял(а)»** | всегда активна |
| `image`, `bullets` | **«Дальше →»** | всегда активна |
| последний шаг рецепта (`isLast`) | **«Готово, рецепт закончен! 🎉»** | по правилу типа шага выше |

Второстепенная кнопка **«← Назад»** — маленькая, иконка-стрелка, отдельно от главной кнопки (не в одном ряду с ней, чтобы физически не совпадать местом с кнопкой подтверждения на предыдущем шаге). Всегда доступна. Переход назад не сбрасывает пройденность шагов впереди (`stepIndex` уменьшается, состояние `checked` не трогаем).

Выдвижной список «все шаги» (строки 643–672, `listOpen`/`listRef`) удаляется полностью вместе с прыжком по клику.

### Защита от тап-каскада

При смене `stepIndex` кнопка подтверждения нового шага не реагирует на тап в течение ~450 мс (короткое окно, совпадающее с длительностью slide-перехода карточки). Реализуется локальным состоянием `armedAt`/`disabled` в `InstructionTask`, сбрасываемым в `useEffect` по `stepIndex`. Клавиатурные хендлеры (ArrowRight/Enter, строка 504) подчиняются тому же замку.

### Судьба `adultConfirmAdvance` в этом экране

Строки 396, 674–682 сейчас: когда `adultConfirmAdvance` включена, `onClick` кнопок становится `undefined`, и класс `instruction-nav--kbd` (styles.css:766–770) делает их визуально-не интерактивными — листает только взрослый с клавиатуры. Эта роль больше не нужна: кнопка «Готово» и антикаскадный замок уже дают равноценную защиту от случайного продвижения. Убираем чтение и использование `adultConfirmAdvance` из `InstructionTask` (строка 396 и производные на 674, 675, 679). Настройка в `SettingsScreen.jsx` и её эффект в `SessionScreen.jsx`/`useSessionEngine.js` не трогаем — используется другими типами заданий.

## Прогресс и фазы

Фазы рецепта — это уже существующие сегменты между `heading`-шагами (не новая концепция данных, просто новая интерпретация существующих `steps`). При загрузке шагов вычисляем сегменты:

```
segments = steps.reduce(...) → [{ title: headingStep.text, startIndex, endIndex }, ...]
```

Шаги до первого `heading` (если он не первый элемент) попадают в безымянный «нулевой» сегмент.

Прогресс-бар в шапке (заменяет текстовый `{stepIndex+1}/{steps.length}`, строка 578) — горизонтальная полоса, разделённая на сегменты по фазам; внутри сегмента — деление по числу шагов фазы. Активный сегмент подсвечен, пройденные — приглушённо-залиты, будущие — контур. Название текущей фазы — под баром, производится из текста активного `heading`-шага.

## Фраза «Готовим на …» на титульном шаге

На самом первом шаге рецепта (`steps[0]`, обычно `type: "heading"` — название блюда + картинка) добавляем подпись с количеством персон, например «Готовим на двоих 🍽️».

- Число берётся из реального выбранного количества порций (`chosenPortions` в `index.jsx:434`, сейчас используется только чтобы вычислить `stepPortionsMultiplier` и потом теряется) — **не** из `portions`-state, который хранит уже коэффициент масштабирования ингредиентов (`chosen / base`, `parseRecipeTxt.js:218`), а не количество людей. Нужно завести отдельное состояние (например `portionsCount`) и сохранять туда `chosenPortions` рядом с существующим `setPortions(...)` на строке 435.
- Собирательные числительные 1–8 с fallback для чисел больше 8:

  | N | Фраза |
  |---|---|
  | 1 | Готовим на одного |
  | 2 | Готовим на двоих |
  | 3 | Готовим на троих |
  | 4 | Готовим на четверых |
  | 5 | Готовим на пятерых |
  | 6 | Готовим на шестерых |
  | 7 | Готовим на семерых |
  | 8 | Готовим на восьмерых |
  | >8 | Готовим на N человек |

- Показывается только когда `stepIndex === 0` и `step.type === "heading"` (типичный титульный шаг). Если по какой-то причине первый шаг рецепта не `heading` — фразу не показываем (нет подходящего места).
- Реализация — небольшая функция-хелпер (например в `parseRecipeTxt.js` рядом с `applyPortions`/`stepPortionsMultiplier`, раз там уже есть похожая RU-числительная логика в `formatWithUnit`) + новая строка-подзаголовок в разметке heading-карточки под текстом заголовка.

## Визуал/анимация

- Переход между карточками — slide+fade (~250–300 мс) вместо мгновенной замены (сейчас смена `step` мгновенная через `steps[stepIndex]`, строка 441).
- Смена фазы — на карточке нового `heading`-шага короткая emoji-пометка «Этап пройден! 👍» перед заголовком нового этапа. Не отдельный экран — переиспользуем существующую heading-карточку (`.instruction-step--heading`, строка 584), никакого нового компонента.
- Финал рецепта переиспользует ту же heading-карточку с другим текстом/иконкой (не новый экран/компонент).
- Чек-листы, warning-чайм (`playWarningChime`, строки 462–464), крупный текст — без изменений.

## Не затронутые части

- `parseRecipeTxt.js`, `engine.js`, `InstructionParamsContent.jsx` — без изменений.
- Вход из Планировщика (`CookPickerSheet.jsx`, `PlannerMenuScreen.jsx`) — без изменений, открывает тот же экран.
- Многопользовательский режим (`instruction-chef-panel`, `instruction-participants`, `owners`) — логика владения шагом не меняется, только низ/верх карточки.

## Проверка (verify)

Ручной прогон в браузере: старт рецепта с несколькими `heading`-этапами → подтверждение шагов кнопкой «Готово»/«Начнём»/«Понял(а)» по каждому типу → чек-лист блокирует «Готово» до отметки всех пунктов → быстрый двойной тап по кнопке не приводит к пропуску шага → «Назад» открывает предыдущий шаг и не сбрасывает прогресс → прогресс-бар сегментирован по фазам и подсвечивает активный сегмент → drawer «все шаги» отсутствует → титульный шаг показывает верную фразу «Готовим на …» для разных выбранных количеств порций (1, 2, 4, 8).
