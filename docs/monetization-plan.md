# План монетизации Mironium

**Начат:** 2026-11-06. **Статус:** план согласован в обсуждении с владельцем, реализация не начата.
Предыдущие документы — `docs/superpowers/specs/2026-09-13-lava-top-payments-design.md` (два рельса
Stripe/Paddle + Lava Top) и `docs/legal-launch-inputs.md` (только ЕС, d.o.o., Stripe). Этот план их
**пересматривает**: где расходятся — действует этот.

Факты о законах, налогах и санкциях ниже записаны по памяти из обсуждения, не по проверенным источникам.
Каждый такой пункт помечен **[проверить]** и до запуска подтверждается бухгалтером/юристом письменно.

## 1. Исходные факты (2026-11-06)

- ~1700 зарегистрированных, почти все за последние 30 дней; ~700 активных за 30 дней.
- **~70% пользователей — из России.** Россия — основной рынок, не боковая ветка.
- Доступ из РФ нестабилен и зависит от оператора/сети (у кого-то открывается без VPN, у кого-то
  только через VPN, у кого-то только по мобильной сети). Вероятная причина — неравномерная
  фильтрация ТСПУ зарубежного хостинга (Railway), а не блокировка зоны `.com`.
- Владелец — налоговый резидент Словении, трудоустроен полный день в своей Smart Washing d.o.o.
  (прачечная, есть убытки). Продавать через эту d.o.o. не хочет: неподходящий профиль, дорогой вывод денег.
- Есть партнёр в России, готовый работать на свой ИП/самозанятость.
- Владелец **принимает**, что рублёвая выручка законно в евро до него не дойдёт и будет тратиться
  внутри России (дикторы, иллюстраторы, консультанты-логопеды, реклама, партнёр).

## 2. Что уже есть в коде (переиспользуем)

- Модель доступа: `entitlements` (trial 30 дней, order, promo), grandfathered `all_access`,
  `backend/lib/billing-repository.mjs`, `billing-orchestrator.mjs` (идемпотентные вебхуки, сверка
  суммы/валюты, отзыв при возврате), письма об окончании доступа (`entitlement-reminder`).
- Провайдеры: `backend/lib/billing-providers/stripe.mjs` (разовый платёж), `lava-top.mjs`.
- Промокоды со скидкой/грантом + раздел в админке — основа для кодов партнёра.
- Экраны: `src/features/billing/SubscriptionScreen.jsx`, `CheckoutRedirectScreen.jsx`,
  `CheckoutReturnScreen.jsx`; согласия при покупке (RU/SL) в `checkout_consents`.
- Юридические черновики `backend/legal/*.html` (написаны под d.o.o.). Оплата выключена,
  пока `LEGAL_DOCS_VERSION=draft`.

## 3. Принятые решения

| # | Решение | Почему |
|---|---|---|
| D1 | Продавец в ЕС — **popoldanski normirani s.p.** владельца, не d.o.o. **[проверить у бухгалтера]** | При ожидаемой выручке в сотни € в месяц: налог ≈ 4% выручки, низкие взносы при основной занятости, деньги сразу личные, продукт отделён от прачечной |
| D2 | Международная оплата — **Merchant of Record (Paddle)**, не Stripe напрямую | MoR сам платит НДС всех стран, выставляет счета и разбирает споры по платежам; для одного разработчика это дешевле, чем делать самому |
| D3 | **Автопродление** с отменой в один клик и письмом за 3–7 дней до списания | Разовая оплата теряет тех, кто просто забыл продлить; честная отмена сохраняет доверие |
| D4 | Россия — **через партнёра**: он продавец (оферта, ЮKassa/Продамус, чеки), приложение выдаёт доступ по коду | Карты РФ не проходят международные рельсы; приём российских денег на словенский счёт — риск для банка |
| D5 | Рублёвая выручка **остаётся в РФ** и финансирует российские расходы проекта | Выплаты лицензиару из «недружественной» страны идут на счёт типа «О» (указ № 95) **[проверить]**; неформальные схемы не рассматриваем |
| D6 | **Крипта — нет** (не основной путь и не «вход для россиян») | Не решает проблему происхождения денег; регулируемый процессор отсечёт такие платежи, нерегулируемый — риск для банка; конверсия у родителей близка к нулю |
| D7 | Доступ из РФ — **TCP-прокси на VPS в России + домен `.ru`**, одна база и один бэкенд на Railway, не зеркало | Внутрироссийский трафик почти не фильтруется; синхронизировать нечего; шифрование до самого Railway, прокси трафик не видит |
| D8 | **Сначала доступ, потом paywall** | Нельзя брать деньги, пока приложение открывается через раз: будут претензии и возвраты |

## 4. Этапы

### Этап 0. Решения и консультации (владелец) — параллельно с этапом 1

- [ ] Бухгалтер (Словения): s.p. против d.o.o. Принести прогноз выручки (пессимистичный и
      оптимистичный) и убыток d.o.o. за прошлый год. Код деятельности (SKD) под продажу ПО.
      Нужна ли фискализация (davčno potrjevanje) при оплате через MoR. Декларирование.
- [ ] Юрист по санкциям (письменно): (а) лицензия/агентский договор между словенским резидентом
      и российским ИП на детское образовательное приложение для частных лиц — не подпадает ли под
      статью 5n Регламента ЕС 833/2014; (б) хранение данных россиян на сервере в ЕС (152-ФЗ) —
      риски для владельца и партнёра.
- [ ] Договор с партнёром: агентский или лицензионный (решает юрист); кто оплачивает VPS и домен,
      какую долю оставляет себе партнёр, на какие расходы проекта идут остальные деньги.
- [ ] Регистрация s.p., затем проверка компании (KYB) в Paddle.

### Этап 1. Доступ из России (код + партнёр) — первым

Инфраструктура (партнёр + владелец, инструкцию напишет Claude):
- [ ] Домен `.ru` (например `mironium.ru`) на партнёра; VPS у российского хостера.
- [ ] TCP-прокси (nginx `stream` с пробросом зашифрованного соединения без расшифровки) на 443 → Railway;
      домен добавлен в сервис Railway как свой домен, сертификат выпускает Railway.
- [ ] Запасной домен на случай блокировки.

Код (Claude):
- [ ] Приложение работает с нескольких доменов: CORS, CSP, `manifest`, область действия service worker,
      cookie без жёсткой привязки к `app.mironium.com`.
- [ ] Ссылки в письмах (подтверждение почты, сброс пароля, напоминания) ведут на домен,
      с которого пришёл пользователь (сохранять его при регистрации/входе).
- [ ] Кеширование ZIP-колод (`/decks/*`) на прокси: длинный срок кеша, у файлов в имени версия.
- [ ] Экран «Переезд на новый адрес» для уже установленного PWA: на новом домене своё хранилище
      браузера, пользователь входит заново; проверить, что всё нужное лежит в аккаунте, а не только на
      устройстве.
- [ ] Метрика: доля входов и активных пользователей по доменам.

Проверка: те, у кого раньше не открывалось, пробуют снова (дома по Wi-Fi и по мобильной сети).

### Этап 2. Оплата в ЕС и мире (Paddle)

- [ ] Провайдер `billing-providers/paddle.mjs`: подписки с автопродлением, вебхуки → существующий
      `billing-orchestrator` (добавить события продления, отмены, неудачного списания).
- [ ] Модель: у `entitlements` появляется связь с подпиской провайдера и `cancel_at_period_end`
      (поле уже есть); период продлевается каждым успешным продлением.
- [ ] Экран «Подписка» и управление ею: текущий план, дата следующего списания, «Отменить»
      (ссылка в портал покупателя Paddle), история платежей.
- [ ] Юридические тексты переписать под s.p. и MoR: продавец для покупателя — Paddle, ты — поставщик.
      Автопродление и отмена описаны явно. Заполнить все `[[...]]`, затем выставить `LEGAL_DOCS_VERSION`.
- [ ] Stripe-модуль оставить в коде выключенным (запасной рельс), Lava Top — не включать.

### Этап 3. Оплата в России (партнёр)

- [ ] Партнёр: оферта на своё имя, ЮKassa или Продамус с чеками (54-ФЗ), политика возвратов.
- [ ] Код: ключ доступа партнёра (одна запись в БД, хранится как хеш). Вебхук «оплачено» из платёжки
      партнёра (или вызов его скриптом) → наш сервер создаёт одноразовый код на план → письмо
      покупателю со ссылкой, которая активирует код. Склада кодов нет.
- [ ] Кабинет партнёра (на базе админки): продажи, активации, возвраты; отзыв кода при возврате
      денег (связь с отзывом доступа уже есть для заказов — расширить на коды).
- [ ] Выбор способа на экране «Подписка»: «Российская карта / СБП» → страница оплаты партнёра;
      «Другая карта» → Paddle. Обе кнопки на обоих доменах; по умолчанию первой показывается та,
      что соответствует домену/языку, но выбор всегда за пользователем.

### Этап 4. Переход на платную модель (продукт + UX)

- [x] Цены (решение владельца 2026-11-07). ЕС: €9,90 / €49,90 / €89,90 (как сейчас).
      РФ: **790 ₽** в месяц; полгода и год — с той же скидкой, что в ЕС (−16% / −24%):
      **3 990 ₽ / 7 190 ₽**. Проверить на первых продажах через партнёра; снижать легче, чем поднимать.
- [ ] Текущие 1700: объявить заранее (за 3–4 недели); бесплатно до даты X; «цена основателя» —
      скидка на первый год для тех, кто оформит подписку до даты Y (через промокоды).
- [ ] Новые пользователи: триал 30 дней (уже есть), без карты.
- [ ] Принципы paywall:
      - никогда не обрывать занятие ребёнка посреди сессии; проверка доступа — только при входе в тему;
      - ребёнок видит нейтральный экран «Позови взрослого», без цен и кнопок оплаты;
      - экран оплаты — только во взрослой зоне (за существующим взрослым замком);
      - после окончания доступа данные ученика не удаляются и видны взрослому в режиме просмотра;
      - напоминания: за 7 и 1 день до конца триала, в день окончания.
- [ ] Специальные условия по запросу (малообеспеченные семьи, специалисты/центры) —
      вручную через промокоды; отдельные тарифы — позже.

### Этап 5. После запуска

- Метрики: переход «триал → оплата» по рынкам, отток по месяцам, доля неудачных списаний,
  возвраты, доступность по доменам.
- Позже: семейный тариф/несколько учеников, тариф для специалистов, перевод интерфейса для
  словенского и других рынков ЕС.

## 5. Риски

| Риск | Что делаем |
|---|---|
| `.ru`-прокси тоже заблокируют | Запасной домен; второй VPS у другого хостера |
| Белые списки мобильного интернета в регионах РФ | Технически не решается; сообщить пользователям, что нужен Wi-Fi |
| 152-ФЗ (данные россиян хранятся за рубежом) | Вопрос юристу (этап 0); партнёр не хранит у себя данные покупателей сверх нужного для чека |
| Претензии к партнёру, если сервис недоступен в РФ | Политика возвратов в оферте; прокси и запасной домен; честное описание условий |
| Выручка в евро мала, а взносы s.p. фиксированные | Посчитать с бухгалтером до регистрации |
| Обиды текущих пользователей при переходе на платность | Объявить заранее, цена основателя, данные не удаляются |
