# Прописи (propis2) — конструктор страниц прописей

**С 2026-10-14 это и есть «Прописи»:** в каталоге тема называется просто «Прописи» (раньше
«Прописи 2»), а старая тема `propis` (v1) переименована в «Прописи старые» и убрана из каталога —
только архив. id, файлы, ключи синхронизации (`propis2:*`) остаются с `2`. Ниже в тексте «Прописи 2»
= эта тема, «v1»/«старые Прописи» = `propis`. Общий движок `src/topics/renderers/propis/` и данные
глифов `tools/propis/` по-прежнему используются этой темой — при уборке старой темы их не удалять;
правки форм букв идут туда.

## Архитектурные решения (2026-10-03)

- **Zip-тема, как и все остальные** (не builtin — это было отвергнуто 2026-10-03). Пакет:
  `tools/propis2/topic.json` + `scripts/build-propis2-deck.mjs` → `public/decks/propis2_vX.zip`
  и запись в `public/decks/catalog.json` (status beta). В zip подмешиваются данные глифов из общих
  `tools/propis/wide.json` и `elements.json` (≈25 КБ в сжатом виде) — один источник правды с v1.
  Сборка: поднять `meta.version` в `tools/propis2/topic.json`, `node scripts/build-propis2-deck.mjs`.
- **Рендерер в приложении**, как у v1 (`RENDERER_REGISTRY.propis2`), код движка не копируется, а
  импортируется из `renderers/propis/` (`wordEngine.js`, `PrintPageView.jsx`). Страница — задача
  `print_page` (`renderers/propis2/pageTask.js`), данные берутся из установленной темы
  (`topicRecord.wide / wideSheets / elements`).
- **Найденная ошибка установщика:** `importTopic` отбрасывал `wide`, `wideSheets`,
  `wideElementRepeat` при сохранении темы (как раньше `elements`). Исправлено в `topicLoader.js`,
  тест `src/topics/propis2Install.test.js` (и для v1).
- **Домашний экран темы — конструктор.** `App.jsx`: экран `params` для renderer `propis2`
  открывает `features/propis2/Propis2Home.jsx` вместо `ParamsScreen`.
- Хранение страниц: IndexedDB (`kv`), синхронизация с аккаунтом — позже; экспорт/импорт файлом.

## Что сделано

- **Шаг 0 (скелет, v0.1.0):** тема в списке, свой главный экран.
- **Шаг 1 (сквозной сценарий, v0.2.0):** «Мои страницы» (`Propis2Library`) → конструктор
  (`Propis2Editor`: название, разлиновка узкая/широкая, строки трёх видов — образец / образец с
  точками старта / чистая; тип «буквы, слоги, слова» или «элемент»; вверх/вниз, дубль, удаление;
  предупреждения о символах без начертания и о строках шире листа) → «Показать как ученику»
  (общий `PrintPageView`: тап по строке — анимация, зум, листание, «🖨 Печать»). Страницы
  сохраняются автоматически в IndexedDB (`propis2:library`), создаются с нуля, из готового набора
  (листы 1–18) или копированием.
  Файлы: `renderers/propis2/{model,storage,pageTask,data}.js`, `features/propis2/*`.
  Тесты: `model.test.js`, `storage.test.js`, `Propis2Home.smoke.test.jsx` (весь сценарий).
- **Шаг 2 (повторение и тексты, приложение без новой версии колоды):** тип строки «Текст
  (переносится по строкам)» — жадный перенос по ширине листа, каждая строка пишется один раз (метка
  `#1` в движке: однословная строка не размножается), слово шире листа предупреждается, не
  обрезается; тип «Пустая строка для письма» и опция страницы «пустая строка после каждой строки»
  (движок рисует пустую разлинованную строку для `""`); отметка «повторить» у строк и кнопка
  «Страница из отмеченного» (целые строки; новая страница редактируема, исходная не меняется).
- **Шаг 3 (панель показа):** тап по образцу на странице открывает панель (`Propis2ShowPanel`):
  тот же фрагмент (слово под пальцем; у строки с повторами — одно слово) крупно на собственной
  разлиновке, кнопки «Повтор», «Медленно» (скорость ×0,4 без перезапуска), «Закрыть». Страница
  остаётся смонтированной под панелью, поэтому номер страницы, зум и прокрутка сохраняются;
  одновременно идёт только одна анимация (на странице встроенная анимация отключена).
  В v1-код добавлены только опциональные, по умолчанию инертные свойства: `PrintPageView`
  (`onFragmentTap`, `bare`, `focus`, `speedFactor`), `AnimatedStrokes`/`useLoopingStrokes`
  (`speedFactor`).
- **Шаг 4 (комплекты):** «Мои страницы» → раздел «Комплекты». Комплект — упорядоченный список
  страниц библиотеки (одну страницу можно добавить несколько раз), общая разлиновка на весь
  комплект, перестановка, «дублировать» (независимая копия страницы в библиотеке сразу после
  оригинала), правка страницы прямо из комплекта, подпись «с листа N». Показ и печать — одним
  буклетом: каждая страница комплекта дополняется пустыми строками до целого экранного листа
  (`setToLines`), поэтому счётчик движка «Страница k из N» и есть номер страницы комплекта на экране
  и на бумаге; переход вручную. Удаление страницы убирает её из комплектов. Код: `model.js`
  (`newSet/setToLines/setPageStarts`), `storage.js` (`upsertSet/removeSet`),
  `features/propis2/Propis2SetEditor.jsx`.
- **Шаг 5 (предпросмотр):** рядом с редактором (на экранах от 900 px — справа и закреплён, на узких —
  под формой) страница так, как она будет показана и напечатана (`Propis2Preview`, `PrintPageView`
  с `bare`), с переключателем листов и кнопкой «Скрыть/Показать предпросмотр». Раскладка идёт по
  отложенной копии страницы (`useDeferredValue`), ввод не тормозит.
- Не проверено вручную в браузере: печать (используется механизм v1), установка из каталога в
  живом приложении.

## Конструктор v2: карусель + страница (2026-10-03)

Редактор из формы (список строк с селектами) заменён на «сборку руками»: слева вертикальная зацикленная
карусель плиток (вкладки Элементы / Строчные / Заглавные, плитки нарисованы собственными траекториями),
справа страница. Плитка перетаскивается на конкретную строку (pointer events: мышь — сдвиг >5px, палец —
горизонтальный сдвиг, вертикальный остаётся прокруткой карусели) или тапается (встаёт под последней строкой).
Тап по строке страницы выделяет её; панель внизу правит текст, вид (образец / с точками / чистая),
«повторить», порядок, дубль, удаление. Слова и тексты — кнопки «+ Слово», «+ Текст», «+ Пустая строка».
Модель страницы и хранение не менялись; новое в `model.js`: `lineOwners`, `dropTile`, `appendTile`.
Геометрия строк для попадания: `rowAtSvgY` в `PrintPageView.jsx`; подсветки — проп `overlays`.
Слогов в карусели нет (набираются в «+ Слово»). Перестановка строк перетаскиванием не сделана (кнопки ↑ ↓).
`paginateRows(..., { exact })`: страницы v2 не добиваются до чётного числа (флаг `exactPages` в задаче).

### Раскладка v2.1 (2026-10-03, по просьбе пользователя)

Холст-страница сверху (на всю ширину, но не выше доступного места больше чем на 20%: `MAX_OVERFLOW` в
`Propis2Editor.jsx`; небольшой вертикальный скролл допускается), над ним одна линия настроек
(узкая/широкая, «писать под каждой строкой», «Из отмеченного»), внизу табы «Символ / Слово / Текст».
«Символ» — горизонтальная зацикленная карусель (перетаскивание вверх; у касания вертикальный жест = перенос,
горизонтальный = прокрутка карусели). «Слово» и «Текст» — ввод + кнопка добавления + плитка-«чип» для
перетаскивания на строку. При перетаскивании у верхнего/нижнего края холста страница сама прокручивается.
Не сделано: переключатель «редкая / частая косая линейка» (движок: шаг косой сетки `NARROW_CELL`, к нему
привязывается начало букв — нужна проверка готовых наборов); буквы ш, ы, ии не имеют своих штрихов
(`compose`) и показаны в карусели текстом.

### Раскладка v2.2 + линейка (2026-10-03)

Альбомный планшет (≥900px и ширина ≥ высоты, `SIDE_QUERY` в `Propis2Editor.jsx`): лист слева на всю высоту, справа
панель (настройки, панель строки, табы; карусель там — обычная прокручиваемая сетка без цикла, перетаскивание
касанием — горизонтальным жестом). Портрет: как v2.1 (лист ≤ 120% высоты свободного места).
Линейка (уточнено пользователем дважды; итог): `page.grid` = "regular" (редкая, стандартная школьная — наклонная
линия через 20 мм, `SHEET_DIAGONAL_LINES`) | "dense" (частая — шаг следует строке и равен расстоянию между вершинами «и»: 3 мм на узкой строке
(`SHEET_DIAGONAL_LINES_DENSE`, как на листах «Элементы букв» v1), 5 мм на широкой (`SHEET_DIAGONAL_LINES_WIDE_DENSE`)); `page.midDash` — пунктир в серединных линиях (узкая и широкая строка). Обе сетки взяты из готовых
тетрадей v1 (`ELEMENT_DIAGONAL_MM`, `DIAGONAL_MM` в propisRuling.js). При "dense" начала букв привязываются к НАРИСОВАННЫМ линиям (`drawnGridSnapX` в PrintPageView.jsx: линия n = n*шаг − y·tan,
нечётные страницы сдвинуты на ширину листа, как рисует PrintPage). При "regular" (20 мм) привязка осталась по скрытой
методической сетке: к линиям через 20 мм буквы не привязать. Методическая сетка на страницах v2 НЕ рисуется (`simpleGrid` в задаче → `PrintPageView`, у v1 флага нет,
v1 не затронут). Комплект берёт линейку и пунктир первой страницы.

### Знаки препинания (2026-10-03, deck 0.3.0)

`. , ! ?` взяты из v1 (`tools/propis/topic.json`, карточки `type: "punctuation"`, записанный штрих) и добавлены в
`tools/propis/wide.json` как глифы `kind: "punct"` (`noJoin`, `noNormalize`, `stretch: 1`, y сдвинут на −26: база v1 88 →

Цифр в v1 НЕТ (там они подставляются системным шрифтом, штрихов не записано): цифры требуют отдельной оцифровки.
Не записаны также заглавные Ё Й Ъ Ы Ь.

### Широкая строка: только буквы внутри строки; телефон (2026-10-03)

* «!» и «?» увеличены до высоты заглавной (в wide.json; ×~2.1 от v1, `. ,` как в v1).
* Широкая строка (`page.ruling === "wide"`) — как в методике: только символы, которые не выходят за строку. Выход считается
  по раскладке движка на узкой строке (`glyphReach.js`, допуск 4 ед. на петлю/точку): недоступны все заглавные, строчные
  б в д з р у ф ц щ и знаки ! ?; `. ,` и элементы доступны. В карусели такие плитки скрыты (вкладка «Заглавные» тоже),
  в набранном слове/тексте они подсвечиваются красным с пояснением (`findOutsideRow`, поле `outside` в `analyzeRow`).
  ё и й попали в допустимые (точки/бровка выходят всего на 3 ед.) — при необходимости ужесточить `TOLERANCE`.
* Телефон (≤640px, портрет): лист на всю ширину, виден примерно наполовину, остальное скроллом внутри холста;
  сверху полный набор настроек (переносится на несколько строк), снизу панель строки и табы.
* Не сделано: цифры (нужны собственные захваты, в v1 их нет), «клетка» и «обычная линейка» как типы сетки.

Сетка «Клетка» (2026-10-03): `page.grid = "square"` — обычная школьная клетка 5 мм (вертикали и горизонтали через 30 ед.), под направляющими
строки (базовая линия, пунктир остаются). Буквы привязываются, как и при «Редкая», к скрытой методической сетке. Дальше: «обычная (не прописная)
линейка» как ещё один вид сетки.

### Тип сетки и ввод тапом (2026-10-03, по просьбе пользователя)

* Первый переключатель настроек: «Прописи / Клетка / Линейка» (`page.gridKind`, по умолчанию «Прописи»; старые страницы с
  `grid: "square"` читаются как «Клетка», `pageGridKind` / `taskGrid` в model.js). «Клетка» (5 мм) и «Линейка» — обычная бумага:
  рисуются только базовые линии строк (без тонкой линии, пунктиров, левой планки), косая линейка и пунктир недоступны
  (deactivated), «Узкая/Широкая» остаются (задают размер письма). Шаг «Линейки» = шаг строк (12 мм), т.е. линии — это базовые
  линии строк; отдельного шага у «обычной линейки» пока нет.
* Символы выбираются без перетаскивания: выделить строку (тап по ней на листе), тап по плитке — символ добавляется в конец
  текста выделенной строки (`tapSymbol`; элемент заменяет строку); без выделенной строки символ начинает новую; «⌫» стирает
  последний символ. Плитки — многострочная сетка с вертикальной прокруткой (внизу на телефоне и портретном планшете, справа на
  альбомном). Горизонтальная карусель и drag&drop удалены.

### Пустые строки выделяются; фиксированные зоны (2026-10-03)

* Строка без символов теперь занимает своё место на листе (пустая линованная строка: `pageToLines` / `lineOwners` отдают ""),
  поэтому её можно выделить. Тап по свободному месту листа (`selectRowAt`) создаёт пустую строку на этом месте (промежуток
  заполняется строками «пустая строка»); тап по «месту для письма» (writeAfter) и вне линеек снимает выделение.
* Зоны экрана не меняют размер: панель настроек, холст и нижняя панель — фиксированные (`--dock-h` = clamp(260px, 36dvh, 380px)
  на портретном планшете; на телефоне холст 72vw/44dvh и панель на остаток; на альбомном планшете лист слева, справа настройки
  и панель на остаток). Внутри нижней панели: полоса выбранной строки (фикс. 104–108px, скролл внутри), табы, тело (плитки
  скроллятся внутри). Сводка «Строк с проблемами» перенесена в полосу панели. Размеры проверены в Chromium (390×844, 820×1180,
  1180×820) при выборе строки, наборе символов и смене табов: не меняются.

### Редизайн конструктора: пиктограммы вместо текста (2026-10-03)

Весь конструктор без видимого текста: каждое управление — иконка (`Propis2Icons.jsx`, 24×24, currentColor), имя — только
`aria-label` (для скринридеров и тестов; тесты находят кнопки по aria-label). Исключение — то, что и есть содержимое: название страницы и
текст строки/слова. Рисунки категорий в пикере — собственный почерк колоды (первый элемент, «а», «А», «?»), вкладка «Символ» — «а».
Палитра семейства «литературные» (кремовая бумага, бирюзовый акцент `#4a9b8f`, синие чернила `#1d4ed8`), кнопки с «3D»-нажатием, цели касания
42/44/48px (телефон/планшет), safe-area в нижней панели. Раскладки: портрет (настройки / холст / панель), телефон (холст ≈ пол-листа),
альбомный планшет (лист слева, инструменты справа). Вся стилистика конструктора — в конце `propis2.css` (блок «constructor «Прописи 2»»).

### Умолчания и точная привязка (2026-10-04)

* Умолчание новой страницы: «Прописи» / «Узкая» / «Частая» (`newPage`: `grid: "dense"`, `ruling: "narrow"`, `gridKind` не задан = прописи) —
  выглядит как классическая пропись. Старые страницы без `grid` читаются как «Редкая».
* Частая сетка на узкой строке = клетка самих букв, 15 ед. (2,5 мм; `NARROW_CELL`, расстояние между вершинами «и»), а не 3 мм: при 3 мм
  стойки букв «уплывали» от линий по слову (шаг букв 15, шаг линий 18). Теперь начало каждого глифа привязано к нарисованной линии
  (`drawnGridSnapX`), а стойки внутри буквы и слова ложатся на линии, потому что шаги равны. На широкой — 5 мм (30 ед.), как раньше.

Пунктиры (направляющие «серединные» линии) на страницах v2 слегка красные (`#e57d7a`, `dashColor` в PrintPageView; страницы v1 сохраняют цвет сетки).
Широкая строка: наклонные рисуются только внутри широких полос (`clipPath` по `wideBandTop`/`wideBandHeight`), в узких полосках между строками их нет
(как в методике); на узкой строке косые идут сплошь.

### Блок «Страница»: согласованный состав (2026-10-04, до реализации)

Верхняя полоса, мини-пикеры (иконка + стрелка, по нажатию список вариантов):
* формат: А4 вертикальный / А5 вертикальный (длина строки определяет вместимость; сейчас отрисовывается только А5);
* сетка: прописи частая / прописи редкая / клетка 5 мм / линейка;
* строка ученика: узкая / широкая;
* флаг «пунктир»;
* поля: нет / слева / справа — красная линия, **1,5 см** (формат тетради меньше школьной), **уменьшают вместимость строки**,
  на развороте **чередуются** (слева/справа по сторонам разворота);
* листание страниц: «ушки» по левому и правому краю холста.
Номер страницы и водяной знак (текст) — **только при экспорте в PDF** (настройки вывода), на экране их нет.
Шаблоны (готовые наборы) переезжают в страницу (галерея), из библиотеки селект убирается. Мокап был локальным (src/mock, в git не входит).

### Пресеты страниц и синхронизация (2026-10-04, согласовано, до реализации)

* Пресет = комплект (set), помеченный как шаблон; выбор пресета открывает **все его страницы**. В галерее — **только текстовые названия**
  (группы: «Методика» — встроенные листы 1–18, «Мои» — свои), миниатюр нет. Первый элемент — «пустая страница».
* Страница из пресета **закрытый макет**: правятся только символы/слова в строках; нельзя добавлять, удалять, переставлять строки и
  менять параметры строк. Блок «Страница» заблокирован (формат, строка, поля, сетка), пока есть содержимое; доступен только пунктир.
  «Очистить страницу» (иконка, отмена на несколько секунд) снимает блокировку. Правка символов — с теми же проверками, что сейчас
  (широкая строка: только буквы внутри строки; слово не влезает по ширине — красная подсветка).
* Встроенные пресеты не редактируются; «сохранить копию в мои». Свои пресеты: «сохранить как пресет» из комплекта или одной страницы.
* Синхронизация между устройствами аккаунта — **существующим механизмом**: офлайн-очередь `syncQueue` (IndexedDB) → `pushOp('kv.upsert',
  { key, value })` → `processSync` → таблица `account_kv`, чтение `GET /api/account-kv?prefix=…` (так уже синхронизируются план урока,
  инструкции, настройки групп). Библиотека «Прописей 2» (страницы, комплекты, пресеты) пойдёт тем же путём. Сервер хранит значение по ключу
  целиком (last-write-wins), поэтому ключи **по документам** (`propis2:page:<id>`, `propis2:set:<id>`, удаление — запись-надгробие с
  `updatedAt`), а не один ключ на всю библиотеку: правки разных страниц на двух устройствах не затирают друг друга.

## Блок «Строка» — согласовано (2026-10-04)

Параметры строки живут в ярусе над холстом (ярус «Строка», под ярусом «Страница»), действуют на **выбранную** строку; умолчаний страницы в этом ярусе нет. Параметры строки **входят в пресет** (сохраняются и воспроизводятся вместе со страницей).

- **Повтор:** одна / на всю строку (копии пунктиром, постоянная яркость 0.6 — как сейчас в v1) / затухание.
- **Затухание:** алгоритм из v1 (коммит b6f3ab0, позже заменён плоским вариантом в 2391bd6): яркость копии линейно падает от 1 до 0 по x начала копии до `WIDE_FADE_END_X = 415` (середина строки); копия с яркостью 0 не рисуется, остаётся только красная точка начала. Первая копия (образец) без затухания.
- **Красные точки (на своей строке):** нет / у образца / у образца и в местах копий.
- **Флаги:** копии пунктиром/сплошной бледной; место для письма под строкой.
- Служебные: ↑ ↓ дубль удалить; поле текста, ⌫ и пометка для повтора — в блоке символов.
- На странице-пресете (раскладка закрыта) параметры строки заблокированы, меняются только символы/слова.
- Не делаем: регулятор интервала, стрелки направления.

## Реализовано: три блока и пресеты (2026-10-04)

- Над холстом два яруса с мини-пикерами: «Страница» (тип бумаги, разлиновка, косая линейка, пунктир, строка для письма, пресеты, из отмеченного) и «Строка» (повтор, красные точки, копии пунктиром, повторить строку, ↑ ↓ дубль удалить). Поле текста, ⌫ и плашки — в нижнем блоке «Символы».

Выбор пресета создаёт НОВУЮ страницу с флагом `locked`; на ней закрыты бумага, разлиновка, сетка, пунктир, строка для письма, добавление/удаление/перестановка строк и параметры строк. Меняются только символы и слова выбранной строки (плашка заменяет текст строки). «Очистить страницу» открывает раскладку (отмена 8 с). «Сохранить как пресет» — в панели «Пресеты», с названием.
- Синхронизация: см. раздел ниже.

## Реализовано: синхронизация библиотеки (2026-10-04)

- Каждая страница, комплект и пресет — отдельный документ `account_kv`: `propis2:page:<id>`, `propis2:set:<id>`, `propis2:preset:<id>`. Запись — через офлайн-очередь (`pushOp("kv.upsert", {key, value})`, как у планировщика/инструкций), чтение — `GET /account/kv?prefix=propis2:`. Бэкенд не менялся.
- Конфликты: last write wins по `updatedAt` документа. Удаление — «надгробие» `{id, deleted: true, updatedAt}` (хранится локально в `library.deleted`), чтобы удаление дошло до других устройств и документ не воскрес со старой копии. Более новая локальная правка переживает более старое надгробие.
- Удаление страницы перештамповывает комплекты, где она была (их `pageIds` изменились).
- Поток: при открытии темы и при возврате на вкладку — pull и слияние (`mergeRemote`); при каждом автосохранении (debounce 300 мс) — `diffOps` против снимка «что известно аккаунту» и отправка только изменённых документов. Что аккаунту неизвестно (первый запуск, офлайн-правки) уходит со следующим сохранением.
- Код: `src/topics/renderers/propis2/syncLib.js` (чистые функции, тесты `syncLib.test.js`), подключено в `Propis2Home.jsx`.
- Не сделано: очистка надгробий (растут по одному на удалённый документ; мелкие), индикатор «синхронизировано».

## Реализовано: поля и формат (2026-10-04)

- **Поля** (`page.margin`: off | left | right): красная линия в 15 мм от края; сторона задана для первой страницы и чередуется на развороте (левая страница — слева, правая — справа при «left»; наоборот при «right»). Поля сужают строку на 15 мм (`rowMaxX(page)` в `model.js`, параметр `maxX` в `layoutWideLinesIntoRows`): копии и перенос текста считаются по меньшей ширине; привязка букв к линиям учитывает смещение содержимого на каждой странице.
- **Формат** (`page.format`: a5 | a4): А5 — страница готовых прописей (148,5×210, две на листе А4 при печати), А4 — целый лист 210×297 вертикально, одна страница на лист (23 строки вместо 16, строка шире на 61,5 мм). Геометрия — `makeGeom` в `PrintPageView.jsx` (сетки наклонных строятся под каждый формат; у А4 нет «пары»: фаза сетки не переходит между страницами). Печать А4 — `@page propis-a4`, один лист на страницу. Для А5 при нечётном числе страниц последняя больше не теряется при печати.
- Формат, поля и параметры строк входят в пресет. Комплект берёт формат и поля у первой страницы.
- Не сделано: номер страницы и текстовый водяной знак при экспорте в PDF (в печати пока только лист).

## Логика параметров строки — пересмотр (2026-10-05)

- **Повтор** — что рисуется: «одна запись» / «на всю строку» / «затухание». Теперь размножаются и одиночный символ, и смешанная последовательность («и м» повторяется целиком), раньше — только слово или уже повторяющаяся группа. Затухание само включает размножение. Флаг движка `#r`.
- **Красные точки** — «нет» / «у образца» / «по всей строке»: точка в каждом месте строки, где начинается копия (или начиналась бы). При «одной записи» копии не рисуются, остаются только точки — это места, где ребёнок начинает писать (`#r#x`). Прежняя «метка #d» (образец + две точки справа) для новых строк не используется.
- Строки из готовых листов и старые страницы (нет поля `repeat`) работают по прежнему правилу (`repeat: "auto"`, метки `#d`/`#c`); пикер показывает для них то, что реально делает движок. Первый же выбор в пикере делает строку «явной».
- «Копии сплошной» работает и вместе с затуханием.

## Ввод одним полем (2026-10-05)

- Нижний блок — одно многострочное поле для системной клавиатуры (`Propis2Field.jsx`, логика `fieldText.js`). Плашек букв, табов «Слово/Текст» и экранного ⌫ больше нет. Рядом кнопка «Элементы» — прокручиваемый список элементов набора; выбор вставляет id элемента отдельной строкой.
- Поле показывает строки листа **от выбранной строки до конца**, одна строка поля = одна строка листа. Без выбора поле пустое: ввод идёт ниже последней строки. Тап по строке листа выбирает её и начинает поле с неё; курсор в поле подсвечивает соответствующую строку листа. Enter создаёт новую строку, удаление строки поля удаляет строку листа. Новая строка наследует параметры строки выше; строки, оставшиеся на своих местах, сохраняют id и параметры.
- Вид строки определяется автоматически: пустая строка — пустая строка для письма; **любой пробел** (и в начале, и в конце строки) — текст с переносом (повтор, точки, копии отключаются); иначе образец. Пробелы в начале строки сдвигают текст вправо на столько ячеек косой линейки (5 мм на широкой, 2,5 на узкой) — так слово можно поставить посередине строки (флаг движка `#iN` на первой строке абзаца; перенос учитывает отступ). Пробелы между словами по-прежнему сжимаются в один. Чередующийся образец («и м») теперь включается кнопкой «Строка как текст» в положение «выкл» (`asText: false`). Кнопка «Строка как текст» в ярусе «Строка» переопределяет правило (`row.asText`). Для текста повтор, точки и копии недоступны; остаётся «строка для письма после каждой строки» (параметр страницы).
- На странице из пресета поле показывает только текст выбранной строки, в одну строку; строки не добавляются и не удаляются.
- Отключены автокапитализация, автокоррекция и проверка орфографии (иначе iOS ставит заглавную букву, а на широкой строке заглавных нет).
- Нижней «зоны» больше нет: блок внизу — только поле ввода. Оно растёт с текстом до прежней высоты зоны (`--dock-h`, на телефоне не больше 45% экрана), дальше скроллится; остальное место отдано холсту. Кнопка «Элементы» слева от поля (как «+» в мессенджерах): справа привычно стоит «отправить», а текст у нас попадает на лист сразу.

- Экранная клавиатура: пока она открыта, редактор занимает ровно видимую часть экрана (`visualViewport`: `top = offsetTop`, `height`), поэтому поле ввода всегда над клавиатурой. Клавиатура считается открытой, когда `innerHeight − visualViewport.height > 90` (iOS сдвигает страницу, `offsetTop > 0`, и формула «innerHeight − height − offsetTop» ошибочно давала 0 — отсюда первая версия, где поле пряталось под клавиатурой). Chrome на Android сам ужимает окно — ничего делать не нужно.
- Элемент из списка вставляется **в позицию курсора** как отдельное слово (пробелы по краям добавляются, в конце строки — нет, чтобы строка не стала текстом): внутри текста элемент рисуется на своём месте между словами. Список открывается над полем; нижний блок не обрезает его (`overflow: visible`, выше ярусов по z-index).
- **Пробелы внутри текста.** Раньше перенос текста (`wrapPassage`) резал абзац по `\s+` и склеивал слова одним пробелом, поэтому любые лишние пробелы между словами пропадали на листе (в поле они были). Теперь один пробел — обычный промежуток между словами, каждый следующий добавляет ячейку косой линейки: `wrapPassage` вставляет в строку для движка псевдослово `_N`, движок сдвигает следующее слово на N ячеек (`pendingGap`), `pickFragment` псевдослова пропускает. Пробелы в начале абзаца по-прежнему отступ (`#iN`).
- **Перенос по сетке и Enter внутри текста (2026-10-05).** (1) Ширину строки при переносе измеряли «в вакууме», а на листе слова встают на линии выбранной сетки (редкая/частая, поля, формат), поэтому на другой частоте наклонных строки выходили за край. Теперь `lineWidth`/`wrapPassage`/`analyzeRow` считают по тому же `snapXFor` (экспорт из `PrintPageView.jsx`) с запасом в одну ячейку; тест перебирает узкую/широкую × редкая/частая × с полями/без. (2) `rowsFromField` сопоставлял строки поля со строками листа по номеру, поэтому Enter посередине сдвигал содержимое относительно параметров строк (в том числе `asText`: «образец» у соседней строки схлопывал пробелы). Теперь неизменённые строки в начале и в конце сохраняют свои строки и параметры, переписывается только изменённый участок.

## Комплекты и «Методика» из печатных тетрадей v1 (2026-10-05)

- **Один термин — «Комплект».** Бывший «пресет» везде называется комплектом (панель «Комплекты» в ярусе «Страница», «Сохранить как комплект», «Из комплекта» в библиотеке). Комплект из одной страницы — страница с закрытой раскладкой; комплект из нескольких — набор страниц (`set`). Группы: «Методика» (готовые) и «Мои».
- **Готовые комплекты из тетрадей v1.** PDF не разбираются: `tools/propis2/build_kits.py` берёт те же списки, из которых `scripts/propis_worksheets` печатает тетради (группы букв, слоги, слова, тексты), и пишет `src/topics/renderers/propis2/kits.json` (≈200 КБ, грузится лениво при открытии темы). Шесть комплектов: «Прописи — часть 1 / часть 2» (на каждую букву две страницы: с образцом и затухающими копиями, затем самостоятельно с образцом в начале строки; строчная и заглавная, у Ё Й Ы заглавной нет — только строчная), «Соединения букв» (160 слогов × 3 строки, 30 страниц), «Слова, часть 1 / 2» (по 2 строки на слово), «Тексты для переписывания» (24 страницы: образец-текст вверху, внизу пустые строки). Страницы — узкая строка, редкая косая линейка 20 мм, поля слева с чередованием, А5, по 17 строк, как в печатных тетрадях.
- **Выбор комплекта** создаёт копию: комплект (`set.kit`) и его страницы (`kitId` = id комплекта, раскладка закрыта). Страницы комплекта не показываются в общем списке страниц и в «Добавить страницу в комплект»; удаление комплекта удаляет и их; копия комплекта получает копии страниц.
- **Не перенесено:** три пустых тетради (стандарт / плотная / точки) — пустая страница с нужной сеткой делается кнопкой «Новая страница»; тетрадь с точками требует нового типа бумаги; обложки и вставка со знаками препинания — отложены. Старые PDF в теме не используются.

- **17 строк на узкой строке (2026-10-05).** Раньше конструктор давал 16 строк на любой разлиновке: «широкая строка» методики устроена так, что нулевая линия разлиновки — лишь верхняя кромка первой широкой полосы, и содержание начинается с первой строки (16 на А5, 23 на А4); я перенёс это правило и на узкую, где оно не нужно. Теперь на узкой строке содержание начинается с нулевой линии и страница вмещает все строки печатной тетради: 17 на А5, 24 на А4 (`rowsPerPage(page)`, флаг `task.narrow17` для `PrintPageView`, у v1 флага нет — его листы не изменились). На широкой по-прежнему 16 / 23.

## Соединение — не часть буквы у о б ю э ф в (2026-10-05)

- Выход вверх, которым буква соединяется со следующей, у части букв — не их собственный штрих, а добавочный элемент. Нашли так: у каждой захваченной буквы взяли последнюю кривую и сравнили с «каноническим соединением» (одна и та же кривая C +9,0 / +29,4,−19 / +39,1,−26 от точки основания). Точно такая кривая в конце штриха у о, ю, с, э, х, ж, б, ф, в; **по решению методиста у с, х, ж она — часть самой буквы** (форма та же, но так их пишут), поэтому добавочное соединение только у **о, б, ю, э, ф, в** (у заглавных Г Р О Ф Б Э З Ю она уже была отдельным `tailStroke`). У г п т и н к л м я ш ц щ ч у д з а е ь ъ ы й — конец штриха своей формы (крючок/хвост буквы), он остаётся частью буквы.
- Теперь эти шесть букв пишутся без соединения, если за ними нет буквы (одна, последняя в слове, перед знаком препинания), и с ним, если следом буква. Движок: у глифа поле `tailSplit` (последняя кривая штриха отрезается как соединение) или `tailStroke`, плюс `tailLift` (подъём конца над пунктиром теперь у соединения, а не у тела буквы) и `tailContinuous`. Значения — `src/topics/renderers/propis2/glyphOverrides.js`: общий `tools/propis/wide.json` (из него строится и замороженная v1) не менялся; перекрытия применяются в `buildGlyphMap`/`buildPageTask` конструктора, пересборка zip колоды не нужна.
- Спорные: а, е, д, з, у, ч, ь, ъ, ы, ц, щ — их хвост не канонический, оставлен как часть буквы. Если по методике у какой-то из них соединение тоже добавочное, это одна строка в `glyphOverrides.js`, но для неканонического хвоста нужно отдельно указать, где начинается соединение.

## Пары «Аа» в прописях букв (2026-10-05)

- Пара — **сначала заглавная, потом строчная**, между ними промежуток: у заглавной нет соединения спереди, а строчная, стоящая перед заглавной, «сливалась» с ней. В строках комплектов это текст «И  и» (два пробела); лишний пробел в образце — это ячейка косой линейки (`rowToLine` превращает его в псевдослово `_N`, как в тексте), так что промежуток можно править прямо в поле.
- Пары в размноженной строке разнесены дальше, чем буквы внутри пары: у строки есть скрытый параметр `gap` (N ячеек между повторяющимися единицами → флаг движка `#gN`, в `multiply` единицы склеиваются через `_N`). В интерфейсе параметра нет, он живёт в самих строках комплектов и копируется вместе со строкой.

## Комплект открывается сразу в просмотрщике (2026-10-05)

- Выбор готового комплекта («Методика») больше не ведёт на экран комплекта: он открывается сразу в просмотрщике (страницы подряд, «Печать», стрелки). В просмотрщике рядом с ✕ кнопка ✎ «Изменить эту страницу» — открывает конструктор на показанной странице, «назад» возвращает в просмотрщик. Экран комплекта (название, разлиновка, порядок страниц) остаётся только по кнопке «Изменить» у своего комплекта в библиотеке; если он не нужен совсем — его можно убрать отдельно.

## Комплект в редакторе и скорость

- Редактор, открытый на странице комплекта (из просмотрщика по ✎ или из экрана комплекта), показывает полосу «Стр. N из M»: листание ‹ ›, «Копия» и «Удалить» (с подтверждением). Отдельный экран комплекта для правки состава больше не нужен. «Показать ученику» из такого редактора открывает весь комплект, а не одну страницу.
- Скорость: раскладка строк с повтором (`wordEngine.js`) считала число копий перебором 1..60 полными раскладками, и геометрия глифа пересчитывалась на каждую копию. Теперь геометрия глифа кэшируется (глиф + масштаб), число копий оценивается по шагу двух копий и проверяется по соседям. Страница «букв» 1,2 с -> ~0,1 с, комплект «буквы-1» 16 с -> ~2,3 с (Node). Просмотрщик больше не пересобирает задачу на каждом рендере (перелистывание вызывает рендер).
- Остаётся: большой комплект раскладывается целиком при открытии (около 2-6 с у «букв»). Следующий шаг, если мало: раскладывать постранично или кэшировать одинаковые строки.

## Панели инструментов (стиль Edits)

- Три панели над холстом (страницы комплекта, страница, строка) теперь по одной строке каждая, листаются пальцем вбок (`scroll-snap`, без полосы прокрутки). Кнопка = иконка над короткой подписью (Формат, Бумага, Строки, Наклон, Поля, Пунктир, Писать, Править, Очистить, Комплекты; Образец, Точки, Копии, Текст, Повтор, Выше, Ниже, Дубль, Удалить). Включённое подсвечено, группы разделены тонкой чертой.
- Выпадающие списки, панель «Комплекты» и подсказки по долгому нажатию закреплены на экране (`position: fixed`) по прямоугольнику кнопки (`usePopupPos.js`, `Propis2Hint.jsx`): прокручиваемая строка их не обрезает. Список закрывается, только если кнопка реально сдвинулась (листание строки), а не от доводки scroll-snap или прокрутки страницы фокусом поля.

## Тетрадь вместо комплекта и страницы

Решение от 2026-10-05: страницы без тетради как отдельной сущности нет, «комплект» в интерфейсе называется «тетрадь».

- **Одна сущность.** Всё, что взрослый хранит, это тетрадь (`set`) со страницами (`page`). Новая страница = тетрадь из одной страницы (`id` тетради `st_<id страницы>`, название тетради следует за названием страницы, пока страница одна). Готовые наборы («Методика», «Мои») создают тетрадь. Экран состава тетради удалён: листание, добавление, копия, удаление и порядок страниц в редакторе (полоса страниц), название меняется в библиотеке («Переименовать»). У одностраничной тетради счётчика и стрелок нет.
- **Бумага у тетради одна** — так было до 2026-10-08, см. «Своя бумага у каждой страницы» ниже.
- **Миграция** (`migrateToNotebooks`, при загрузке и после синхронизации): страница, которой нет ни в одной тетради, оборачивается в тетрадь. Идентификатор и отметки времени берутся от страницы, поэтому разные устройства строят одну и ту же тетрадь (last write wins, дублей нет). Удалённая тетрадь (tombstone) заново не создаётся.
- **Удаление тетради** удаляет её страницы (кроме страницы, которая есть и в другой тетради); копия тетради копирует страницы.
- Слова: «Комплекты» -> «Тетради» (панель в редакторе: «Готовые тетради»), «Сохранить как тетрадь», «Из готовой тетради», «Мои тетради». В коде и старых разделах этого файла слово «комплект»/`kit` остаётся как историческое имя (`kits.json`, `kitId`).

## Библиотека: плитки и карточки тетрадей

- Верх экрана: две плитки, «Новая» (создаёт тетрадь из одной страницы) и «Готовые» (поверх плитки лежит прозрачный нативный `select`, тап открывает системный список: «Методика» и «Мои»). Ниже «Мои шаблоны» (сохранённые готовые тетради) и «Мои тетради».
- Карточка тетради: значок, название (тап превращает его в поле, Enter или уход фокуса сохраняет, Escape отменяет, название меняется, не открывая редактор), «N стр. · дата» и строка инструментов в стиле редактора: Открыть, Править, Копия, Удалить (иконка над короткой подписью). Переименование нужно именно здесь: у многостраничной тетради название тетради в редакторе нигде не меняется (в шапке редактора название страницы).

## Готовые тетради лежат в списке (пресетов нет)

Решение от 2026-10-06: пресеты как отдельная сущность убраны (панель «Готовые тетради» в редакторе, «Сохранить как тетрадь», «Мои шаблоны», выпадающий список «Готовый набор»). Копия тетради заменяет «сохранить как шаблон».

- Готовые (шесть комплектов методики и шесть листов) показываются в библиотеке теми же карточками под «Мои тетради», с инструментами Открыть и Править. Тетрадью в аккаунте готовая становится тихо, при первом открытии или правке: создаётся копия с `set.sourceId` (`kit:<id>` или id листа), карточка переезжает в «Мои». Удалил копию, и готовая снова в списке. Заранее все готовые не создаются: это около 150 страниц, которые иначе ушли бы в аккаунт и возвращались бы после удаления.
- Старые сохранённые шаблоны («Мои») превращаются в тетради из одной страницы (`presetsToNotebooks`: id страницы `pg_ps_<id>`, обёртка `migrateToNotebooks`; идемпотентно; удалённая тетрадь заново не создаётся). Сами документы `propis2:preset:*` не трогаются.

## Методика: часть 1 на широкой строке, часть 2 на узкой

Раньше готовые листы методики в «Прописи 2» были шестью одиночными страницами (Лист 1, Лист 2, четыре «Заглавные») и все с жёстко заданной узкой строкой. Исходное разделение (v1, `tools/propis/topic.json`, `engine.js`): часть 1 = `part1` + `page3..page7` на ШИРОКОЙ строке, часть 2 = `part2` + `page8..page18` на УЗКОЙ. Теперь это две готовые тетради (`PROPIS2_METHOD_NOTEBOOKS` в `data.js`, сборка `methodNotebooks` в `model.js`): «Листы методики, часть 1 (широкая строка)» (6 листов) и «Листы методики, часть 2 (узкая строка)» (12 листов, включая `page14` «Заглавные И, Ш, Ц, Щ, У, Ч», которого раньше не было). Страницы закрыты (`locked`), бумага (`ruling`) у тетради одна. Шесть комплектов из PDF-списков (`kits.json`: буквы, слоги, слова, тексты) остаются на узкой строке: так напечатаны исходные тетради.

## Сохранение только по подтверждению (черновик)

Решение от 2026-10-06. Автосохранение при каждом изменении убрано из редактора: простое открытие редактора оставляло в списке «Новая тетрадь» / «Новая страница».

- **Сессия** (`Propis2Home.jsx`): открытие тетради (просмотр, правка, «Новая тетрадь», «Готовые») начинает сессию `{sid, lib, base}`: все правки идут в черновик в памяти (`lib`), в библиотеку ничего не попадает, пока взрослый не подтвердил. `lib !== base` = есть несохранённое. Открыл и вышел без правок: ничего не создаётся, готовая тетрадь остаётся в «Готовых» (копия с `sourceId` появляется только при подтверждении).
- **Подтверждение.** Синяя кнопка-галочка «Сохранить тетрадь» в шапке редактора (серая, пока нет изменений). Новая тетрадь при сохранении спрашивает название (поле, `Propis2SaveDialog`), чтобы список не наполнялся «Новая тетрадь»; тетрадь, которая уже в списке, сохраняется без вопроса. При выходе в библиотеку с несохранённым: «Сохранить» / «Не сохранять» / «Остаться».
- **Что именно записывается:** только эта тетрадь (её `set` и страницы, снятые страницы удаляются: `mergeNotebook` в `storage.js`), остальная библиотека остаётся как есть, поэтому синхронизация, пришедшая во время правки, не затирается.
- **Черновик на устройстве** (`saveDraft/loadDraft/clearDraft`, ключ `propis2:draft`, не синхронизируется): пока есть несохранённое, тетрадь дублируется на устройство, и закрытое или убитое приложение её не теряет. В библиотеке баннер «Не сохранена тетрадь «…»»: «Продолжить» / «Удалить».
- **Пустые тетради** от прежнего автосохранения (ни одной строки с текстом, не готовые): баннер «Пустых тетрадей: N» и кнопка «Удалить пустые» (`isBlankNotebook`).
- Копия, переименование и удаление тетради в библиотеке остаются сразу (это явные действия); удаление теперь переспрашивает.

## Склеенные слова: зазор считается по чернилам

Слово ставится по СТАРТУ своей первой буквы, а у «с, а, о, д…» чернила лежат левее старта, поэтому «любит спать» слипалось в «любитспать» (зазор в 1 единицу против 18–31 у остальных). В `wordEngine.js` для слова рядом с чем-то (`labels.length > 1 || prevToken.isWord`, и не повтор того же знака) чернила нового слова должны отстоять от чернил прежнего не меньше `WIDE_WORD_MIN_GAP` (28 ед. при масштабе 1); иначе слово уходит на следующую наклонную линию. Повторы знаков в строках-образцах (`с с с`, смешанные последовательности `и м`) идут по своему измеренному шагу и не затрагиваются. Проверено на всех 466 парах соседних слов из тетради «Тексты»: минимальный зазор 12–14, медиана 22.

## Узкая строка: сдвиг вниз на 4,5 мм

Измерено на странице A5 (210 мм = 1260 ед., 6 ед./мм): на узкой разлиновке (`narrow17`, 17 строк по 12 мм) первая пунктирная линия стояла на 0 мм, то есть на обрезе страницы, а под последней строкой оставалось 6 мм свободного места. Сетка и запись сдвинуты вниз на `NARROW17_SHIFT_MM = 4,5` (`PrintPageView.jsx`, `n17Shift`): верхняя линия теперь на 4,5 мм, последняя на 208,5 мм, снизу остаётся 1,5 мм. Наклонные линии не двигаются (они идут по всей странице), запись привязывается к ним на новой высоте (привязка и `rowAtSvgY` учитывают сдвиг). Широкая разлиновка и узкие листы v1 не затронуты. Менять величину: одна константа.

## Заглавная У: целая, соединитель как у о, конец в узле сетки

В «Утром» буква «т» ложилась на нижний крюк «У»: у заглавной У крюк заканчивается СЛЕВА от стойки (конец в (139;36)), а движок ставит следующую букву от точки выхода. Конец крюка это штрих самой буквы (не соединитель), его нельзя отрезать. Правила владельца (из истории разработки букв): соединитель после заглавной идёт «с самой нижней точки вправо, какое-то расстояние практически сливаясь с траекторией буквы», и приходит «в ту же точку, что приходит любой другой соединитель», то есть в пересечение серединного пунктира со следующей наклонной (конец привязан к сетке, а не имеет фиксированную длину). У «У» та же стартовая точка, что у «Ч» («У как Ч»), и выход «Ч» (175,2; 36) это и есть этот узел.

Реализация: `joinFrom {stroke}` + `joinLikeLabel` («о») + `joinEndLikeLabel` («Ч») в `glyphOverrides.js` (`withGlyphOverrides` связывает глифы) и `wordEngine.js` (`wideGlyphLocal`): соединитель = кривая соединителя «о», начало в самой нижней точке штриха, масштабирована по X так, чтобы конец пришёл в выход «Ч»; дальше обычный механизм `pendingTail` (как у Г и Р), а конец подгоняется под траекторию следующей буквы, как у остальных. Одна «У» остаётся с крюком, штрих буквы не режется. Только «Прописи 2».

## Экран ученика: управление сверху

Листание (‹ «N / M» ›) и печать (🖨) вынесены из нижней панели в верхнюю строку, слева от ✎ и ✕, в том же стиле круглых тёмных кнопок (`.propis-text-nav--top`, проп `topNav` у `PrintPageView`, передаёт только Прописи 2; v1 остаётся с нижней панелью). Полный текст «Страница N из M» остался в `title`.

## Окно показа написания

- Скорость пера равномерная (`evenSpeed` в `useLoopingStrokes`, включается только в окне показа, у v1 прежний ease-in-out): все штрихи с одной скоростью, замедление только в конце последнего штриха слова (последние 12% пути, до 45% скорости).
- Перо снова крупное (`tipSize="large"`, ~20 мм настоящей ручки) и в окне показа тоже.
- Окно на весь экран: в одну верхнюю строку названия фрагмента и кнопки ↻, 🐢 (медленно), ✕. Окно-вырезка (`focusCrop`) охватывает только фрагмент плюс запас под перо; SVG растягивается по аспекту вырезки как можно больше (`container-type: size` + `--crop-ratio`), то есть слово ограничено шириной, короткая буква — шириной/высотой экрана.

## Поле ввода конструктора

- Пока поле не в фокусе, оно сложено до одной-двух строк; при наборе растёт по тексту (до максимума). Тап вне поля (строка на странице, инструмент) снимает фокус и сворачивает его (`Propis2Field`).
- Элементы в тексте поля показываются коротким кодом в фигурных скобках: `{э1}`, `{э2}`… (номер по месту элемента в списке колоды; `bracesIn`/`bracesOut` в `fieldText.js`). Строки хранят настоящий id (`5`, `01_pryamaya_liniya`), движок его и читает, коды только слой показа, поэтому переименовывать данные колоды и миграции страниц не понадобилось. Код зависит от порядка элементов в колоде: если порядок изменится или элемент вставят в середину, номера в поле сдвинутся, но сохранённые страницы не пострадают. Рукой набранный `{id}` тоже понимается. В списке под плиткой стоит тот же `{код}`.
- Иконка списка элементов нарисована как плитка из списка: клетка с линейками и штрихом.

## Исправления по тексту «Сегодня мы с мамой…» (2026-10-06)

- Слово, повторившееся в строке сплошного текста («я … я», «и и»), раньше рисовалось второй раз пунктиром как копия образца: в движке «копией» считается любой повтор токена в строке. Теперь в строках `#1` (написать один раз, то есть связный текст) копий нет (`wordEngine.js`, `dashed = !once[rowIndex] && …`).
- ь и ъ: выходной подъём отделён как добавочное соединение (`tailSplit` в `glyphOverrides.js`, как у о ю ф в): последняя ь в слове кончается без хвоста.
- Копирование/вставка в поле: `<body>` отключает `-webkit-touch-callout`, оно наследуется текстовым полем; для поля конструктора возвращено `default`.
- Вход в ъ: соединение от предыдущей буквы идёт к началу ъ, к его флажку (`joinAtStart` в `glyphOverrides.js`), а не к стойке.
- Выход из ъ: флажок сместил начало ъ левее, чем у ь, и выход не доставал до следующей буквы дальше допустимой подвижки 6 ед. У ъ допуск больше (`exitNudge: 24` в `glyphOverrides.js`, читает `wordEngine.js`).

- Вход в ь: прямая линия от предыдущей буквы к самому верху стойки, как к э, без изгиба на конце (`joinAtStart` и `joinStraight` в `glyphOverrides.js`; без `joinStraight` конец загибался по направлению стойки).
- ь последняя в слове: хвоста нет совсем. Раньше отрезалась только последняя кубика подъёма, и оставался укороченный хвост; теперь соединением считается весь подъём от низа петли (`tailSplitCount: 5` у ь, поддержан в `wordEngine.js`). Перед буквой ь пишется как раньше.

## Цифры и знаки (захваты 2026-10-06)

- Захваты 0–9 и + − = < > лежат в `tools/propis/captures/digits_signs_raw_2026-10-06.json`; в данные темы они переведены скриптом `python3 tools/propis2/build_digit_glyphs.py` в `src/topics/renderers/propis2/digitGlyphs.json`. Скрипт: режет штрих по углам (перекладины 4 и 7, флажок 5 не скругляются), каждый кусок сглаживает по длине дуги (дрожание руки уходит, концы на месте) и пересчитывает в кубические кривые, а прямые куски (знаки, стойки 1 и 4, перекладина 7) делает точными линиями. Размер: цифра высотой с ЗАГЛАВНУЮ букву (104 ед., от −42 до 62). Растёт ТОЛЬКО высота (общий множитель ×2,167), а не ширина: движок и так растягивает любой глиф по горизонтали (stretch 1,806), и первая версия, где я увеличил обе оси, дала цифры почти вдвое шире нужного (137×104). Наклон штрихов сохранён сдвигом вдоль сетки (SLANT 0,466): ширина сечения цифры остаётся такой, как нарисовала рука. Знаки сохраняют место относительно цифр, база захвата 88 → 62 (как у запятой и точки из v1). Из-за высоты с заглавную на широкой строке цифры, как и заглавные, не допускаются (предупреждение «на широкой строке нельзя»); на узкой разрешены. Подмешиваются в `withGlyphOverrides`, то есть только в «Прописи 2»; `wide.json` и v1 не тронуты.
- Названия глифов с «№»: `№5`, `№+`. Причина: в `wide.json` уже есть ЭЛЕМЕНТЫ 5 6 7 8, а «+» в движке означает цепочку букв («п+и»). Руками это набирать не надо.
- В поле конструктора набираются обычные символы с клавиатуры: слово из одних цифр и знаков (`15`, `2+3=5`, одинокий `-`, `<`, `7`) в строках превращается в `№1№5` и т. д. и показывается обратно (`fieldText.js`, `digitsOut/digitsIn`). Одинокие 5 6 7 8 цифрой пишутся тоже, а элементы с этими именами видны в поле в скобках: `{э1}`. Слова с буквами не трогаются («п+и», «кое-что»).
- Старые страницы с одиноким `5` в данных остаются элементами; цифры в них появятся, когда строку отредактируют в поле.
- Цифры не соединяются с соседями, между словами промежуток по ширине чернил (как у слов), в числе идут подряд.
- Привязка к косой сетке (2026-10-07). Движок ставит на наклонную только СТАРТ первого штриха; у букв палочки сами лежат на линиях, потому что захвачены по сетке, а у цифр рука увела палочки 1, 4, 7 на 0,2–0,3 клетки от линии (точка на линии, а цифра рядом: «привязки не видно»). Скрипт (`on_grid`) теперь сдвигает так, чтобы старт каждого штриха и каждая палочка были на целое число клеток от первой точки (клетка в единицах глифа = 30 / (1,806 · 48/52) ≈ 18): у 1 подгибается подводящий флажок, у 4 сдвигается палочка, у 7 изогнутая и более крутая палочка заменена прямой по наклону сетки, перекладина 7 центрируется на палочке (её точка — единственная не на линии: перекладина в клетку длиной не может и пересекать посередине, и начинаться на линии). Цифры ВНУТРИ числа («25») раньше ставились просто после чернил предыдущей, мимо сетки; теперь движок (`wordEngine.js`, только `kind: "digit"`) ставит их на первую наклонную не левее этого места. Проверка — тест «stand on the slant grid» в `model.test.js`.
- Минус в захвате стоял на нижней пунктирной (y=33, «7_4»); скрипт поднимает его вдоль наклона на высоту перекладины плюса (y=10).
- «<» и «>» — две прямые через вершину (у «>» рука скруглила верхнее плечо). Перекладина «+» длиной ровно 2 клетки и центрирована на вертикали: пересечение строго посередине, а её начало остаётся на наклонной (`straight_signs`).
- Минус той же длины, что перекладина плюса (2 клетки сетки).
- **Клетка (2026-10-07).** Бумага «Клетка» больше не подкладка под строки прописей, у неё своя разметка: строка = две клетки (10 мм), в одной пишут, вторая пустая («строки через одну клетку»), низ строки на линии сетки, первая строка в 10 мм от верха; A5 — 20 строк, A4 — 29 (`PrintPageView.jsx`: `SQUARE_*`, `squareRowY`, `perPageOf(..., square)`, `rowAtSvgY(..., square)`; модель: `rowsPerPage`, `pageRuling` — клетка раскладывается в размере узкой строки). Цифры и знаки ставит движок «по клеткам» (`snapX.cell`, `cellGlyphLocal` в `wordEngine.js`): цифра высотой в клетку, НАКЛОН КАК В ПРОПИСЯХ (65° от горизонтали; первая попытка с уменьшенным наклоном ~11° владелец отверг), цифра КАСАЕТСЯ ПРАВОЙ стороны клетки (как школьная «1» из правого верхнего угла). Ширина задаётся ПО БУМАГЕ, а не поперёк наклона (`CELL_DIGIT_SPAN`: 0,78 клетки, 1 — 0,55, 4 — 0,7, 7 — 0,6: верх 7 владелец попросил укоротить на ~20%): первая версия сужала всех одинаково поперёк наклона, и 7 (это почти одна верхняя перекладина, палочка идёт вдоль наклона) вышла огрызком, а все цифры — узковатыми. Знаки — общий масштаб (`CELL_SIGN_BAR` 0,55 клетки: перекладина +, минус и черты = одной длины; растягивать каждый знак до ширины клетки делало минус длиннее плюса). Знак между двумя цифрами ставится ПОСЕРЕДИНЕ между их чернилами (`cellRun` в `layoutWideLinesIntoRows`): цифры прижаты вправо, поэтому середина клетки знака — не середина промежутка. Число — в соседних клетках, следующее слово/число/знак через пробел — через одну клетку (как в школе), в повторе строки тоже. Решения владельца: наклон «как в школьной тетради» (вариант б), числа подряд, строки через одну клетку. Буквы на клетке — буквы прописей БЕЗ ИЗМЕНЕНИЙ, только меньше (решение владельца после двух отвергнутых попыток: сжатие верха/хвостов при строчной в клетку — «полная фигня», привязка слов к линиям клетки — лишняя): строчная 3/4 клетки, значит заглавная 1,5 клетки (школьная норма для клетки) и хвосты 3/4 клетки (`SQUARE_LETTER_SCALE` = 0,75·30/48, передаётся движку через `snapX.cell.scale`, поэтому перенос считает так же). Цена: строки через одну клетку, хвост (3/4) строки сверху и заглавная (1,5) строки снизу в сумме 2,25 клетки на 2 — если р/у/д стоит прямо над заглавной, они заходят друг на друга на четверть клетки. Альтернатива (строчная в клетку, заглавная 2) требует строк через две клетки. Буквы на клетке ставятся на НЕВИДИМУЮ косую сетку своей клетки (сетка прописей, уменьшенная вместе с буквами, `squareSnapFor`): соединения прописей выверены по этой сетке; без неё каждая буква вставала, куда вывело соединение, и все соединения выходили длиннее (сильнее всего от нижней точки: э ж о — «у Э, Ж слишком длинные исходящие штрихи»). Теперь слово на клетке = слово прописей × масштаб (тест «copybook's word»). Слова к вертикальным линиям клетки НЕ привязаны и идут с обычным промежутком, как в прописях (привязку «слово с линии клетки, через клетку» владелец отверг). Норма (единый орфографический режим начальной школы): строчные в 1–2 классе в клетку, в 3–4 — 2/3 клетки, заглавные во всех классах 1,5 клетки; для хвостов вниз нормы не нашлось. Наклон букв 65°, как в прописях. Буквы по ширине — пропорции прописей (строчная «и» ~1,4 клетки шириной).
- Не сделано: плитки цифр в списке элементов (не нужны, клавиатура набирает их сама); × и ÷ (захватов нет).

## Отмена и возврат в редакторе (2026-10-07)

Две круглые кнопки-стрелки («Отменить» / «Вернуть», без подписей, как в Edits) столбиком справа поверх холста (`.p2-history`: отдельный слой в той же области сетки, что и лист, — не прокручивается вместе со страницей; на планшете стоят в полосе у листа, на телефоне поверх правого края страницы). Первая версия в шапке — «функционал не очевиден». Все изменения тетради идут через одну функцию `edit(next, {typing})` в `Propis2Home.jsx`, состояние неизменяемое, поэтому история — это стек прежних состояний тетради `{lib, pageId}` в сессии (`session.past` / `session.future`, до 200 шагов). Набор текста (поле, название) склеивается в один шаг, пока клавиши идут чаще раза в секунду (`UNDO_TYPING_MS`); вставка элемента плиткой, бумага, точки, страницы — отдельные шаги. Отмена возвращает на страницу, где было изменение (отмена «Добавить страницу» — обратно на исходную). Новая правка после отмены сбрасывает «Вернуть». Отмена до сохранённого состояния — тетрадь снова «без изменений» (кнопка сохранения гаснет). История живёт, пока тетрадь открыта. Старая всплывашка «Страница очищена / отменить» убрана: очистка отменяется общей стрелкой. Удаление последней страницы (= всей тетради) не отменяется (уходит в библиотеку сразу, как раньше).

## Скорость набора (2026-10-07)

Жалоба: задержка между клавишей и появлением текста растёт с объёмом страницы. Профиль (CPU profile через CDP, dev-сборка, планшет 820×1180): на каждую клавишу ВСЯ страница переносилась и раскладывалась по нескольку раз — `wrapPassage` (жадный перенос: каждый растущий префикс строки раскладывается движком целиком, O(слов²) на строку) звали `lineOwners` и `analyzePage` синхронно в обработчике клавиши и `pageToLines` в предпросмотре; потом весь лист раскладывался заново (`layoutWideLinesIntoRows`) и React пересоздавал все линии всех строк. Было: 2 строки ~140 мс на клавишу, 10 строк ~500 мс.
Сделано:
- `snapXFor` отдаёт ОДНУ И ТУ ЖЕ функцию для одинаковых параметров страницы (`cacheable`), по ней кэшируются результаты;
- `layoutWideLinesIntoRows` кэширует готовые строки (строки раскладываются независимо: строка зависит только от своего текста, номера, сетки и глифов) — меняется одна строка, раскладывается одна;
- `lineWidth` и `wrapPassage` кэшируются (при наборе в конце все прежние префиксы — из кэша);
- в редакторе проверки строк и карта строк листа считаются по отложенной копии страницы (`useDeferredValue`, как предпросмотр) — буква в поле появляется сразу;
- чернила строки рисует `RowInk` (`memo`): неизменённая строка приходит из кэша тем же объектом, React её пропускает.
Стало (dev): ~80–100 мс на клавишу и на 2, и на 10, и на 16 строках — от объёма больше не зависит. Остаток — раскладка самой изменяемой строки (подбор числа копий образца) и отладочный режим React (в боевой сборке его нет). Тест «layout cache»: раскладка из кэша совпадает с раскладкой с нуля на всех сетках.

## Окно показа (перо пишет фрагмент), переделка 2026-10-07

Было: строка ниже центра (запас под перо только сверху), окно начиналось от начала строки (буква прижата влево, мелкая), перо в 2,5 раза выше заглавной, название мелким текстом в углу, кнопки — серые кружки с эмодзи без подписей.

Где перо отрывается от бумаги, оно перелетает к началу следующего штриха по воздуху (полупрозрачное, в 2,5 раза быстрее письма, без следа). Замедление — только в конце последнего штриха (конец слова или буквы). Анимация на листе и в других темах — прежняя (паузы остаются там, где `evenSpeed` не включён).

- Область нажатия на строке листа (`.propis-text-word-hit`, открывает показ) — по чернилам самой строки ± 10 (`hitBox`), а не по старой разметке v1 вокруг NATIVE_L3: на узкой строке она сидела ниже букв («таб смещён вниз»). И лежит ПОВЕРХ чернил (прозрачная): иначе линии букв перехватывали нажатие.

## Пиктограммы конструктора (2026-10-07)

Пиктограммы бумаги и строк — трёхцветные: то, что ПИШЕТСЯ, — тёмным (currentColor), разлиновка — серым, направляющие пунктиры, стартовые точки и поля — красным, как на листе. Формы не нарисованы от руки, а взяты из данных темы скриптом `tools/propis2/build_icon_shapes.py` → `src/features/propis2/iconShapes.json`: письменная «а» (строки узкая/широкая, «писать после»), элемент «крючок» (образец/копии/точки — вместо прежних «двух горбов», похожих на «m»), крючки влево и вправо на плитке «элементы». Формат — просто надпись «А4» / «А5». Поля: лист тёмным, строки серым, поле красным («без полей» — серая черта: красный только для линии поля). «Очистить страницу» — ластик (корзина — «удалить»). Кнопки действий (добавить, копия, удалить, стрелки, повтор, отменить/вернуть, сохранить, показать, замок, править, предупреждение) — одноцветные, как в любом редакторе: так их не спутать с настройками листа. «Текст» — прежний знак абзаца (вариант из мелких письменных «и» на размере кнопки читался как частокол). Выбранный вариант в выпадающем выборе — светлый с бирюзовой обводкой: на сплошном бирюзовом серые и красные детали пропадали.
- Кнопка «Повтор» (пометка строки «для повторения») убрана с панели строки (2026-10-07): страницы из отмеченных строк в интерфейсе давно нет, пометка ни на что не влияла. `pageFromMarked` и поле `marked` в данных остались (тесты), вернуть — одна кнопка.

## Своя бумага у каждой страницы (2026-10-08)

Владелец: тетрадь на отработку цифр — это страницы в клетку (сами цифры) и страницы прописей (цифры в тексте), значит бумага в одной тетради бывает разной. Ограничение «бумага общая на тетрадь» было моим упрощением, не ограничением данных: бумага всегда лежала на каждой странице.

- **Редактор.** Тип бумаги, строки, наклон, поля, пунктир и «писать после» меняются только у открытой страницы (`PAGE_PAPER_KEYS`). Формат А4/А5 остаётся общим на тетрадь (`NOTEBOOK_KEYS`, `notebookLayout`): страницы печатаются одним буклетом. Новая страница («Добавить») берёт бумагу страницы, после которой встаёт. ~~Кнопка «Всем»~~ — убрана 2026-10-15, см. ниже «Страница или вся тетрадь».
- **Показ ученику.** Тетрадь режется на участки — подряд идущие страницы с одной бумагой (`notebookSections`, ключ `paperKey`: формат, тип, строка, пунктир, поля; «писать после» не бумага для движка). Размечается только открытый участок, каждый на своей бумаге (`setToLines(set, byId, map, ids)`, каждая страница добита до целых экранных страниц по своей разлиновке). Тетрадь на одной бумаге — один участок, ровно как раньше. `PrintPageView` получил `pageBase` / `pageTotal` / `onEdge` / `startAt` / `onPageCount`: счётчик «N / M», `onPageIndexChange` и сторона поля (чередуется по номеру страницы) считаются по всей тетради; ‹ на первой странице участка и › на последней переходят на соседний участок. Число экранных страниц участка сначала оценивается по числу строк, потом уточняется тем, что движок реально разложил (`onPageCount`). Окно показа написания и тап по фрагменту берут бумагу участка.
- **Показ из редактора** открывается на редактируемой странице, а не на первой.
- **Миграция** (`pagesTakeNotebookRuling` в `storage.js`, при загрузке, после синхронизации и при восстановлении черновика): раньше строка тетради (`set.ruling`) перекрывала строку страниц при показе. Тетрадь без отметки `pagePaper` один раз переписывает свою строку на страницы (как она и выглядела) и получает отметку; новые тетради создаются с `pagePaper: true`. Детерминированно, `updatedAt` не трогается (устройства получают одинаковые документы). `set.ruling` больше ни на что не влияет.
- **Печать тетради с разной бумагой (2026-10-08).** Экран тетради строит задание на каждый участок (`runTasks` в `Propis2Home.jsx`; открытый участок показывается тем же заданием) и передаёт все в `PrintPageView` (`printParts`). Разметка задания вынесена в чистую функцию `layoutTaskPages(task)` (ей же пользуется сам просмотрщик); печать размечает все участки и раскладывает их страницы ОДНИМ сквозным списком: номер страницы и сторона поля по всей тетради, две страницы А5 на листе А4 и через границу участков (у пустой половины последнего листа — бумага соседней страницы). Тетрадь на одной бумаге печатается как раньше (`printParts` не передаётся). Проверено печатью в PDF готовой тетради «Прописи — цифры»: 12 листов, 1–20 в клетку, 21–24 на прописях.


## Готовая тетрадь «Прописи — цифры» (2026-10-08)

Седьмая готовая тетрадь (`kits.json`, id `digits`, 24 страницы), собирается `tools/propis2/build_kits.py` из того же плана страниц, что печатная тетрадь цифр (`scripts/digits_workbook/digits_pages.py`: порядок цифр, списки чисел и примеров, тексты). - Страницы 21–23 (цифры в тексте): под КАЖДОЙ фразой пустая строка (8 фраз на страницу, остальное из списков печатной тетради не вошло). Первая версия ставила верхние фразы подряд, как в печатной, где они были пунктиром для обводки; в конструкторе пунктирной фразы нет, и писать было негде (владелец, 2026-10-08). Стр. 24 «Списываем» — 7 образцов сверху, 10 пустых строк ниже (списывание на расстоянии).
- Упрощено против печатной: две крупные строки (в две клетки) — обычные; строки с пропусками («1 _ 3 _ 5») — ряд-образец и пустая строка; обводка целых фраз пунктиром — образцы.
- Цифры в строках — метки глифов (`№5`), в том числе перед запятой и точкой («Оле №3.»): `num()` в сборщике.
- Исправлено в движке при проверке (касается и ручного ввода): (1) на странице, где сетка привязки не нарисована (редкая косая 20 мм; `snapX.hidden`, ставит `makeSnapX` в `PrintPageView.jsx`, обёртки сетки в `wordEngine.js` и `model.js lineWidth` её переносят), вторая и следующие цифры числа ставятся с ровным зазором `WIDE_DIGIT_GAP`, а не на следующую невидимую наклонную («2 0» → «20»); на частой сетке цифры по-прежнему на нарисованных линиях. (2) После слова или числа, кончающегося знаком препинания, следующее слово или число стоит не ближе 1,8 × `WIDE_WORD_MIN_GAP` от чернил знака (обычный пробел ≈ 2×): «кот,2» → «кот, 2», «утра,в» → «утра, в». Тексты с запятыми могут переноситься чуть иначе, чем раньше.
- (3) Пробел после широкого слова (одиночная заглавная: «В классе», «В году») был вдвое шире обычного: следующее слово ставится шагом клеток от НАЧАЛА предыдущего. Теперь слово, вставшее дальше, подтягивается назад по наклонным, пока зазор не меньше обычного пробела `WIDE_WORD_SPACE` (44 при масштабе 1; «В классе» 54 → 24 на узкой строке). Остальные пробелы не меняются; повторы образца, нарочно набранные пробелы (`pendingGap`) и строки из одиночных букв («Я и») не трогаются.

## Печать: обложка и номера страниц (2026-10-08)

Владелец: при печати спрашивать про обложку (выбор дизайна) и ставить номера страниц. Решения: все три обложки, оборот пустой, номера по умолчанию включены.

## Обложка — универсальный шаблон и задник (2026-10-08)

**Решения владельца (2026-10-08):**
- Обложка — часть тетради: пользователь выбирает одну из готовых обложек для своей тетради, а в напечатанной тетради (PDF) она появляется только при печати. Хранится в самой тетради (`set.cover`), синхронизируется и копируется вместе с ней. Главное в окне — плитки готовых обложек; тонкая настройка свёрнута под «Настроить обложку».
- Задник печатается на обороте лицевой стороны. Тетрадь А5: задник — левая половина того же листа А4, лицо — правая; следом пустой лист (оборот). Тетрадь А4: лицо — первый лист, задник — второй (вместо пустого).
- Набор украшений и задников — как в ТЗ.
- Цвета — только тёмные: бирюзовый `#2f6f65` и серый `#4b5563` (читаются при ч/б печати).

**Где что лежит** (`src/features/propis2/cover/`):
- `coverConfig.js` — схема `CoverConfig` (`enabled`, `title {text, style: print|cursive, kicker}`, `decor`, `fields`, `accent`, `logo`, `back {kind, paper}`), умолчания (задник по бумаге первой страницы: клетка → «Цифры», иначе «Алфавит»), пресеты (`applyPreset` меняет только лицо; название, цвет, логотип и задник остаются), `presetOf` (какой пресет — или своя обложка), миграция старого `cover: "school"|"propis"|"sample"|"none"` (`migrateLegacy`; старый выбор из `localStorage` `propis2:print` читается, пока у тетради нет своей обложки), валидация `normalizeCover`. ## Строчная «г»: начало на 1 мм выше (2026-10-12)

Соединение «ог» уходило далеко вправо по пунктиру, прежде чем подняться в «г». Начало строчной «г» поднято по её же
начальной прямой на 13 ед. захвата (= 1 мм на узкой строке, 2 мм на широкой): `startLift` в `glyphOverrides.js`. Соединение
от предыдущей буквы теперь поднимается прямо к началу «г» (ветка `riseToStart` в `wordEngine.js`), «г» стоит ближе. В
`wide.json` «г» — псевдоним элемента «г1»; перекрытие по псевдониму делает строчную отдельным глифом, элемент «г1» не меняется.
Проверено картинками: ог, ога, аг, иг, ег, рог, гора, огород, снег, игра, гг. Меньший подъём (6,5 ед.) рвал соединение.

**Грабли (исправлено в тот же день):** движок ставит букву на сетку по точке начала, и поднятое начало сдвинуло всю «г» влево
на ~0,5 мм — выход «г» ушёл с сетки, перед следующей буквой появился зазор ~3 ед. (почти у всех пар «г+буква»). Теперь
`liftStart` кладёт в глиф `anchorY` (высота исходного начала), а `wideGlyphLocalCompute` берёт `start` для привязки на
продолжении начальной прямой на этой высоте: «г» стоит там же, где до правки, рисуется с поднятым началом. Проверка —
зазоры между штрихами по всем «г+буква» × разлиновки × сетки × поля совпали с исходными.

**Пересмотрено (2026-10-12, по просьбе пользователя):** образец «г» — как в «аг»/«игра»: две отдельно написанные буквы должны
склеиваться сами, без продления хвоста предыдущей. Естественный выход а и у л м н д я кончается на 2,2 ед. движка выше пунктира
на следующей наклонной — туда и поставлено начало «г» (`startLift: 2.2 * 52 / 48` ед. захвата, на её начальной прямой; привязка
к сетке по-прежнему по `anchorY`). Подъём на 1 мм (13) заставлял движок дотягивать каждый хвост вверх. `joinAtStart` — чтобы
чуть более низкий выход «ш» тоже приходил в начало «г». Зазоры по всем парам «г+буква»/«буква+г» совпадают с исходной «г».
Соединение «о» лежит более полого, чем выход остальных букв, — с «г» это особенно заметно; отдельная задача.

## Пары «Аа» в готовых тетрадях — ровные промежутки, как на заднике обложки (2026-10-21)

Владелец: в «Прописях — часть 1/2» неправильные расстояния между буквами пары — тот же баг, что уже исправлен на заднике обложки.
Причина та же: строка ставит следующий символ целым числом клеток косой сетки от СТАРТА предыдущего, а пары не соединяются, поэтому

- Строка конструктора получила поле `even` (`model.js rowToLine` -> `#v`). Все пары готовых тетрадей (`letters-1/2`, `alphabet-1/2`;

## Буквы на частой косой — на линиях и в тетради из разной бумаги (2026-10-24)

Владелец: на частой косой (широкая и узкая строка) буквы должны стоять на наклонных линиях — они так и рисовались. Проверено
измерением отрисовки (доля штриха на линии, отклонение начала буквы от ближайшей линии):
- на одной бумаге (готовые тетради серии, набор образцом и связным текстом, широкая и узкая строка) буквы на линиях: начало буквы

- **ошибка**: в тетради из РАЗНОЙ бумаги участок, начавшийся с нечётной страницы (например, стр. 1 в клетку, стр. 2 — широкая
  строка с частой косой), рисуется как нечётная страница (сетка сдвинута на ширину листа — 148,5 мм, это 29,7 клетки по 5 мм; поле с
  другой стороны), а буквы привязывались как на чётной: на 1,5 мм мимо линий (на линии 2 % штриха). Теперь участок знает свою первую
  страницу (`buildPageTask({ firstPage })` = `sec.start` в `Propis2Home.jsx`), `snapXFor({ pageShift })` считает строки участка со сдвигом
  на страницу. После: отклонение 0, на линиях 40–57 %. Тест `snapShift.test.js`.
- Не тронуто: перенос связного текста в редакторе (`model.js pageSnap`) по-прежнему считает страницу чётной — ширина слова от фазы
  сетки может отличаться на клетку; если где-то строка вдруг вылезет за край, искать здесь.
- **В PDF «Тетрадью» — тот же сдвиг, другая причина** (владелец: «на экране идеально, в PDF смещение»). Измерено по векторам PDF

## Настройки строки — «На следующие строки» (2026-10-24)

Как «На всю тетрадь» у бумаги, но для полосы строки. «Образец» и «Точки» меняют выбранную строку; если ниже есть строки,

## Первая буква строки на одном месте; «Без наклонных» (2026-10-25)

Владелец: на редкой косой и без косой «чтобы ... слева начиналось на одной позиции»; на частой — пусть буквы стоят на её линиях,

  строк гуляло от строки к строке. Широкая строка, клетка, линейка и болгарская бумага уже были ровными — не менялись.
- **Частая косая не менялась:** буквы стоят на её нарисованных линиях (`drawnGridSnapX`), начало строк разное — так задумано.
- Старая тема `propis` (без `simpleGrid`) сохраняет прежнюю сетку — её тетради не сдвигаются.
- **«Без наклонных»** — третий вариант «Наклона» (`GRIDS` id `"none"`, `pageNoSlant`): только горизонтальные линии строк, буквы — по той же

- **Иконки «Наклона»** (2026-10-25): только наклонные линии; «Без наклонных» — одна наклонная, перечёркнутая (без красного пунктира).

Соединение «е» с т р п м л шло рядом со штрихом следующей буквы. Владелец отверг два варианта: «заострить» (`steepExit`: низ стал острым углом и не доставал до строки) и прямую линию от самой нижней точки. Принято: `softHook: 0.35` у «е» в `glyphOverrides.js` (`softenHook`): последняя кубика (завиток внизу) чуть разогнута, чернила по-прежнему доходят до нижней линии, конец хвоста на середине строки без изменений. Изменение лёгкое, расстояние до следующей буквы оно не меняет; если «слишком близко» останется, следующий шаг — отодвигать следующую букву.

## Т: соединение кончается на первой наклонной, дальше ручка идёт строго по ней (2026-10-27)

Жалоба владельца была на анимацию (статика выглядела правильно): после касания перо пересекало наклонную и шло к верхней точке под другим углом. Причина, видимая только с настоящей привязкой к косой сетке (`snapXFor`, в замерах без неё всё совпадало): в высоте, где приходит соединение, подъём арки «т» (он отходит от нижней части первой линии) проходит на ~1,6 ед. правее первой линии, движок выбирал это ближайшее пересечение, хвост кончался на подъёме, а переход «касание → начало буквы» (`M contact L start` в `trajectory`) шёл под 73° вместо 65° линии. Теперь у «т» свойство `touchFirstLine` (`glyphOverrides.js`): соединение ищет касание только на первой кривой (`firstCurveD` в `wordEngine.js`) и правило «тянуть соединение к самому началу» для неё выключено. Замер на сетке: касание лежит ровно на линии (0,00), угол перехода 65° = угол линии, для ет ат ит ут ст нт лт ьт от. Статика меняется на ~1,6 ед. (хвост чуть короче). Не проверено: «п» и «р» (у них тот же устройство, владелец просил только «т»).

Проверка всех пар (2026-10-27, на настоящей сетке `snapXFor`, 32 буквы × 32, переход «касание → начало буквы»): после обычной буквы переход шёл не по первой наклонной у «т» (1,6 ед. правее, угол +8°), «п» и «р» (1,1 ед., 5,9°) и чуть у «к» (0,5 ед., 2,5°); у «н», «ш», «щ», «й», «ю», «и», «ц» — по линии. Теперь `touchFirstLine` стоит у т п р к, у всех четырёх касание на линии (отклонение ≤0,15) и угол 0°. Заглавные не проверялись.

## Пары `#v` на плотной бумаге (тетрадь 10, «Тетрадью»): строчные не по линиям

Строки-пары «К к», «У у» и т. п. идут с флагом `#v` («ровный просвет»): каждая следующая буква ставилась
на `inkMaxX предыдущей + EVEN_GAP`, то есть мимо решётки. На обычной бумаге решётка невидимая, и это
незаметно, а на плотной (`drawnGridSnapX`, линии нарисованы на листе) палочки строчных оказывались
между линиями (до 6 ед. при шаге 15). Это было и в приложении, и в PDF, потому что разметка одна.

Фикс: у `drawnGridSnapX` флаг `drawn`, он пробрасывается через обёртки `snapXFor`/`makeSnapX` и
построчные обёртки в `wordEngine.js`. В `#v`-ветке при `snapX.drawn` старт подтягивается к ближайшей
линии, а если так букву прижмёт ближе 0.6·EVEN_GAP, берётся следующая линия справа (`nextLineRight`).
Невидимая решётка и не-плотные наборы не затронуты. После правки отклонение палочек от линий в
парах всех 16 страниц тетради 10 ≤ 1.3 ед.

## «ъ»: стойка строго по наклонной (2026-10-28)

Владелец: сначала просто нарисовать «ъ» так, чтобы вертикальный штрих шёл строго по наклонной линии, не меняя размеров буквы.
(Школьное «ъ» на две клетки — отдельная задача, не сделана: первая попытка растянуть флажок и сместить стойку была отклонена.)
- Причина: движок ставит на линию начало буквы (кончик флажка), а стойка «ъ» стоит в 9.3 единицах глифа (≈ 0.56 клетки, 16.8 единицы
  строки) правее линии, проходящей через начало. Поэтому стойка всегда лежала между двумя линиями.
- `glyphOverrides.js`: у «ъ» `stemOnLine: true` -> `markStem` кладёт в глиф `stemAnchor` (верх стойки: начало первого длинного
  прямого отрезка штриха). `wordEngine.js` (`wideGlyphLocalCompute`): `local.stemDx` = насколько правее начала лежит наклонная линия через стойку
  на высоте начала (с растяжкой 1,806 и масштабом узкой строки). При расстановке `snapStart(x) = snapX(x + stemDx) − stemDx`: на линию встаёт та точка,
  что на `stemDx` правее начала, то есть стойка. Форма и размер буквы не меняются, начало флажка теперь может стоять между линиями (это кончик, не стойка).
- Урок про единицы: клетка широкой строки = 30 единиц СТРОКИ, а в единицах глифа 30/1.806 = 16.6 (глиф растянут по x, `stretch`).
  Первая попытка считала смещение в единицах строки и промахнулась в 1.8 раза.
- Тест `glyphOverrides.test.js`.
- **Флажок ниже, «ъ» ближе (2026-10-28, тоже по просьбе владельца).** Флажок рисуется с более низкой точки, примерно с четверти высоты
  строки от верхней линии (раньше начало было почти под самой линией, 11 %). `startDrop: 7` (`dropStart`, обратное `startLift`): начальная прямая
  флажка продолжена назад и вниз на 7 единиц, направление то же, остальной путь побайтно прежний. Соединение от предыдущей буквы идёт теперь выше/круче,
  потому что кончается ниже; чтобы «ъ» встал на клетку ближе, а не остался на той же линии (привязка по ближайшей линии съедала сдвиг в ~3 единицы),
  `snapNotRight: 0.2`: после буквы, которая соединяется с «ъ», стойка встаёт на линию не ближайшую, а не правее точки (запас 0.2 клетки вправо),
  так соединение не положе угла соединения. В начале строки «ъ» стоит как стоял (там нет предыдущей буквы).
- **Излом на входе во флажок (2026-10-28).** Соединение от «с» подходило к флажку под ≈53°, а начальный кусочек флажка идёт под 62.5° — излом. Сначала
  пробовали повернуть сам флажок под угол соединения (`startSlope`) — владелец отклонил: флажок оставить как был, а соединение сделать вогнутее. Причина в
  `retargetTailEndD` (wordEngine.js): хвост предыдущей буквы, заходя в начало следующей, подходил под полусмесью направления хорды и направления открытия
  буквы (`ua = 0.5·хорда + 0.5·открытие`). `joinArrive` (параметр глифа, по умолчанию 0.5): у «ъ» `joinArrive: 1`, хвост заходит строго по направлению флажка
  своей полной кривой. Проверено по раскладке: у с о н и л м т а е в ю ф б угол входа = углу флажка = 62.5° (тест).

### «ъ»: один оборот пуза, два варианта (2026-10-28)

Владелец: в «ъ» овал (пузо) проходил нижнюю точку дважды (второй проход шёл чуть мимо первого, внизу линия раздваивалась, до 4 единиц); нужно, чтобы
