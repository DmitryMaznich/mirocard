# Разработка Мирокарда с телефона в GitHub Codespaces

Откройте ветку с этой конфигурацией на GitHub → **Code → Codespaces → Create codespace**.
Начните с машины с двумя ядрами. Установка зависимостей происходит один раз при создании;
приложение запускается автоматически при каждом старте Codespace.

В панели **Ports** откройте адрес порта **8080**. Оставьте доступ **Private**:
приложение и тестовая почта доступны после входа в ваш GitHub. Не публикуйте порт:
режим разработки содержит отладочные инструменты. Бэкенд 3012 и почту 4311 открывать не нужно.

Среда использует экспериментальный bundled dev mode Vite: код объединяется для
уменьшения количества запросов через туннель GitHub, автоматическое обновление
сохраняется. Если возникнет несовместимость, обычный режим доступен командой
`MIROCARD_DEV_UNBUNDLED=1 node .devcontainer/start.mjs`.
Service worker устанавливается только в production. После обновления старого
Codespace один раз откройте **`/__dev/reset`** на тестовом сайте, чтобы снять
его старую регистрацию; аккаунт и IndexedDB сохраняются. В DevTools не включайте
**Network → Disable cache** и **Application → Service Workers → Update on reload**
для повседневной разработки: они искажают обычную загрузку.

## Ежедневная работа

1. Возобновите Codespace на https://github.com/codespaces.
2. Откройте приложение через порт 8080 в соседней вкладке телефона.
3. Меняйте код: Vite обновляет интерфейс, Node перезапускает бэкенд.
4. Создайте отдельный тестовый аккаунт. Письмо подтверждения появится по адресу
   **`/__dev/mail`** на том же тестовом сайте. Ссылки в письмах можно нажимать.
5. Сохраняйте изменения коммитами и отправляйте в отдельную ветку.
   Агент в другом окружении должен отправить коммит в эту ветку; затем выполните
   `git pull --ff-only` в Codespace, чтобы увидеть его изменения.
6. По окончании остановите Codespace через меню GitHub. Закрытие вкладки не означает остановку.

Чтобы запустить вручную, выполните `node .devcontainer/start.mjs` в терминале.
Не запускайте второй экземпляр одновременно. Логи автоматического запуска доступны
в журнале создания/запуска dev container. Если зависимости изменились, остановите
серверы, выполните `node .devcontainer/setup.mjs` и запустите снова.
Лог автозапуска: `runtime/codespaces/dev.log`. Чтобы остановить автозапущенную среду,
найдите процесс `node .devcontainer/start.mjs` командой `ps -ef`, затем выполните
`kill <PID>` для этого процесса: он завершит оба сервера.

## Данные и интеграции

- SQLite-база находится в **`runtime/codespaces/data/mirocard.db`**. Она сохраняется
  при остановке и возобновлении Codespace; не коммитится и не подключается к production.
- Удаление Codespace удаляет и его тестовые данные. Ценные данные сохраните отдельно.
- Секреты для тестового сервера генерируются при первом запуске и сохраняются в
  игнорируемом файле `runtime/codespaces/secrets.json`. Админ-токен можно посмотреть
  в этом файле внутри своего Codespace; не отправляйте его в репозиторий.
- Письма хранятся только в памяти и очищаются после остановки среды разработки.
- Настоящие платежи, Google-вход, push, AI и уведомления во внешние сервисы по
  умолчанию не подключены. Бэкенд не наследует ключи интеграций и не читает `.env`.
  Для проверки этих функций потребуется отдельная настройка тестовых интеграций.
- Каталог и ZIP-файлы колод читаются из `public/decks`. Правки renderer-кода тем,
  загружаемых из ZIP, требуют пересборки ZIP — см. правила в `CLAUDE.md`.

## Проверка перед выпуском

Для быстрой разработки используется Vite. Для проверки собранного приложения:
`npm run test:env -- --build`. Этот существующий режим использует порты 4310/4311
и **временную базу**, которая удаляется при завершении. Перед запуском остановите
обычную среду разработки: почтовый порт 4311 у них общий. Для открытия этого режима
с телефона потребуется отдельно настроить его публичный адрес в APP_BASE_URL:
его текущий скрипт рассчитан на localhost. Это не постоянный staging.

Пуш в `main` автоматически запускает Railway-deploy приложения и лендинга.
Работайте в отдельной ветке и выпускайте проверенные изменения отдельно.

## Стоимость

Codespaces использует квоту личного GitHub-аккаунта, затем — платные ресурсы,
если они включены в Billing. Этот конфиг не включает prebuilds и не меняет биллинг.
Проверяйте расход и бюджет: https://github.com/settings/billing.
Остановленный Codespace продолжает занимать оплачиваемое/квотируемое хранилище.
