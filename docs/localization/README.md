# Локализация: аудит и первый рабочий пакет

Дата: 19 октября 2026. Ветка: `codex/localization-sl-plan`.
Исходная точка: `c667c669ec5fe22eedc003582fe7cd0366fd12fc`, приложение 1.0.2605.

Этот документ описывает первое статическое обследование исходников на указанном коммите. После аудита реализован [прототип LOC-01](loc-01-prototype.md): RU/SL на входе и в настройках, сохранение языка устройства и защита ручного выбора от позднего bootstrap. Готовность всего приложения к выпуску на словенском не заявляется. Исходный [план](../superpowers/plans/2026-10-19-localization-sl-en.md) остаётся целевым; здесь он уточняется по коду.

## Что установлено

1. Языковые поля существуют, но не образуют рабочего языкового потока. `settings.uiLanguage` и `cardLanguage` по умолчанию равны `ru` (`src/core/store.js`); SQLite, bootstrap и PATCH настроек знают эти поля. В `SettingsScreen.jsx` нет выбора языка. Общего переводчика в зависимостях нет.
2. Основной язык ребёнка — отдельное поле `primaryLanguage`, доступное в двух формах ученика. В списке учеников любой непустой код кроме `ru` сейчас подписывается как English (`StudentsScreen.jsx`). Добавления `sl` только в выпадающий список недостаточно.
3. Нормализация карточек выбирает `labels.ru` раньше `labels.en` (`deriveConcepts`, `topicUtils.js`). Генератор получает уже выбранную подпись. Выбор языка должен происходить до генерации очереди, а не при рисовании ответа.
4. `useSpeech` задаёт `ru-RU`; при выборе движка допускает первый голос движка, даже другого языка. Flashcards читает `card.audio.ru`. Смена языка страницы эти пути не исправит.
5. `activeSession` сохраняет student/topic/text/mode, но отбрасывает дополнительные поля контекста. Версия темы проверяется в sessionState; язык не проверяется. Добавить поле только вызывающему коду недостаточно.
6. Прогресс в SQLite имеет ключ `(student_id, topic_id, concept_id)`; клиентская индексация использует такую же тройку. Расчёт прогресса по истории также фильтрует без языка. Новое поле в таблице прогресса само по себе проблему не решает.
7. ZIP-файлы темы хранятся по `topicId/filename`, кэш renderer — по topicId, CSS тоже привязан к topicId. Две языковые версии под одним id могут перезаписать друг друга. Правила владения и платного доступа при этом опираются на общий id темы.
8. Учебный интерфейс из ZIP и генератор заданий из app bundle обновляются разными путями. `SessionScreen` предпочитает загруженный renderer, кроме специального пути `spatial_prepositions`. Языковой контракт нужен на обеих сторонах.
9. В «Сравнении» есть русская грамматика прямо в engine: именительный, родительный, дательный числительных, составляемые вердикты. Режимы нельзя считать полностью визуальными по названию темы.
10. Словенский уже частично представлен в согласиях оплаты, письме о покупке и `backend/legal/sl/`. Остальные письма в `mailer.mjs` русские. Покупка имеет собственный locale, который фиксирует язык согласия; его нельзя молча заменить текущим языком интерфейса при отправке webhook-письма.

## Границы аудита

Обследованы все нетестовые JS/JSX/JSON в `src`, backend/lib, server, generated inventory, текстовые манифесты тем, shared-модули, основные генераторы аудио, HTML запуска, service worker и юридические HTML. Точный состав — в source-files.csv. Отдельные исходники сборки колод, CSS, SVG/изображения и внешние сервисы не входят в автоматический текстовый проход.

Сигнал кириллицы — не строка перевода: в нём бывают комментарии, данные, несколько фраз и пользовательские примеры. Поэтому количество сигналов не используется для оценки стоимости перевода. `review=unreviewed` означает, что из каждой позиции ещё нужно выделить пользовательские сообщения, адресата, переменные и ключи. Английские строки без языковых маркеров такой проход не обнаруживает.

GitHub-коннектор позволил получить и сверить текстовые исходники по Git blob SHA; обычное клонирование было недоступно через прокси окружения. Бинарные ZIP этот интерфейс не декодирует. Встроенные в ZIP манифесты, полное количество аудиозаписей, текст в изображениях и PDF требуют отдельного прохода в полноценном checkout. Числа `bundle_modes/cards` взяты из существующего generated inventory, не пересчитаны по ZIP; ноль не означает отсутствие исполняемых режимов. Сверка source/package обязательна: например, `tools/comparison/topic.json` имеет 2.36.0, а catalog bundle — 2.36.1.

Нет проверки в браузере, на устройстве или носителем языка. Ни одна тема не объявлена готовой на словенском. Этап 0 исходного плана начат и имеет воспроизводимую основу, но ещё не закрыт.

## Воспроизведение

В полном checkout:

```bash
python3 scripts/audit-localization.py --revision c667c669ec5fe22eedc003582fe7cd0366fd12fc
```

Скрипт использует стандартную библиотеку Python, читает Git blobs выбранного коммита, не запускает приложение и не обращается в сеть. Повторный запуск с тем же коммитом даёт те же CSV/JSON. При изменении аудируемого коммита обновлять реестры отдельным осознанным изменением; автоматически не заменять исходную точку на текущий main.

LOC-01 реализован как ограниченный прототип; результаты и недостающие проверки — в [отчёте](loc-01-prototype.md). Следующая функциональная задача — LOC-02: синхронизация предпочтения аккаунта. LOC-00 по пакетам остаётся открытым. До открытия словенских занятий обязательны LOC-02–06; до публичного словенского интерфейса — весь доступный путь взрослого и его проверки.
