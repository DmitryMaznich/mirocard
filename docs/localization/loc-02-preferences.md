# LOC-02: языковые предпочтения

Повторный выпуск: причина отказа прежнего деплоя установлена — полный том Railway. В main исправлены очистка резервных копий до открытия БД (1.0.2664, PR #28) и повтор sync при временных ошибках хранилища (1.0.2665, PR #29). LOC-02 перенесён поверх этих исправлений для выпуска 1.0.2666. CI дополнен проверкой сборки и запуска того же production Docker-образа; после публикации проверяется точная версия, health, страница приложения и каталог.

Язык интерфейса аккаунта хранится независимо от предпочтительного языка занятий.
Словенский UI остаётся ограниченным прототипом: вход и настройки. Выбор языка
занятий не меняет язык существующих материалов и активного занятия.

## Сохранение и конфликты

- Синхронная boot-копия UI-языка остаётся в `mironium.uiLanguage`.
- Отдельная очередь `mironium.accountLanguages` хранит операции по account ID,
  без токенов. Сначала сохраняется операция, затем отправляется узкий PATCH
  `/api/account/languages`. При запрете хранения показано предупреждение.
- Каждая операция имеет случайный ID и ожидаемую серверную languageRevision.
  Сервер меняет только uiLanguage/cardLanguage; PIN и остальные настройки
  не входят в запрос. Повтор принятой операции не применяет её второй раз.
- Неотправленный ручной выбор защищён от позднего bootstrap. При конфликте
  он повторяется с актуальной серверной ревизией, без сравнения часов устройств.
  Подтверждённое серверное предпочтение применяется на остальных устройствах
  при следующей обычной синхронизации (видимость вкладки / периодический pull).
- Более старые ответы не отменяют новый ручной выбор. После logout либо
  смены аккаунта ответы прежнего контекста игнорируются, операции изолированы.
- Гостевой выбор переживает reload. Он инициализирует только аккаунт без
  явного выбора (revision=0). У существующего предпочтения приоритет выше.
  Гостевой выбор потребляется один раз.

## Ученики

Общий справочник различает Русский, Slovenščina и English. Он описывает
предпочтения и основной язык ученика, а не готовность переведённых материалов.
Неподготовленный English UI по-прежнему не предлагается.

`student.preferredLessonLanguage` — nullable: null наследует
`settings.cardLanguage`. Поле проходит формы, локальное хранение, student.upsert,
SQLite, GET студентов и bootstrap. Основной язык `primaryLanguage` сохраняет
свой смысл. Старый клиент, не передающий новое поле, не стирает его.
Неизменённый выбор в форме и автоматическая отправка профилей при входе
не переписывают предпочтение на сервере.

Явные изменения профиля используют существующую очередь student.upsert и
существующее объединение профилей по updatedAt. Разрешение доступного языка
учебного пакета, фиксация языка занятия и разделение прогресса относятся к
LOC-03–06; этот этап не объявляет словенские занятия доступными.

## Миграция и откат

Изменения SQLite только добавляют поля и таблицу идемпотентных операций.
Существующие значения и история сохраняются. Старые нестандартные предпочтения
аккаунта получают revision=1; прежний default ru остаётся revision=0.
Повторный initDb сохраняет ревизии и журнал операций. Прежняя версия приложения
совместима с расширенной схемой: для отката кода не нужна обратная миграция.

## Проверки

Автоматические сценарии покрывают reload/offline/retry, поздний bootstrap,
серверный конфликт, ответ старой операции, logout/другой аккаунт, guest adoption,
запрет хранения, валидацию кодов, сохранность PIN, отдельные языки учеников,
legacy upsert, наследование и повторный запуск миграции. React-проверка настроек
проверяет неизменность активного занятия и раздельность UI/lesson preferences.
Полная сборка, frontend/backend suites и проверка Railway выполняются в CI.

Проверка словенских формулировок редактором и ручная проверка на устройствах
остаются отдельной частью приёмки. Следующий технический этап — LOC-03,
контракт языковых пакетов; LOC-00 по содержимому ZIP остаётся открытым.
