# LOC-01: прототип RU/SL

Дата: 19 октября 2026. Ветка: `codex/localization-sl-plan`.
Основание: аудит `9e41cfd0dbdfa356861e6e984fe428959557854b`.

## Реализовано

- Видимый выбор «Русский / Slovenščina» на входе и в настройках; названия языков даны в собственном написании, без флагов.
- Общий словарь со смысловыми ключами и React-подпиской. Переведены подписи и ошибки входа, оболочка настроек, диалог PIN, состояния локального хранилища и управление зонами. Имена и названия личных зон не переводятся.
- Выбор применяется сразу и сохраняется в `localStorage` под ключом `mironium.uiLanguage`; переживает перезагрузку и выход из аккаунта. При запрете хранения выбор работает до закрытия страницы, рядом с переключателем показано объяснение.
- Короткий синхронный скрипт в HTML выставляет `html.lang` до первого отображения; BootScreen берёт текст из того же языкового состояния. Неизвестный код не активирует неподготовленный язык.
- `settings.uiLanguage` отражает выбор устройства. Поздний IDB/server bootstrap не отменяет ручной выбор; если ручного выбора ещё нет, поддерживаемое старое значение может его инициализировать.
- Переключение не перемонтирует форму, сохраняет значения полей и состояние пароля. Ошибка входа хранится как ключ, поэтому уже показанное сообщение также переводится.
- Google-кнопка получает выбранный locale при загрузке SDK и renderButton; при изменении locale контейнер очищается перед повторным render. Реальный redirect/auth и поведение стороннего SDK в браузере ещё не проверены.
- PIN-dialog ограничен шириной доступного экрана и учитывает существующие переменные iOS safe area.

Словенские тексты — редакционный черновик. Другие экраны, регистрация, восстановление пароля, учебные материалы и сервисные письма не объявляются переведёнными. Рядом с выбором языка указана граница прототипа.

## Граница технического решения

LOC-01 использует небольшой `shared/i18n` модуль без новых npm-зависимостей. Он поддерживает только уже добавленные простые сообщения и именованные переменные; HTML и числовые формы через него не создаются. Это ограниченный прототип, а не замена полноценной системе перевода всего приложения. Перед расширением на количественные сообщения перейти к запланированной i18next/Intl-основе, сохранив смысловые ключи и API хука.

Настройка пока относится к устройству, не отправляется PATCH-запросом на сервер и не синхронизируется между устройствами/открытыми вкладками. Существующие `cardLanguage`, primaryLanguage, задачи занятия, пакеты и озвучка не изменяются. Конфликты аккаунта и долговечная очередь синхронизации — LOC-02.

## Проверка

В этом окружении выполнено:

1. Семь тестов стандартным Node runner: ключи и переменные RU/SL, сохранение/reload, поздний bootstrap, старые и невалидные значения, запрет хранения, подписка/отписка, ранний HTML-bootstrap.
2. Синтаксическая проверка изменённых JS и преобразование JSX парсером Babel.
3. Интеграционный DOM-прогон исходных LoginScreen, SettingsScreen, UiLanguagePicker, PinGateModal, store и applyBootstrapToStore. Использованы React 19 canary из compiled runtime Next.js v16.0.0 и LinkeDOM v0.18.12 во временной тестовой среде; API/DB и каталог заменены тестовыми данными, пакет Zustand — тестовым адаптером состояния на useSyncExternalStore. Проверены поля формы, RU/SL-подписи, текущая ошибка, поздний bootstrap, сохранённые настройки, изоляция cardLanguage и snapshot, личные названия зон, PIN и logout. Эти временные зависимости не входят в приложение.

В репозиторий добавлены обычные Vitest-тесты входа/настроек и locale Google-кнопки. **Их запуск на штатных зависимостях проекта пока не подтверждён.** Для полного checkout:

```bash
node tests/localization/ui-language.test.mjs
npx vitest run src/features/account/LoginScreen.localization.test.jsx src/features/settings/SettingsScreen.localization.test.jsx src/features/account/GoogleSignInButton.test.jsx src/features/account/authErrors.test.js src/core/bootstrap.test.js
npm run build
```

Ограничения проверки: сетевой прокси терминала не позволил получить полный checkout и зависимости; `npm run build` остановился в prebuild на `ERR_MODULE_NOT_FOUND: jszip`. Chromium завершился при запуске из-за sandbox-ограничения `setsockopt: Operation not permitted`. Поэтому production-сборка, штатный Vitest, визуальные размеры/переносы, реальные устройства, Google OAuth и редакторская проверка остаются обязательными перед выпуском. DOM-проверка не подтверждает визуальную корректность или полную совместимость с точной версией React проекта.

Изменения сохраняются в рабочую ветку локализации; main и production не обновляются. Перед последующим переносом app-кода в main требуется отдельное повышение версии по CLAUDE.md и успешная штатная сборка.
