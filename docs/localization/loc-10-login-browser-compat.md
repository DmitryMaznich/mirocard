# LOC-10: совместимость входа на Android

Приложение 1.0.2677, [PR #39](https://github.com/DmitryMaznich/mirocard/pull/39), main `84bf4c6ed8ed1e54eefd6023364fefba80b5061f`.
[PR CI](https://github.com/DmitryMaznich/mirocard/actions/runs/39454106637), [main CI](https://github.com/DmitryMaznich/mirocard/actions/runs/39454625440): по шесть успешных jobs.
Откат: codex/rollback-before-login-compat-2677, 1.0.2676 / 840c7f0.

Пользователь сообщил об ошибке входа обоими способами на установленном приложении
Android/Lenovo. Точная версия Chrome пока не известна; прямого доступа к планшету нет.
Публичные version/health/signup-status исправны, БД доступна, Google client настроен.
Последний перенос режима не менял auth-код. Но ранее добавленное восстановление
предпочтений языка безусловно вызывало Object.hasOwn, отсутствующий в старых Chrome.
Воспроизведение: сервер принимает пароль (HTTP200), bootstrap/sessions тоже успешны,
а accountLanguages.reconcile бросает TypeError. UI показывал «Проверьте email и пароль».
Тот же completeLogin вызывается Google. Это воспроизводимый дефект, но его совпадение
с причиной на конкретном устройстве требует пользовательского подтверждения.

src/browserCompatibility.js импортируется первым из main.jsx. Только при отсутствии
native метода устанавливаются Object.hasOwn и Array.at, а при наличии getRandomValues
и отсутствии randomUUID — криптографический UUID v4. Существующие native реализации
не заменяются. Методы нужны для восстановления языка, merge учеников и ID операций.
Глобальная установка сохраняет работу IIFE скачанных тем без перепаковки архивов.
Проверки пароля, Google nonce/кодов/подписей, токены, серверная БД и схема IDB не менялись.
Ошибки пароля по HTTP401 по-прежнему отличаются от общей ошибки завершения входа;
истёкший Google-код показывается только при server invalid_or_expired_code.

Проверено: 2300 frontend-тестов, 39 account tests, strict lint и production build.
CI первый раз упал в независимом случайном тесте word_formation: 24 правильных из 60
при строгой границе >24. Повторён только failed job; он прошёл без изменения теста
или кода этой темы. Локальный повтор тоже успешен.
Chromium и собранный production HTML: пароль/Google, native API присутствуют/удалены,
вход и восстановление после reload успешны, page errors отсутствуют. Проверяется
первый/повторный вход того же аккаунта, собственные/наследованные ключи и secure UUID.
Тестовые аккаунты/ответы смоделированы, настоящие пароли не использовались.

Railway подтвердил 1.0.2677/точный коммит и здоровье БД. В выданном HTML есть fallback
и новый нейтральный текст ошибки; каталог и все архивы пилота/оригинала неизменны.
Для проверки на устройстве полностью закрыть установленное приложение и открыть
снова с интернетом; данные не очищать. При наличии доступного обновления Chrome
его можно поставить без удаления приложения. Наличие ещё более старого/неподдерживаемого
браузера или другой ошибки хранилища не исключено: результат на Lenovo нужно проверить.
