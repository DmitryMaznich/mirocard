# Объявления пользователям (однократный показ)

Начато 2026-11-24 (владелец: «механизм объявления — по желанию разработчика, один раз, пока не нажал ОК»).

## Как выпустить объявление

1. Добавить запись в начало `src/announcements/announcements.js` (формат описан в шапке файла):
   `id` (уникальный, потом не менять), `title` и `body` на `ru` / `sl` / `en` (нет языка → английский → русский),
   `until` — обязательно по смыслу (тест требует), чтобы старая новость не всплыла через полгода.
2. По желанию — кому показывать: `topics` (у аккаунта есть одна из тем), `accountsCreatedBefore` (только старым
   аккаунтам — новость о перемене не нужна тому, кто старого не видел), `languages`, `from`, `match(ctx)`.
3. `npx vitest run src/announcements` — проверка списка (id, тексты, даты).
4. Обычный релиз: версия `package.json` + `git push origin main`. Без деплоя объявление не выходит — это и есть «по желанию».

Снять объявление раньше срока — удалить запись (или поставить `until` на сегодня). Отметки «прочитано» останутся в базе, не мешают.

## Как показывается

- `src/features/announcements/AnnouncementHost.jsx` (подключён в `App.jsx`): только на экране `home`, никогда во время занятия.
  Первое подходящее непрочитанное из списка; следующее — при следующем заходе на главный экран.
- Окно — обычный `Modal`, без крестика и без закрытия по тапу мимо: закрывает только «Понятно» (`announcement.ok` в
  `src/shared/i18n/announcementMessages.js`).

## Где хранится «прочитано»

- Ключ `announcements:seen:<id>` = `{ at }` — **по ключу на объявление** (не один список: два устройства, отметившие
  разное без сети, не затрут друг друга — сервер хранит последнюю запись по ключу).
- На устройстве (IndexedDB keyval) и в аккаунте (`kv.upsert` через офлайн-очередь; читается `GET /account/kv?prefix=…`).
  Прочитал на телефоне — на планшете того же аккаунта не покажется. Без аккаунта (локальный режим) — только на устройстве.
- Без сети: решает отметка устройства; отметка с сервера, когда пришла, копируется на устройство.
