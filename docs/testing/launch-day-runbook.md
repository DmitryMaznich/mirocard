## Во время (каждые 30–60 минут первые 3 часа)

| Смотреть | Где | Беда, если |
|---|---|---|
| Ошибки | канал `ERROR_REPORTING_WEBHOOK_URL` | любое `email send failed` — письма не уходят, люди не могут войти |
| Письма | Resend dashboard → Emails | отправлено заметно меньше, чем регистраций; много bounced |
| CPU / память | Railway → mirocard-backend → Metrics | CPU у потолка дольше минуты; память растёт без остановки |
| Ответы | Railway → HTTP error rate / response time | 5xx > 0; p95 > 1–2 с |
| Живость | `https://app.mironium.com/api/healthz` | не `ok` |

Ориентир из локальных замеров: до ~2–3 регистраций в секунду всё быстро (p95 < 150 мс).
Задержки > 1 с начинаются примерно с 5 регистраций в секунду — это 300 человек за минуту,
для поста в Instagram маловероятно.

## Если…

- **Письма не уходят** → Resend dashboard (лимит? домен? блокировка?). Пока чинится,
  тем, кто написал, активировать аккаунт вручную:
  ```bash
  curl -X POST https://app.mironium.com/api/admin/verify-account \
    -H "Authorization: Bearer $MIROCARD_ADMIN_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"email":"<адрес человека>"}'
  ```
  (токен — из менеджера паролей, не вставлять в чаты и документы).
- **Люди пишут «слишком много попыток» при регистрации** → это лимит 10 регистраций в час
  с одного IP (находка N7). Обход для конкретного человека: зарегистрироваться с другой
  сети (Wi-Fi ↔ мобильный интернет).
- **Сервер тормозит под регистрациями** → Railway Metrics; кратковременно поднять ресурсы
  сервиса в Railway; постоянное решение — асинхронный scrypt (находка N8).
- **Сломалась тема или весь релиз** → откат по `docs/commercial-launch-runbook.md` §11.
